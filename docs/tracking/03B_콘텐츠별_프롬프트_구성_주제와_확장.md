## 5. 코드에서 확인된 어긋남과 주의점(수정은 하지 않았다)

1. 서버 차감 1운 고정 대 클라 3운: 연애, 재물, 재회는 클라가 3운을 차감하는데 서버 두 함수는 1운만 차감한다(IDX:2491, IDX:2591). 로컬과 Firestore 잔액이 어떻게 맞는지는 확인 못 함.
2. 재회운 max_tokens 16000(CT:1015)은 split 경로에서는 쓰이지 않는다. 실제 상한은 본문 12000 + 카드 8000.
3. 합격 이직운 서버 필드 8개(changeMode, jobChangeLuckLevel, bestChangeMonths, avoidChangeMonths, interviewDirection, changeDirection, postChangeOutlook, luckyItemForExam)는 클라에서 읽는 곳이 0건이다. 반대로 ExamViz 가 읽는 bestExamMonth, jobChangeTiming 등은 서버 exam 스키마에 없다.
4. 직업운 CareerViz 가 읽는 statusAnalysis, fieldFitScore, fieldFitAnalysis, jobChangeTiming 은 서버 스키마에서 빠졌다(2026-05-28 재정의). 재물운 incomeSources 는 서버 스키마에 없고 클라는 추정값을 쓴다. 궁합 timeline 도 같다.
5. archetype 은 서버가 여러 주제에서 요구하지만 클라에서 읽는 곳이 없다. keywords 는 서버가 만들고 화면은 렌더하지 않는다. sajuConnection 과(10개 주제에서) sajuBasis 도 화면에 안 나온다. 프롬프트 규칙 6번은 여전히 "keywords는 #으로 시작"(CT:1797)인데 스키마 예시에서는 '#'이 빠졌다(커밋 599923b). sanitize 가 짧은 해시태그를 정리한다.
6. 결혼운 기혼 + 배우자 정보 입력 시, 제목은 기혼 분기인데 상태 블록 문구는 "연애 중, 교제 상대방"이다(CT:1467~1484).
7. 사업운 프롬프트에 archetype 이 8종(CT:468)과 4종(CT:1772)으로 함께 적혀 있다.
8. 스트림 outline 이벤트의 섹션 제목은 sanitize 전 원문이다(IDX:2611).
