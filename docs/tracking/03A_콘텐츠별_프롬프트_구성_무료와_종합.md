### 1-4. 시스템 프롬프트 구성
스트림 5개 호출과 폴백, 콜러블이 모두 같은 system 을 쓴다: DAILY_FORTUNE_SYSTEM_V3 (ai/promptsV3.ts:1219~1269).
순서는 (1) V3_BASE_SYSTEM(36~390, 끝에 LUCKY_SSOT_BLOCK) (2) GOOSEBUMP_BLOCK(399~440) (3) 무료 데일리 절대 원칙 (4) 엔드포인트 특화.
콘텐츠 고유 핵심 규칙(1219~1269):
- 본문은 100% 일상어. 명리 용어(건록격, 정관, 일간, 대운 등)를 문장 주어나 핵심으로 쓰지 않는다. 한자가 꼭 필요하면 문장 끝 괄호로 가볍게, 한 섹션에 2개 이하.
- 결론부터, 장면으로. 점집 어르신처럼 다정하고 단정적으로. 번역체와 드라마체 금지.
- 같은 날 안에서 "좋다"와 "나쁘다"가 충돌하지 않게, 시간대는 구간을 나눈다.
- 성별 기준 해석(여성은 관성, 남성은 재성이 연인의 별). "당신은 여성이라" 같은 설명 문장 금지.
- 검증 불가 보장과 수치 금지("3개월간 좋은 결과", "성공 확률"). 처방형 미신 금지(이 글자를 쓰면 운이 오른다 등).
- 반복과 낙인 금지, 시간 표기는 "오후 2시"(오후 14시 금지).

### 1-5. 유저 프롬프트 구성

1. 이름, 사주 JSON 전체(원국, 십성, 오행, 대운, myeongriAnalysis 포함)
2. 용신 SSOT 줄(용신, 희신, 기신. 행운 항목은 이 용신 하나로 도출하라는 지시) (1288)
3. 오늘 정보: 날짜와 요일, 오늘 간지
4. 서버 확정 일진 판정 한 줄 (sajuFacts.ts:358 todayYongsinLine. 천간과 지지가 용신, 희신, 기신 중 무엇인지, 도움이 되는 날인지)
5. 오행 관계 확정표 (sajuFacts.ts:508 todayRelationsText. 오늘 기운과 일간, 용신, 연인의 별, 일지 사이의 생극과 합충)
6. 시간대 확정표 (sajuFacts.ts:598 todayHourWindows. 한국 진태양시 :30 경계 시진 8개 구간 점수와 가장 좋은 시간, 조심할 시간)
7. 절기, 길신, 흉살, 내일 간지(그룹별로 다름, 아래)
8. 점수 SSOT: 종합사주 기반 baseScores100 의 재물, 관계, 일, 건강 base 를 주고 subScores 는 base 에서 2점 이내로, overallScore 는 4축 평균에서 5점 이내로
9. 생성 지침과 스키마, 필드 floor, 자기 체크, 만나는 사람 글자 확정 블록(dailyMeetPromptBlock)
10. 서브콜이면 "이번 호출의 최종 출력 범위" 키 목록(index.ts:931~934)
11. 맨 끝 TONE_FINAL_CHECK(index.ts:951 근방)
그룹별 차이: A1은 길신, 흉살, 내일 간지가 없다. A2는 내일 간지가 없다. B는 점수 SSOT 가 없고 내일 간지가 있다. 클라이언트는 baseScores100(computeDailyBase100)과 내일 간지를 함께 보낸다(DailyFortunePage.tsx:373~384).

### 9-1. 코드에서 확인된 불일치 (사실만 기록, 수정 판단은 오너)
1. 꿈해몽은 같은 콘텐츠인데 스트림(2그룹, 7500과 7000, 서로 다른 스키마와 글자수 하한)과 콜러블 폴백(단일 14000, narrative와 sajuTone과 todayConnection 300자 이상 및 interpretation 500자 x 3)이 서로 다른 프롬프트를 쓴다. 폴백으로 떨어진 사용자는 더 긴 본문과 sajuConnection, interpretation 을 받지만 화면은 그 필드를 읽지 않는다. 또 스트림은 system 에 캐시를 걸지 않는다(index.ts:1429).
2. 오늘의 운세도 스트림과 콜러블 폴백이 다르다. 콜러블은 시간대 range 확정값 덮어쓰기와 nextHooks 정리를 하지 않고(ai/claudeFortune.ts), 모델은 Sonnet 한 개, temperature 0.7.
3. 오늘의 운세 화면 미사용 AI 필드가 여러 개 있다: grade, overallScore(유효성 판정에만), keywords, sajuTone, pillarMessages(buildPillars 호출 시 인자 누락), ohengDistribution, todayOhengEmphasis, subScoreReasons. 이 필드들은 Sonnet 호출(A2a와 A2b)의 출력 토큰을 쓴다. 총정리 문서의 "미사용 AI 필드 8개 정리 미룸"과 같은 계통이다.
4. DailyMockupView 는 relationExplain 을 읽지만 서버가 만들지 않는 필드다.
5. 종합사주 STATIC_SYSTEM_PROMPT 와 그룹 focus 의 분량, actionList 개수, topicMini 키 수가 서로 다르다 (4-6-1).
6. 종합사주 그룹 파싱이 모두 실패하면 빈 객체가 반환되어 해당 그룹의 필드가 조용히 비고, 재시도가 없다. 1운 리포트에는 temperature 0.3 재시도가 있다.
7. 종합사주 사주 base 블록에는 지장간, 12운성, 공망, 형충합이 없지만 시스템 프롬프트는 STEP1에서 "지장간까지 확인"하라고 지시한다. 1운 리포트 유저 프롬프트에는 그 항목들이 들어 있다.
8. 대운은 TONE_FINAL_CHECK, sanitizeAiOutput, GOOSEBUMP_BLOCK, 용신 주입이 모두 없고 JSON 복구도 없다. 현재 비공개라 사용자에게는 노출되지 않는다.
9. 사주대화에는 용신, 격국, 강약, 십성 분포가 주입되지 않는다. 같은 사람의 종합사주와 오늘의 운세에서 쓰는 SSOT 를 사주대화는 직접 받지 못하고, 결과 페이지에서 들어온 경우에만 [CONTENT_CONTEXT] 로 간접 전달된다. 그 블록이 history 첫 항목이라 최근 6개 슬라이스에 밀려 사라질 가능성이 코드상 있다 (실측 못 함).
10. 사주대화 temperature 가 지정되지 않아 API 기본값이다. CLAUDE.md 2026-10-13 정정 블록과 같은 서술.
11. 운 장부가 클라이언트 로컬 장부와 서버 Firestore 장부로 두 개이고, 종합사주는 양쪽에서 각각 차감한다 (PremiumSelectPage.tsx:57, index.ts:264). 동기화 방식은 이 조사에서 확인하지 못함.
12. PDF 파일 머리 주석의 리전(asia-northeast3)과 실제 리전(us-central1)이 다르다.
13. 오늘의 운세 스트림의 Sonnet 단일 폴백에는 1시간 TTL 캐시가 남아 있다(index.ts:1042). 주 경로는 5분 TTL 로 바꿨다.

### 9-2. 확인하지 못한 것
- 꿈해몽, 사주대화, 1운 리포트, 대운, PDF 의 실측 생성 시간.
- 1운 리포트와 대운의 건당 AI 원가(메모리의 원가 문서에 기록 없음, aiUsage 컬렉션은 이번에 조회하지 않음).
- 1운 기본 리포트 코드가 현재 어떤 화면에서 호출될 수 있는지(ResultPage.tsx:431 분기와 LoadingPage.tsx:235 의 도달 가능성).
- 클라이언트 로컬 장부와 서버 Firestore 장부의 동기화 규칙과 종합사주 이중 차감 여부.
- 사주대화에서 [CONTENT_CONTEXT] 가 최근 6개 슬라이스로 실제로 잘리는지.
- PDF 버튼이 현재 배포된 앱 번들(.ait)에 노출되는지.
- 오늘의 운세 pillarMessages 가 화면 어딘가에서 다른 경로로 쓰이는지(검색 범위 안에서는 사용처를 찾지 못함).
- 이 문서의 줄 번호 일부(promptsV3.ts 의 오늘의 운세 스키마 범위, 서브콜 TONE_FINAL_CHECK 부착 줄)는 대략값이며, 대표 줄 번호만 직접 확인했다.
