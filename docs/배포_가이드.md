# 배포 가이드 — 웹 vs 앱인토스 (SSOT)

> **핵심 원칙: 코드베이스는 하나(`D:\550saju`). 폴더로 안 나눈다.**
> 웹/앱인토스는 **빌드 명령**으로만 갈린다. `isAppsInToss()` + `--mode ait`가 런타임/번들에서 자동 분기.
> 폴더를 둘로 나누면 = 코드 두 벌 = 매번 두 번 작업 = 드리프트 지옥. **절대 금지.**

---

## 빌드·배포 명령 (외우기)

| 타깃 | 빌드 | 배포 | 출력 | 도착지 |
|------|------|------|------|--------|
| **웹** | `npm run build` | `firebase deploy --only hosting` | `dist/` | Firebase Hosting (네이버/구글) |
| **앱인토스** | `npm run build:ait` (= `tsc && vite build --mode ait && ait build`, 포트원 SDK stub 포함. `npx ait build` 단독 금지 — 2026-10-13 정정) | (수동) | `dist/web` + `saju-500.ait` | 토스 콘솔 업로드 |
| **서버(공통)** | `cd functions && npm run build` | `firebase deploy --only functions` | `functions/lib` | Cloud Functions |

`npm run deploy` = `build && deploy --only hosting` (웹 단축).

## ⚠️ 배포 순서 — 반드시 지킬 것 (2026-06-03 사고 재발방지)

```
1. npm run build                      # 웹 dist/ 생성
2. firebase deploy --only hosting     # ← dist/ 가 웹 빌드인 상태에서 배포
3. NODE_OPTIONS=--max-old-space-size=4096 npm run build:ait   # ← 이게 dist/ 를 앱 번들로 덮어씀! (웹 hosting 은 10-03 이후 배포하지 않음)
4. cp saju-500.ait D:\550saju\saju-500.ait
```

**함정**: `npx ait build`는 `dist/`를 앱인토스 RN 번들로 **덮어쓴다**.
→ ait build를 hosting 배포보다 **먼저** 하면, 웹에 RN 번들이 올라가 **사이트가 깨진다** (실제로 한 번 발생).
→ **무조건 hosting 배포 → 그 다음 ait build** 순서.

## 버전
- SSOT = `package.json` "version" (vite가 `__APP_VERSION__`로 주입, 내정보 하단 표기).
- 토스 콘솔 업로드 시 버전은 **수동 입력** (.ait엔 안 박힘). package.json과 맞춰서 입력.
- 변경 후 반드시 **재빌드**해야 내정보 버전 표기 갱신됨.

## 검증 (배포 전 필수)
- `npx tsc --noEmit -p tsconfig.json` (클라) + `cd functions && npx tsc --noEmit` (서버) → 0 에러
- 결제 앱이므로 큰 변경 시 결제·로그인 플로우 수동 QA 후 배포.
