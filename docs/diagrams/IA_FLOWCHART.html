3.3 모든 페이지 → /charge 진입

잔액 부족 모달은 다음 8 페이지에서 발생:

  • ChatPage: navigate('/charge', {state: {message: '사주대화에 1운이 필요해요'}})
  • CompatibilityPage: state.from='compat' + 메시지
  • DaeunPage / MonthlyPage / TojungPage: 각 콘텐츠별 메시지
  • DreamPage: 심층 해몹
  • InputPage: ?need=1 또는 ?need=10
  • BalanceBar: 상단 클릭 (모든 페이지 공통)

/charge?need=10 query로 패키지 자동 선택, state.returnTo로 결제 후 원위치 복귀.

4 결제·잔액 3-bucket 시스템

3-bucket 종류

  • paid — 환불 가능 (전자상거래법)
  • bonus — 충전 보너스 (환불 X)
  • reward — 공유·출석·3원 (환불 X)

localStorage 키: saju500_balance_v2

소비 우선순위

reward → bonus → paid

환불 가능한 paid 잔액을 마지막에 소비해서 보호. spendBalance() 함수가 자동 처리.

결제 원자성 (E13)

sequenceDiagram
    participant U as 유저
    participant C as 클라이언트
    participant FN as Cloud Function
    participant T as Toss API
    participant FS as Firestore

    U->>C: 충전 클릭 1500원·4운
    C->>FN: confirmPayment orderId amount
    FN->>FS: payments orderId status pending
    FN->>T: POST v1 payments confirm
    alt Toss 승인 성공
        T-->>FN: 200 OK
        FN->>FS: TRANSACTION balance += 4 status confirmed
        FN-->>C: success true
        C->>C: localStorage 동기화
    else Toss 승인 실패
        T-->>FN: 4xx
        FN->>FS: status failed
        FN-->>C: error PAYMENT_FAILED
        C->>U: 결제 승인 실패 토스트
    else Toss OK 그러나 DB 실패
        FN->>FS: status needs_reconciliation + tossApprovedAt
        FN-->>C: error NEEDS_RECON
        C->>U: 고객센터 문의 토스트
    end
회귀 방지: Firestore rules에서 payments 클라이언트 write 차단됨. balanceService.spendUn() deprecated (2026-05-15 삭제 예정). 클라이언트는 localStore만 조작.
