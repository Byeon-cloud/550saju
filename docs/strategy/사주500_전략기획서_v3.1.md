## 0. 경영 요약 (Executive Summary)

### 0.1 한 줄 정의
**"500원에 제공하는, 점집 아닌 극상 퀄리티 AI 사주 풀이 서비스"**

### 0.2 세 가지 판돈
1. **가격** — 1운(500원) 진입장벽으로 기존 카테고리(3,000~50,000원) 재편.
2. **퀄리티** — 6대 원전 기반 백과사전 + "AI같지 않은" UX 라이팅·디자인.
3. **플랫폼** — 앱인토스 + 웹 동시. 토스 생태계 바이럴 + 일반 웹 SEO 양날개.

### 0.3 왜 지금인가
- **공급 측**: Claude Opus 4.6 수준의 LLM이 명리학 해석을 300자×10섹션 분량으로 학술적 톤 유지하며 생성 가능.
- **수요 측**: 점신·포스텔러 등 기존 앱은 "재미용 가벼움" 또는 "무거운 고가"로 양극화. **"가볍지만 깊은"** 중간대가 비어 있음.
- **채널 측**: 앱인토스 생태계가 Threads·X 바이럴과 결합하면 초기 획득 비용 0에 가까움.

### 0.4 핵심 지표 타겟 (런칭 후 90일)
- MAU 10,000 / D7 리텐션 25% / 유료전환율 4% / 평균 결제 단가 1,200원 (바스켓 2.4운)
- **경쟁 대비**: 점신 유료전환율 ≈2%, 포스텔러 ≈6%, 본 서비스 목표 4%는 "가격은 점신, 깊이는 포스텔러"의 중간값.

## 2. 제품 전략 (Product Strategy)

### 2.1 가격 v3.1 (3층 구조)

| 층 | 가격 | 상품 | 목적 | Unit Economics |
|----|------|------|------|----------------|
| 무료 | 0원 | 오늘 운세 · 꿈해몽 · 사주대화(1일 1회) | 획득·SEO | 원가 ≈ $0.003/call (Haiku) |
| 본격 | **500원 (1운)** | 10섹션 리포트 + 인포그래픽 + 블러잠금 후기 | 본격 전환 | 원가 ≈ $0.08 (Opus) → 마진 70%+ |
| 프리미엄 | 5,000원 (10운) | 심층 + PDF + 월운 + 궁합 | LTV 확장 | 원가 ≈ $0.6 → 마진 80%+ |
| 전문가 | 50,000원 | 명리학자 1:1 (Phase 3) | 옵션 | 별도 정산 |

**3-bucket 잔액**: `paid · bonus · reward`
- 소비 우선순위: reward → bonus → paid
- 환불: paid만 가능 (법적 리스크 관리)
- 어뷰징 방지: 공유 리워드 월 5운 한도 · 동일 IP/전화번호 제한

**충전 패키지**: 1운(500) / 4운(1,500) / 7운(2,500) / 14운(5,000)
- 심리 포인트: "1잔 커피 = 10운" (프리미엄 프레이밍)

상세: `docs/prd/가격_상품구조.md`

### 2.2 런칭 프로모 "3원 리워드"

- 신규 가입 시 3원(0.006운 상당) 지급 → 결제 플로우 체험용
- 목적: "결제는 무섭다"는 심리 장벽 돌파 + 토스페이/IAP 흐름 1회 경험
- 예산: 10,000명 × 3원 = 30,000원 (무시 가능)

상세: `docs/prd/런칭프로모_3원리워드.md`

### 2.3 블러잠금 후기 (Soft Paywall)

- **CSS blur + 노이즈 오버레이 + 서버 차단** 3층 방어
- 후기 미리보기는 흐릿하게 보이되 읽을 수 없게 → "궁금하다 → 결제" 전환 트리거
- 프리미엄 섹션도 동일 패턴 (500원 결제 후 잠금 해제)

상세: `docs/prd/프리미엄_티저블러.md` · `docs/prd/소셜프루프.md`

### 2.4 퀄리티 바 4축

1. **디자인** — "AI 생성 같지 않은" 손맛. 인포그래픽 원국판·오행 레이더·점수링 등 (`인포그래픽_카탈로그.md`).
2. **UX 라이팅** — 점집 톤 · AI 번역투 금지. 마이크로카피 룰 (`UX라이팅_가이드.md`).
3. **섹션 리듬** — 10섹션 × 300자 이상 + 아코디언 · 카드 · 대화형 믹스 (`섹션_아코디언.md`).
4. **지식 기반** — 6대 원전 백과사전 + 학파 매핑 (`명리학_백과사전.md`).

"사람 손이 탄 느낌" 체크: `docs/prd/사람손떼_체크리스트.md`

### 2.5 한자·전문성 이원화 (핵심 정책)

| 구분 | 한자 허용량 | 원칙 |
|------|------------|------|
| 내부 참고서 | 풍부 | 학술 깊이 확보용 |
| AI 프롬프트 | 원문·용어 다수 | 해석 정확도용 |
| **유저 출력물** | **섹션당 2~3개 이하** | "상징·프레임" 수준 |
| UI 라이트 문구 | **한자 금지 기본** | 접근성 |

- 한자 등장 시 **문장 안에 풀이가 녹아있어야** 함.
- 전문가 만족용 "마이크로 디테일"은 카드 푸터 `*[전문: 정관격/수용신]*` 식으로 별도.

상세: `docs/prd/한자노출_정책.md`

## 3. 기술 아키텍처 (Tech Architecture)

### 3.1 스택 개요
- **Frontend**: React 18 + TypeScript + Vite + Tailwind CSS
- **앱인토스**: @apps-in-toss/web-framework + @toss/tds-mobile
- **Backend**: Firebase (Auth + Firestore + Functions + Storage)
- **AI**: Claude API (Opus 4.6 메인 / Sonnet 4.6 검증 / Haiku 4.5 보조)
- **만세력**: lunar-javascript + 자체 KR 진태양시 보정 래퍼
- **결제**: 토스페이먼츠 (웹) + 토스 IAP (앱인토스)

### 3.2 계정 통합 (Multi-Platform)
```
앱인토스(토스 로그인) ─┐
                       ├→ Firebase Auth → uid
웹(카카오/구글/네이버) ─┘
```
- Phase 1: 플랫폼별 독립 uid
- Phase 2: 전화번호 기반 `linkWithCredential()` 통합

### 3.3 프롬프트 v2.1 아키텍처
1. 1차 호출 (Opus): 사주 데이터 → 10섹션 생성
2. 2차 호출 (Sonnet, 비용 절감): 1차 결과 자기 리뷰 → 톤·한자·누락 보강
3. 출력 스키마: JSON (섹션별 필드 + 메타)

Opus vs Sonnet A/B 비교는 런칭 전 P0 태스크. 순수 Sonnet 전환은 **품질 벤치 통과 시에만** 허용.

상세: `docs/prd/프롬프트템플릿_v2.1.md`
