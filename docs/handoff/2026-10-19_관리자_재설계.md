# 관리자 v4 재설계 (2026-10-19)

오너 질문: 웹 버전은 어떻게 관리하나, 어떤 데이터를 기준으로 운을 넣어 주나, 원본 데이터는 어떻게 관리하고 어떻게 다듬어 데이터베이스와 대시보드로 쓰나. 예전 관리자(6월판)는 낡았다.

## 1. 한 줄 요약

- 관리자 화면은 앱과 웹을 한 화면에서 본다(전체, 앱, 웹 전환). 주소는 그대로 `saju500.app/admin`.
- 숫자는 원본을 매번 읽지 않고, 서버가 매일 밤 만든 하루 요약 한 장(`statsDaily/날짜`)을 읽는다.
- CS 는 '고객 찾기'에 문의에 온 아무 값이나 넣으면 그 사람 카드가 나오고, 카드의 사실을 보고 사유를 골라 운을 넣는다.
- 예전 화면은 `saju500.app/admin?old=1` 에 당분간 남겨 둔다.

### 세는 기준

- 사람: 기기(did) 기준, 오너 기기(internal) 제외. 기간 합은 날마다 센 것을 더한 값(같은 사람이 이틀 오면 두 번).
- 매출: 결제 장부 기준. 같은 주문번호는 한 번(기기 이관과 결제이력 복구 중복 제외), 상태 확정, 확정된 날. 오너 계정 시험 결제 제외.
- 환불: 웹 포트원 취소는 `syncPortoneCancellations` 가 장부를 refunded 로 바꾸고 환불된 날에 잡힌다. 토스 앱 결제 환불은 아직 어디에도 기록되지 않는다(토스 콘솔에서만 보임, 아래 남은 일).
- 들어온 곳: 기기가 그날 처음 utm 을 달고 들어온 곳. 광고 주소에는 `utm_source` 를 꼭 붙인다.
- AI 비용: 토큰 단가 추정(캐시 읽기 0.1배, 쓰기 1.25배, 1달러 1,400원). 실제 청구는 Anthropic 콘솔.

## 3. 웹 회원 관리와 CS

- 찾는 값: 회원 ID(내 정보 맨 아래 '고객센터 코드', 웹도 10-19부터 보임), 문의 메일 제목 통째로(`[회원ID:…]`), 토스 기기 ID(토스 CS 콘솔), 이메일(소셜 로그인 또는 메일 신청), 결제번호(포트원 paymentId, 토스 orderId), 초대 코드, 토스 회원 번호.
- 카드: 앱인지 웹인지, 로그인 방식(카카오, 네이버, 구글, 토스, 익명), 가입과 마지막 활동, 처음 들어온 곳, 기기 잔액(기기가 알려 준 값), 결제와 상태, 쓴 운과 풀이(보관함), AI 실패, 보상 내역(받았는지), 최근 행동 30개.
- 운을 넣는 기준(사유를 고르면 운이 미리 채워진다):
  - 결제했는데 운이 안 들어옴: 그 결제의 운(보너스 포함)
  - 풀이가 안 나옴, 깨짐: 쓴 운 + 사과 2운 (예: 신년운세 7 + 2 = 9운). 잘못 만들어진 주제 결과도 같이 지울 수 있다.
  - 기록 유실, 복구됨: 10운 / 복구 안 됨: 15운
  - 불편 사과: 2운
  - 현금 환불 대신 운으로, 넉넉하게(CS 원칙). 한 번에 100운까지.
- 받는 방법: 회원 ID 로 넣으면 앱과 웹 모두에서, 토스 기기 ID 로 넣으면 그 기기에서 다시 열 때 자동으로 들어가고 알림이 뜬다. 10-19 전에는 웹 회원이 받을 길이 없었다(앱에서만 수령 코드가 돌았다). 토스 로그인 회원 ID(toss_숫자)는 형식 검사에 걸려 넣을 수 없었다. 둘 다 고쳤다.
- 모든 지급은 `compensationLog` 에 사유, 메모, 넣은 사람과 함께 남는다.
