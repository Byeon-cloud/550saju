## 1. 목적 (Goal)

**"로그인으로 인한 구매 이탈을 0에 수렴시킨다."**

500원 상품은 구매 마찰 1단위가 매출 구조를 통째로 뒤집는다. 업계 평균 "비로그인 결제 허용" 전환율 보너스가 **+20~40%**인 걸 감안하면, 로그인을 결제 이전 단계에 두는 순간 사주500의 유닛이코노믹스가 무너진다.

따라서 원칙은:

> **로그인 없이 100% 사용 가능. 로그인은 "내 자산"을 제공할 때만 요구한다.**

## 2. 핵심 결정 (Decisions)

### 2.1 로그인 구분선

| 기능 | 로그인 필요? | 이유 |
|---|---|---|
| 사주 입력 / 만세력 조회 | ❌ | 재방문도 가능해야 함 |
| 오늘의 운세 (무료) | ❌ | 영구 무료, 진입장벽 0 |
| 꿈해몽 (무료 + 블러) | ❌ | 블러가 CTA, 로그인이 CTA 아님 |
| **500원 심층분석 결제·열람** | ❌ | 전환율 최우선 |
| **5,000원 프리미엄 결제·열람** | ❌ | 같은 원칙 |
| 사주대화(상담) 시작 | ❌ | 익명 대화 가능 |
| **보관함 (리포트 영구 조회)** | ✅ | "내 자산" 가치 명확 |
| 리워드 3원 수령·출금 | ✅ | 어뷰징 방어 필요 |
| 공유 리워드 (0.5운) | ✅ | 계정 단위 한도 강제 |
| 내정보 · 프로필 편집 | ✅ | 자명 |
| 결제 내역 조회 | ✅ | 전자상거래법 계정 귀속 |

### 2.2 익명 세션 모델

**모든 비로그인 사용자에게 Firebase Anonymous Auth로 익명 uid를 즉시 발급**한다.

- 익명 uid로도 Firestore 쓰기·읽기·결제 연동 가능
- 구매 시 리포트는 `users/{anonymousUid}/reports/{rid}` 경로에 저장
- 리포트마다 `accessToken` (nanoid 16자) 자동 발급 → `/r/<accessToken>` URL로 로그인 없이 열람 가능
- 앱인토스: 구매 직후 `getTossShareLink` + `setClipboardText`로 **URL 복사 버튼** 제공
- 웹: 구매 직후 "이메일로 받기" 옵션 (선택)

### 2.3 익명→인증 이관

유저가 나중에 로그인하면:

1. 앱인토스: `appLogin()` → 서버에서 토큰 교환 → Firebase Custom Token 발급 → `signInWithCustomToken`
2. 웹 (Phase 2): 카카오 OAuth → Firebase Custom Token → `signInWithCustomToken`
3. `linkWithCredential()`로 익명 uid에 인증 정보 연결 ← 데이터 이관 불필요
4. 단, 이미 해당 인증 정보로 가입된 계정이 있으면 **Cloud Function `mergeAccounts`** 호출 → Firestore 서브컬렉션 이관 + 익명 uid tombstone

### 2.4 앱인토스 특화

- 미니앱 진입 시 `getIsTossLoginIntegratedService()` 체크
  - `true` → 토스 인증 유저. 최초 1회만 `appLogin()` 자동 호출 가능 (동의 UI는 필수)
  - `false` → 토스 로그인 미연동. 완전 익명 세션 유지
- 토스 세션은 기기 변경에도 유지되므로 **앱인토스 내에선 "로그인 이탈"이라는 개념이 사실상 없음** — 자연스러운 유인 시점에만 제안
- `getUserKeyForGame`는 게임용 API라 사주500에서는 미사용. 식별은 토스 OAuth 경로로만.

### 2.5 웹 특화

- Phase 1: Firebase Anonymous Auth만 사용. 쿠키 기반 uid 유지.
- Phase 2: 카카오 원탭 로그인 추가. 네이버·구글은 요청 생기면 추가.
- 브라우저 데이터 삭제 시 익명 uid 소실 → "이메일 입력 시 복구 링크 발송" 옵션으로 보완.

## 3. 유저 스토리 (User Stories)

### US-01. 완전 익명 첫 구매
> *수아(24, 여, 앱인토스로 진입)는 인스타에서 "500원 사주 소름" 짤을 보고 앱인토스로 왔다. 로그인 화면 없이 바로 생년월일 입력 → 500원 결제 → 리포트 열람. 소요 시간 2분 30초.*

### US-02. 익명 구매 후 재방문
> *수아는 3일 뒤 다시 왔다. 토스 세션이 유지되어 있어 바로 보관함 배너가 뜸: "지난번 리포트 열람하기". 클릭 → 열람.*

### US-03. 익명 → 로그인 전환
> *2주 후 수아는 친구 궁합 기능을 쓰려 한다. "공유 리워드 0.5운을 받으려면 로그인이 필요해요" 다이얼로그 등장. 수아가 `appLogin()` 동의. 기존 익명 uid에 토스 계정 연결. 데이터 이관 자동.*

### US-04. 기기 변경 복구 (웹)
> *민지(29, 여, 웹 사용자)는 폰 기변 후 "나의 리포트"가 사라졌다. 이전에 이메일을 입력해 뒀기에, 이메일로 복구 링크 클릭 → 기존 익명 uid 복원.*

### US-05. 로그아웃
> *수아가 로그아웃을 누른다. 다이얼로그: "로그아웃하면 보관함은 숨겨지지만, 리포트 열람 URL은 그대로 사용 가능해요. 계속하시겠어요?" → 확인. 앱은 **비로그인 모드**로 fallback, 세션은 유지.*

### US-06. 중복 계정 병합
> *수아가 앱인토스로 익명 구매한 뒤, 웹에서 카카오 로그인을 하려 한다. 카카오 이메일과 토스 전화번호가 같다고 감지 → "기존 토스 계정과 통합할까요?" 팝업. 확인 시 서브컬렉션 이관. (Phase 2)*

## 4. 화면 · 인터랙션 (Screen Flow)

### 4.1 랜딩(홈)
- 로그인 버튼 **우측 상단 아이콘으로만** 존재 (TDS `NavigationBar` 우측 슬롯)
- 로그인 안 해도 "사주 입력하기" CTA는 항상 최상위 노출
- 배너 "로그인하면 보관함 이용" 타입 배너 **없음** (진입 마찰)

### 4.2 결제 직전
- **로그인 프롬프트 절대 금지**
- TossPay (앱인토스) or 토스페이먼츠 (웹) 바로 호출
- 결제 성공 → 리포트 생성 중 로딩 → 결과 페이지

### 4.3 결과 페이지 하단 "보관 제안" (로그인 유인 1)
구매 완료 리포트 조회 시 하단에 은은하게:

```
┌─────────────────────────────────────────────┐
│  이 리포트를 보관함에 저장할까요?             │
│  토스 로그인하면 언제든 꺼내 볼 수 있어요.    │
│  [나중에]            [저장하기]              │
└─────────────────────────────────────────────┘
```

- 스크롤이 80% 도달한 시점에 슬라이드-업 (AI 해석을 다 읽은 직후)
- "나중에" 누르면 24시간 재노출 금지
- 로그인 없이도 URL 토큰은 이미 발급됨 — "저장하기"는 편의 기능이라고 메시지에 명시

### 4.4 세 번째 방문 시 "보관함 연결" (로그인 유인 2)
- 3회 이상 진입하고 미로그인 상태면, 홈 진입 시 1회 한정 모달
- "벌써 세 번째 찾아주셨네요. 보관함을 연결하면 그간의 명조가 모두 복원됩니다."
- 거절 시 30일간 재노출 없음

### 4.5 기능별 로그인 요구 시점
- 공유 리워드 버튼 탭 → "리워드 수령에는 로그인이 필요해요" → `appLogin()`
- 보관함 탭 → "보관함은 로그인 후 이용해요" → 버튼 중앙 1개
- 내정보 → 동일

### 4.6 로그아웃
- 설정 페이지 최하단
- 다이얼로그: **"로그아웃해도 리포트 URL은 그대로 사용할 수 있어요. 보관함만 숨겨집니다."**
- 확인 시 익명 모드로 fallback (새 익명 uid 발급 X, 익명→인증 연결만 해제)

## 5. 데이터 모델 (Firestore)

### 5.1 users 컬렉션

```
users/{uid}
├─ authMethod: 'anonymous' | 'toss' | 'kakao' | 'google' | 'naver' | 'apple'
├─ linkedAt: timestamp | null        // 익명→인증 연결 시각
├─ isAnonymous: boolean              // 빠른 필터용 복제 플래그
├─ phone: string | null              // hashed (sha256)
├─ email: string | null              // hashed (sha256)
├─ tossCi: string | null             // 앱인토스 전용
├─ createdAt: timestamp
├─ lastActiveAt: timestamp
├─ entryPlatform: 'apps-in-toss' | 'web'
└─ mergedFrom: string[] | null       // tombstone된 이전 uid들
```

### 5.2 리포트 접근 토큰

```
users/{uid}/reports/{rid}
├─ accessToken: string               // nanoid 16자, URL 공유용
├─ tokenRevoked: boolean             // 유저가 수동 폐기 가능
├─ purchasedVia: 'anonymous' | 'authed'
└─ ... (기존 리포트 필드)
```

- 접근 경로: `/r/<accessToken>` (공개) 또는 `/my/reports/<rid>` (로그인 필수)
- `accessToken`은 유저가 "URL 공유 끄기"로 폐기 가능

### 5.3 merge 이력

```
merges/{mergeId}
├─ fromUid: string
├─ toUid: string
├─ reason: 'link' | 'phone-match' | 'email-match'
├─ migratedCounts: { reports: number, payments: number, ... }
├─ executedAt: timestamp
└─ executedBy: 'client' | 'cloud-function'
```

## 6. 상태 분기 · 엣지케이스 (Edge Cases)

| # | 케이스 | 처리 |
|---|---|---|
| E-01 | 앱인토스 진입 + `getIsTossLoginIntegratedService()` false | 익명 세션만 유지, 로그인 UI 노출하지 않음 |
| E-02 | 앱인토스 진입 + true + 미연동 유저 | 랜딩은 익명으로. 로그인 유인 시점까지 대기 |
| E-03 | 앱인토스 진입 + true + 연동 유저 | 토스 세션 감지 시 **자동으로 조용히** `signInWithCustomToken` 수행 (UI 변화 없음) |
| E-04 | 결제 진행 중 세션 만료 | 결제는 webhook으로 서버 기록 → 재진입 시 토큰으로 리포트 연결 |
| E-05 | 결제 완료 후 앱 강제 종료 | 재진입 시 구매 감지 → "완료된 리포트 확인" 배너 |
| E-06 | 브라우저 쿠키 삭제 (웹) | 새 익명 uid 생성됨. 이전 리포트 URL 토큰을 갖고 있으면 조회 가능. 이메일 복구 옵션 안내. |
| E-07 | 동일 유저가 앱인토스 + 웹 둘 다 사용 | Phase 1 = 별도 계정. Phase 2 = 전화번호 해시 매칭으로 병합 제안 |
| E-08 | 익명 uid에 쌓인 데이터 大 + 로그인 후 이관 | Cloud Function 트랜잭션. 30초 이상 걸리면 "이관 중…" UI 표시 |
| E-09 | 로그인 이미 된 계정에 다른 로그인 추가 | "계정 병합" 다이얼로그 → Cloud Function `mergeAccounts` |
| E-10 | `appLogin()` 중 유저가 앱 전환 (메모리 회수) | `useWaitForReturnNavigator` 훅으로 복귀 감지, 세션 재검증 |
| E-11 | 공유 URL 토큰으로 접근한 비소유자 | 읽기 전용 모드, "보관함에 저장" 버튼만 활성 (본인 로그인 시) |
| E-12 | `tokenRevoked: true` 리포트 URL 재사용 시도 | 404 페이지 + "소유자에게 문의" 안내 |
| E-13 | 동일 기기 다중 유저 (가족 공유) | 세션은 기기 단위. 로그아웃 → 새 익명 세션으로 완전 분리 |
| E-14 | 오프라인 상태 결제 시도 | 결제 호출 자체가 불가. 익명 세션 유지 |
| E-15 | Firebase Anonymous Auth 실패 (rate limit) | 10초 후 1회 재시도. 2회 실패 시 "잠시 후 다시 시도해주세요" |

## 7. 수용 기준 (Acceptance Criteria)

- [ ] AC-01 비로그인 상태로 사주 입력 → 결제 → 리포트 열람 **단 하나의 로그인 화면도 거치지 않고** 완주 가능
- [ ] AC-02 결제 직전 로그인 프롬프트가 **절대** 노출되지 않음 (코드 리뷰·E2E 모두)
- [ ] AC-03 구매 직후 `accessToken` URL 발급, 클립보드 복사 버튼 노출
- [ ] AC-04 앱인토스 진입 시 0.8초 이내 익명 세션 확립
- [ ] AC-05 보관함 탭 진입 시에만 로그인 버튼 노출 (중앙 1개)
- [ ] AC-06 익명 → 로그인 이관 시 데이터 유실 0건, 이관 실패율 < 1%
- [ ] AC-07 3회 재방문 후 보관함 모달 1회 노출, 거절 시 30일간 재노출 없음
- [ ] AC-08 로그아웃 다이얼로그에 "리포트 URL은 유지된다"는 안내 포함
- [ ] AC-09 모든 로그인 유인 다이얼로그의 "나중에" 버튼이 주(primary)가 아닌 보조(secondary) 스타일
- [ ] AC-10 Firestore Rules에서 `tokenRevoked: true` 리포트 접근 차단
- [ ] AC-11 익명 uid에 쌓인 리포트가 5건 이상일 때 이관 UI 표시
- [ ] AC-12 세션 만료 후 결제 재개 시 "결제 이미 처리됨" 감지 → 중복 결제 방지
- [ ] AC-13 웹 익명 유저가 이메일 입력 시 복구 링크 발송 (24시간 유효)
- [ ] AC-14 로그인 유인 시점에 "로그인하면 데이터 유실 방지" 대신 "보관함 이용" 카피 사용 (공포 아닌 가치)
- [ ] AC-15 앱인토스 `setSecureScreen` 활성화 (결제·보관함 화면 스크린샷 방지)

## 8. 테스트 케이스 (TC)

### 8.1 기본 플로우
- **TC-L01** 익명 상태 → 500원 결제 완료 → 리포트 열람 성공
- **TC-L02** 익명 구매 후 즉시 `appLogin()` → 보관함에 리포트 이관 확인
- **TC-L03** 익명 구매 URL 토큰으로 다른 기기(쿠키 초기화 후)에서 열람 성공
- **TC-L04** 앱인토스 `getIsTossLoginIntegratedService()` true + 첫 방문 시 `signInWithCustomToken` 자동 실행 없음 (UI 변화 없음)
- **TC-L05** 익명 uid로 10회 접속 후에도 동일 uid 유지

### 8.2 데이터 이관
- **TC-L06** 익명 uid 5개 리포트 + 로그인 → Cloud Function으로 전량 이관, `merges/` 기록 생성
- **TC-L07** 이관 중 Firestore 장애 → 트랜잭션 롤백 후 유저에게 재시도 안내
- **TC-L08** 중복 이메일 로그인 → `mergeAccounts` 호출, tombstone 생성

### 8.3 세션·복구
- **TC-L09** 웹 쿠키 삭제 후 이메일 복구 링크로 기존 uid 복원 성공
- **TC-L10** 결제 중 세션 만료 → 결제 webhook 수신 → 재진입 시 리포트 열람 성공
- **TC-L11** 로그아웃 → 새 세션(다른 익명 uid) → 기존 URL 토큰으로는 여전히 열람 가능

### 8.4 엣지
- **TC-L12** `tokenRevoked: true` 리포트 URL 접근 시 404
- **TC-L13** `appLogin()` 도중 유저가 앱 백그라운드 전환 → 복귀 시 세션 재검증 성공
- **TC-L14** Anonymous Auth rate limit 도달 시 재시도 로직 동작
- **TC-L15** 오프라인 상태에서 결제 버튼 클릭 → 사전 체크로 "네트워크 연결 필요" 안내

### 8.5 마찰 감지 (E2E · 자동화 필수)
- **TC-L16** 결제 완주 플로우 전 구간 스크린샷 15장 + 로그인 관련 UI 픽셀 감지 → 0건
- **TC-L17** Playwright 스크립트로 "로그인", "login", "sign in", "인증", "가입" 문자열 결제 경로에서 탐지 → 0건
- **TC-L18** 랜딩 → 결제 완료까지 총 탭 수 측정 → 앱인토스 ≤ 7탭, 웹 ≤ 8탭

## 9. 리스크 · 의문점 (Open Questions)

1. **리포트 URL 토큰 유효기간** — 무기한? 1년? 유저가 삭제 요청 시 즉시 폐기는 필수이고, 자동 만료는 UX 호불호가 갈림. 내 제안: **무기한 + 유저 수동 폐기**.
2. **앱인토스 유저가 웹으로 올 때** — 전화번호 해시 매칭 정밀도 문제. Phase 2에서 정확도 95% 이상 확보 전까진 자동 병합 금지, 수동 제안만.
3. **GDPR/개인정보보호법** — 익명 uid도 "개인정보"로 해석될 수 있음(기기 식별 가능). 익명 세션에도 개인정보 처리방침 명시 필요.
4. **Firebase Anonymous Auth 수량 제한** — Firebase 무료 플랜 100건/초. MAU 10만 규모에서 peak 이슈 가능성 점검.
5. **토스 OAuth 토큰 갱신 주기** — `appLogin()`의 authorization code 10분 유효. access token 만료 시점 재인증 UX 설계 필요 (백그라운드 자동 갱신 시도).
