## 1. 의도 (Why)

| 레이어 | 목적 |
|--------|------|
| 1 | **매일 들어올 명분** — 사주 8글자는 평생 안 바뀌니까 매일 볼 이유 없음. 출석 도장으로 "오늘은 0.1운 받으러 들어가자" 핑계 만들기 |
| 2 | **결제 마중물** — 0.1운씩 모이는 게 잔액바에 보이면 "10번 더 들어오면 한 번 분석" 카운트다운 인지 → 결제 저항 0.1운만큼 깎임 |
| 3 | **도파민 마이크로 보상** — 매일 +0.1, 토스트 한 줄, 잔액바 깜박임 → "사주500 = 매일 가는 곳" 습관화 |
| 4 | **앱인토스 채널 펌프** — 토스 미니앱은 "최근 사용" 으로 노출 결정. 매일 들어오면 토스 추천 알고리즘이 끌어올림. 공짜 마케팅 |

## 2. 등장 위치 (Where) — 정확한 명세

### 2.1 메인 등장 — DailyFortunePage 헤더
- **위치**: `/daily` 페이지 헤더 바로 아래, 사주 4기둥 위
- **조건**: `hasAnyProfile === true` (본인 사주 1개 이상 등록 시)
- **컴포넌트**: `<DailyRewardBadge />` (이미 P2-5 에 구현)
- **3-state 시각화**:
  - **a. 미수령 (오늘 첫 방문)**: 골드 강조 카드 "오늘의 출석 도장 → +0.1운 받기" CTA
  - **b. 수령 완료 (오늘 이미 받음)**: 회색 톤 "오늘 출석 완료 · N일 연속" 정보 카드
  - **c. 월 한도 초과 (30회 다 채움)**: 차분한 카피 "이번 달 출석을 마쳤어요 · 다음 달 1일 리셋"

### 2.2 보조 등장 — HomePage 잔액바
- **위치**: 홈 상단 고정 잔액바 옆 작은 배지
- **조건**: 미수령 상태일 때만 노출 (수령 후 사라짐)
- **렌더**: 작은 골드 점(8px) + "출석 0.1운" 텍스트 (호버 시 `/daily` 이동)
- **이유**: 데일리 페이지를 안 들어가는 유저도 동선에 노출

### 2.3 알림 — Toast (수령 직후)
- **트리거**: `claimDailyReward()` 호출 성공 후
- **카피**: "+0.1운이 지갑에 들어왔어요" (이모지 없음, 평문)
- **추가**: streak 보너스 트리거 시 "+1운 보너스 · 7일 연속 출석" 별도 토스트

## 3. 출석 도장 게임화 (확장 — v1 신규)

### 3.1 시각화 — 30칸 도장판
- **위치**: `/daily` 페이지 데일리 리워드 배지 아래 접기/펼치기 카드
- **렌더**: 6×5 그리드 30칸 (이번 달 출석일)
- **상태**:
  - 출석한 날: 골드 채움 + 작은 한자 印(인) 박힘 (도장 메타포)
  - 미출석 (지난 날): 회색 X
  - 미출석 (미래 날): 흰색 빈 칸
  - 오늘 (미수령): 골드 외곽선 깜박임 + "TODAY" 라벨
- **카피**: "이번 달 N회 출석 · 매일 +0.1운"

### 3.2 Streak 보너스 (이동 윈도우)
| Streak | 보너스 | 카피 |
|--------|--------|------|
| 7일 연속 | +1운 (=500원 상당) | "7일 연속 출석 · +1운 보너스 적립" |
| 14일 연속 | +2운 | "14일 완주 · +2운 보너스 적립" |
| 30일 만석 | +5운 + 다음 달 첫 분석 10% 할인 | "이번 달 매일 출석 · +5운 + 할인 쿠폰 발급" |

- **이동 윈도우**: 지난 7일 중 7일 모두 출석 → 보너스. 8일째도 출석하면 새 streak 시작 (즉, 일요일 깜빡해도 다시 도전 가능)
- **인수인계 §7.P2-5 ("streak 운1 · 7일완주 토스포인트 100원") 정책 흡수**

### 3.3 카피·문구 톤
- 격식체 50%, 친근체 30%, 학술 20%
- 예시:
  - 미수령 CTA: "오늘의 출석 도장을 찍어보세요"
  - 수령 후: "오늘도 사주500과 함께해주셔서 감사합니다"
  - 한도 초과: "이번 달 출석을 모두 마치셨습니다 · 다음 달 1일에 다시 시작됩니다"

## 4. 데이터 모델

### 4.1 Phase 1 (현재 — localStorage)
- `saju500:daily_reward:last` — 마지막 수령일 ISO 문자열
- `saju500:daily_reward:month` — `{ year, month, count }` 월별 카운터
- **신규 추가** `saju500:daily_reward:streak` — `{ currentStreak, lastClaimDate, longestStreak }`
- **신규 추가** `saju500:daily_reward:claimedDates` — `["2026-04-22", "2026-04-21", ...]` (이번 달 출석일 배열, 30칸 시각화용)

### 4.2 Phase 2 (Firestore 이관 — 어뷰징 방어)
- `users/{uid}/dailyReward/{YYYY-MM}` — 월별 도큐먼트
  - `claimedDates: string[]`
  - `monthCount: number`
  - `currentStreak: number`
  - `longestStreak: number`
- `markAttendance` Cloud Function 으로 atomic 처리 (이미 부분 구현 — eventsClient.ts)

## 5. 어뷰징 방어 (Phase 1 → Phase 2)

| 시나리오 | Phase 1 (현재) | Phase 2 (이관 후) |
|---------|---------------|------------------|
| 시계 조작 (오늘 날짜 임의 변경) | localStorage 키 + 클라 시간 비교 (취약) | 서버 타임스탬프로 검증 |
| 다중 디바이스 중복 수령 | 디바이스별 카운트 (취약) | uid 기반 글로벌 카운트 |
| localStorage 초기화 후 재수령 | 가능 (취약) | 서버 기록으로 차단 |
| 봇 자동 클릭 | 검증 X | reCAPTCHA v3 + 행동 패턴 분석 |

**현재 결정**: Phase 1 그대로 출시 (어뷰징 손실 < 신규 유저 획득). Phase 2 는 DAU 1만 도달 후 우선순위 격상.
