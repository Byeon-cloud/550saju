## 1. 목적 (Goal)

**"로딩을 '기다림'이 아니라 '의식'으로 바꾼다."**

AI 리포트 생성은 20~60초 걸린다. 기계적 스피너 + "잠시만 기다려주세요" 는 이탈의 가장 큰 원인. 반면 사주아이처럼 **로딩을 여러 단계로 나누어 각 단계에 서사를 입히면**, 유저는 "분석이 진행되고 있다"는 안정감과 "뭔가 진지하게 뽑히고 있다"는 신뢰감을 동시에 얻는다.

**전략 요약:**
1. 로딩을 **3단계**로 분할 — 각 단계는 명확한 산출물.
2. 각 단계에 **인터랙티브 카피** + **시각적 산출물(만세력 표 등)**.
3. **체감 속도 최적화** — 실제 생성 중에도 유저는 "이미 뭔가 보고 있다".

**성공 지표:**
- 리포트 생성 전 이탈률 ≤ 5% (업계 평균 20~30%).
- "로딩이 길어서 떠났다" 피드백 비중 ≤ 3%.
- 평균 체감 로딩 시간 ≤ 실제 시간의 60% (유저 설문 기반).

## 2. 로딩 3단계 설계

### 2.1 전체 플로우

```
[ 유저 결제/진입 ]
       ↓
┌──────────────────────────┐
│  1단계: 만세력 추출       │  ~2초
│  (Saju Pillars Extracted) │
└──────────────────────────┘
       ↓
┌──────────────────────────┐
│  2단계: 오행·십성 분석    │  ~3초
│  (Element Analysis)       │
└──────────────────────────┘
       ↓
┌──────────────────────────┐
│  3단계: AI 해석 생성      │  ~15~45초 (스트리밍)
│  (AI Interpretation)      │
└──────────────────────────┘
       ↓
[ 리포트 페이지 이동 ]
```

- **1, 2단계는 즉시 실행** — 만세력은 lunar-javascript로 수 밀리초. 시각적으로 2~3초 연출 추가.
- **3단계만 실제 대기 발생** — Claude API 스트리밍. 스트리밍 덕에 체감 속도 대폭 단축.

### 2.2 단계별 화면

#### 2.2.1 1단계: 만세력 추출

```
┌─────────────────────────────────┐
│                                 │
│    당신의 시간을 읽고 있어요   │
│                                 │
│    1998년 3월 3일 05시          │
│    ↓ 한국 진태양시 보정 (-30분)│
│    1998년 3월 3일 04시 30분     │
│                                 │
│    ■■■■□□□□  33%                 │
│                                 │
└─────────────────────────────────┘
```

**표시 내용:**
- 원본 시각 → 보정 시각 (30분 보정 설명 겸)
- 낮은 진행바 (33%)
- 하단 카피: "잠시만요. 우주의 배열을 맞추는 중이에요."

**연출:**
- 시계 애니메이션 (은은한 초침 회전).
- 골드브라운 포인트 색.

#### 2.2.2 2단계: 사주 원국 완성

```
┌─────────────────────────────────┐
│                                 │
│    당신의 사주가 모였어요       │
│                                 │
│    ┌──┬──┬──┬──┐                │
│    │辛│乙│甲│戊│                │
│    │巳│酉│寅│寅│                │
│    └──┴──┴──┴──┘                │
│     시  일  월  년              │
│                                 │
│    오행 배치 분석 중…           │
│                                 │
│    ■■■■■■□□  66%                │
│                                 │
└─────────────────────────────────┘
```

**표시 내용:**
- **사주 원국 4기둥 즉시 공개** (이미 계산됨, 로딩 연출만)
- 오행 배치 각 한자 아래 색상 컬러 바 애니메이션
- 진행바 66%
- 하단 카피: "천간과 지지가 만나는 자리를 보고 있어요."

**연출:**
- 기둥 4개가 순차적으로 떨어지듯 등장 (0.3s 간격 × 4).
- 오행 색상(木 녹색 / 火 빨강 / 土 노랑 / 金 회색 / 水 파랑)이 글자 뒤에서 번짐.

#### 2.2.3 3단계: AI 해석 생성

```
┌─────────────────────────────────┐
│                                 │
│    당신의 이야기를 적는 중이에요│
│                                 │
│    ────────────────             │
│    총평                         │
│    당신은 겉은 단단하지만…      │
│    (스트리밍 중)                │
│    ────────────────             │
│                                 │
│    성격의 뼈대 ▒▒▒▒▒           │
│    대인관계    ▒▒▒▒▒           │
│    직업·재능   ▒▒▒▒▒           │
│                                 │
│    ■■■■■■■■□  85%                │
│                                 │
└─────────────────────────────────┘
```

**표시 내용:**
- 첫 섹션(총평)이 **실시간 스트리밍**으로 타이핑됨.
- 하위 9섹션은 제목만 노출, 본문은 ▒▒ 블럭 플레이스홀더.
- 진행바는 섹션 완료 기반 (총 10섹션, 1섹션당 10%).

**연출:**
- 타이핑 효과 (약 40자/초, 사람 타이핑 속도).
- 섹션 완료 시 ▒▒ 플레이스홀더가 골드 라인과 함께 본문으로 전환.
- 하단 카피 회전:
  - "당신의 기질을 헤아리는 중…"
  - "대인관계의 결을 보고 있어요…"
  - "재물의 흐름을 추적 중…"

### 2.3 단계 전환

- 각 단계는 **slide-up fade** 전환 (0.4s).
- 카피는 **typewriter 진입** (0.6s).
- 긴 3단계 내부는 슬라이드 전환 없이 제자리 업데이트.

## 3. 체감 속도 최적화 (Perceived Performance)

### 3.1 Progressive Rendering

- 3단계에서 AI 응답을 **스트리밍으로 수신** (Claude `stream: true`).
- 섹션별 JSON 객체 완성 시마다 플레이스홀더 교체.
- **첫 섹션 공개까지 5~8초** 목표.

### 3.2 Skeleton 상태

- 각 섹션 제목은 **서버에서 미리 확정된 순서**로 즉시 노출 (AI 응답 전).
- 본문만 ▒▒.
- 이로써 유저는 "앞으로 10섹션이 나올 것"을 미리 이해 → 기대감 + 안정감.

### 3.3 Prefetch

- 만세력 추출은 유저 "생성 요청" 직전에 프리페치 가능.
- 예: 입력 완료 → 결제 CTA 노출 시점에 만세력 계산 트리거 → 결제 완료 시점엔 이미 완성.
- **결제 → 리포트 렌더 지연 최소화.**

### 3.4 실제 지연 시나리오

| 시점 | 실제 작업 | 유저 체감 |
|---|---|---|
| 0.0s | 결제 성공 → 로딩 진입 | 1단계 화면 시작 |
| 0.5s | 만세력 완료 | 1단계 "33%" 진행 중 |
| 2.0s | 1단계 종료 → 2단계 진입 | 사주 원국 공개 |
| 5.0s | 2단계 종료 → 3단계 진입 | AI 스트리밍 시작 |
| 7.0s | 첫 섹션 스트리밍 50% | 총평 읽을 수 있음 |
| 15.0s | 3~4 섹션 완료 | 일부 섹션 완독 가능 |
| 35.0s | 10섹션 모두 완료 | 리포트 페이지 자동 이동 |
| 40.0s | 리포트 페이지 안정 | 완전 전환 |

**핵심:** 유저는 5초 시점부터 이미 본문(총평)을 읽기 시작. 나머지 30초는 "더 읽을 게 생기는" 느낌.

## 4. 인터랙티브 카피 (Rotating Copy)

### 4.1 단계별 카피 풀

**1단계 (만세력):**
- "잠시만요. 우주의 배열을 맞추는 중이에요."
- "시간을 되돌려 당신이 태어난 순간을 보고 있어요."
- "한국의 진태양시로 보정하고 있어요."

**2단계 (사주 배치):**
- "천간과 지지가 만나는 자리를 보고 있어요."
- "오행의 균형을 재고 있어요."
- "십성의 자리를 확인 중이에요."

**3단계 (AI 해석):**
- "당신의 기질을 헤아리는 중…"
- "대인관계의 결을 보고 있어요…"
- "재물의 흐름을 추적 중…"
- "애정의 파동을 읽고 있어요…"
- "올해의 운을 가늠 중이에요…"
- "개운의 실마리를 찾는 중…"

### 4.2 회전 규칙

- 3초마다 다음 카피로 페이드 전환.
- 풀에서 순환, 랜덤 아님 (예측 가능성으로 안정감).
- 2/3단계에서는 **실제 진행 상황과 매칭** — "재물의 흐름을" 은 실제로 재물 섹션 생성 중일 때.

### 4.3 브랜드 톤

- 존댓말 + 시적 호흡.
- 이모지 0개.
- 쿨다운 단어: "정성껏" "조심스럽게" "깊이" (남용 금지).

## 5. 실패·재시도

### 5.1 단계별 실패 처리

| 단계 | 실패 원인 | 처리 |
|---|---|---|
| 1 | 만세력 계산 오류 | 즉시 "다시 시도" 버튼, 리워드 차감 없음 |
| 2 | 오행 분석 오류 | 자동 재시도 1회, 실패 시 1단계와 동일 |
| 3 | Claude API 오류 | 자동 재시도 3회, 각 시도 5초 간격. 모두 실패 시 자동 환불 + "잠시 후" 안내 |

### 5.2 부분 성공 처리

- 3단계에서 10섹션 중 일부만 실패 시:
  - 성공 섹션은 정상 노출
  - 실패 섹션은 "이 부분은 잠시 후 다시 생성돼요" 표시
  - 백그라운드에서 재시도 → 성공 시 자동 업데이트

### 5.3 이탈 후 복귀

- 결제 완료 후 로딩 중 유저가 이탈
- 서버는 리포트 생성 백그라운드로 지속
- 복귀 시 `/r/:token` 링크 또는 보관함에서 완성된 리포트 바로 확인
- 이탈자에게는 "리포트 준비 완료" 푸시 (옵트인 유저만)

## 6. 기술 명세

### 6.1 스트리밍 구현

```ts
// src/services/ai/reportGenerator.ts
async function* streamReport(sajuData: SajuData): AsyncGenerator<SectionPartial> {
  const response = await claude.messages.stream({
    model: 'claude-sonnet-4-5',
    messages: [...],
    stream: true,
  });
  
  let buffer = '';
  for await (const chunk of response) {
    if (chunk.type === 'content_block_delta') {
      buffer += chunk.delta.text;
      
      // JSON 섹션 완성 감지
      const completed = tryParseCompletedSection(buffer);
      if (completed) {
        yield completed;
        buffer = remainder(buffer, completed);
      }
    }
  }
}
```

### 6.2 프론트 렌더

```tsx
function LoadingPage() {
  const [stage, setStage] = useState<1 | 2 | 3>(1);
  const [sections, setSections] = useState<Section[]>([]);
  
  useEffect(() => {
    stage1().then(() => setStage(2));
    stage2().then(() => setStage(3));
    stream3((section) => {
      setSections((prev) => [...prev, section]);
      if (sections.length + 1 === 10) navigateToReport();
    });
  }, []);
  
  return <StagedLoader stage={stage} sections={sections} />;
}
```

### 6.3 서버 파이프라인

- Cloud Function `generateReport`:
  1. Firestore에 `reports/{rid}` 문서 생성 (`status: 'processing'`).
  2. 만세력 계산 → 저장.
  3. Claude API 스트리밍 호출 → 섹션별 저장.
  4. 완료 시 `status: 'done'`.
  5. 클라이언트는 Firestore 실시간 구독으로 업데이트.

### 6.4 폴백 모드

- 클라이언트 스트리밍 실패 시 → 2초 폴링으로 Firestore 문서 구독.
- 모바일 네트워크 불안정 환경 대응.

## 7. 유저 스토리

### US-01. 체감 속도 만족
> *지은(27, 여). 결제 후 5초 만에 총평을 읽기 시작. 20초 더 기다리는 동안 본문을 읽으며 "진짜 분석되고 있네" 느낌. 이탈 없음.*

### US-02. 느린 3G 환경
> *태현(33, 남, 지하철). 3단계 스트리밍 지연. 하지만 1·2단계 애니메이션이 의식처럼 느껴져 "기다릴 만하다" 감정. 완주.*

### US-03. AI 오류 후 복구
> *수아(24, 여). 3단계 도중 Claude API 오류. 자동 재시도 3회 후 성공. 유저는 "당신의 이야기를 다시 적고 있어요" 메시지만 봄. 리워드 차감 없음.*

### US-04. 이탈 후 복귀
> *민준(29, 남). 결제 후 로딩 중 카톡으로 이탈. 5분 후 복귀. 보관함에 완성된 리포트 확인.*

## 9. 수용 기준 (Acceptance Criteria)

| ID | 기준 |
|---|---|
| AC-01 | 로딩은 3단계로 분할 (만세력·오행·AI) |
| AC-02 | 각 단계에 인터랙티브 카피와 진행률 노출 |

## 11. 오픈 퀘스천

1. **1·2단계 연출 길이** — 2초·3초가 적절한가. 체감 "빠름" vs "의식" 트레이드.
2. **카피 풀을 유저별로 개인화할지** — "재물"이 중요한 유저에게 관련 카피 우선. 엔지니어링 비용 대비 효과.
3. **BGM 넣을지 말지** — 의식 분위기 강화 vs 소음 거부감. 기본 OFF + 옵션 ON 추천.
4. **오행 색상 연출이 너무 화려한 건지** — "AI 같지 않은" 원칙과 조화 필요.
5. **스트리밍 우선 vs 배치 우선** — 섹션 단위 JSON 배치가 안정성 높음. Phase 1은 스트리밍 시도, 안정성 이슈 시 배치로 폴백.
6. **사주아이의 로딩 카피를 그대로 벤치마킹 가능한가** — 표현 복제는 금지, 구조만 차용.
7. **PDF 생성 4단계를 별도 UI로 분리할지** — 3단계 완료 후 이동, PDF는 리포트 페이지에서 비동기 생성 + 알림.
