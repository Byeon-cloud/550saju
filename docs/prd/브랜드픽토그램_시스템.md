# 브랜드 픽토그램 시스템 PRD

> **목적**: 이모지를 대체하여 **"AI같지 않은, 손맛 있는, 일관된"** 공식 픽토그램 세트를 구축한다.
> **작성일**: 2026-04-18
> **근거 지시**: 준기 2026-04-18 — "3D 이미지는 AI 같고, 한자만 쓰면 딱딱하다. 조화가 중요하다. 이모지보다는 픽토그램이나 직접 만든 이미지(우리 브랜드 공식 컴포넌트)를 일관성 있게 사용해달라."

---

## 0. 왜 이 시스템이 필요한가

### 문제
- 현재 Dream/Topic/Daily 페이지에 유니코드 이모지(🌿🔥🌊💰 등) 사용 → **"AI 같아 보이는" 퀄리티 하락**.
- 플랫폼별 이모지 렌더링 편차(iOS/Android/Win) → 브랜드 일관성 파손.
- 3D 이미지(Notion AI풍) 는 오히려 AI 티가 더 남.
- 한자만 쓰면 너무 학술적·딱딱함.

### 해결 원칙 — "한자 ↔ 픽토그램 ↔ 카피" 3중 조화
1. **한자는 상징·프레임으로만** (섹션당 2~3개 이하, 한자노출_정책 참조)
2. **픽토그램은 의미 보조** (카테고리 식별, 목록 스캔 개선)
3. **카피가 핵심** (UX라이팅_가이드 참조)

→ 셋 중 하나만 두드러지면 실패. **세 요소가 조화**될 때 "손맛"이 나온다.

## 1. 시각 스타일 원칙

### 1.1 라인 & 톤
- **스트로크**: 1.5px (24×24 viewBox 기준), `strokeLinejoin="round"`
- **필 스타일**: `fillOpacity="0.1~0.2"` 의 아웃라인+소프트 필 (기존 Icons.tsx 일관)
- **컬러**: 오행 팔레트 + 브랜드 골드/네이비. 유채도 중간. 원색 금지.
- **무드**: 미니멀 · 모던 · 약간 고전적(동양화 느낌 한 스푼)

### 1.2 반드시 피할 것
- ❌ 3D 렌더링 아이콘 (Notion AI · Pitch 스타일)
- ❌ 플랫 만화 스타일 (이모지 복제)
- ❌ 그라데이션 과다
- ❌ 텍스처(나무결·대리석) 넣은 아이콘

### 1.3 허용되는 것
- ✅ 2D 라인 아트 + 20% 이하 소프트 필
- ✅ 오행 컬러(목=#2D8A4E / 화=#D32F2F / 토=#F57F17 / 금=#757575 / 수=#1565C0) 매핑
- ✅ 브랜드 골드(#C9A96E) 강조
- ✅ 가끔의 동양 고전 심볼(태극·주역·부적 변형). 점집 톤이 되지 않도록 추상화.

## 2. 컴포넌트 구조

### 2.1 파일 조직

```
src/components/brand/
├── Icons.tsx             # UI 기본 (Home·Back·Share·Close 등) — 기존
├── OhengIcons.tsx        # 오행 목화토금수 — 기존
├── Logo.tsx              # 브랜드 로고 — 기존
├── DreamIcons.tsx        # 꿈 카테고리 9종 — 신규
├── TopicIcons.tsx        # 주제 분석 10종 — 신규
├── ConcernIcons.tsx      # 일일운세 관심사 6종 — 신규
└── PictogramRegistry.ts  # 중앙 레지스트리 + 타입 — 신규
```

### 2.2 공통 인터페이스

```tsx
interface PictogramProps {
  size?: number;       // default 24, 주로 20/24/32/48
  color?: string;      // default 'currentColor' 또는 도메인 컬러
  className?: string;
}
```

### 2.3 Registry 패턴

```ts
// PictogramRegistry.ts
import type { ComponentType } from 'react';

export type PictogramKey =
  | `dream:${DreamCategory}`
  | `topic:${TopicKey}`
  | `concern:${ConcernKey}`
  | `oheng:${OhengKey}`
  | `ui:${UiKey}`;

export const PICTOGRAMS: Record<PictogramKey, ComponentType<PictogramProps>> = {
  // ...
};

export function Pictogram({ k, ...props }: { k: PictogramKey } & PictogramProps) {
  const Cmp = PICTOGRAMS[k];
  return Cmp ? <Cmp {...props} /> : null;
}
```

→ 사용처에서 `<Pictogram k="dream:water" color="#1565C0" />` 식으로 통일.

## 4. 사용 가이드

### 4.1 한자·픽토그램·카피 3중 조화 공식

**좋은 예 (3중 조화)**
```
[IconWater]  水 (수)     "물의 기운이 내 안에 가득한 달"
(픽토그램)   (한자)    (쉬운 카피 — 핵심)
```

**나쁜 예 (이모지 남발)**
```
🌊 물 기운 가득 ✨
(이모지만 있고 한자·카피가 빈약)
```

**나쁜 예 (한자 남발)**
```
五行 中 水氣 旺盛 之月
(한자만 있고 쉬운 풀이 없음)
```

### 4.2 사이즈 가이드

| 컨텍스트 | 사이즈 | 비고 |
|---------|--------|------|
| 리스트 아이템 좌측 | 20 | 카테고리 라벨 옆 |
| 카드 헤더 | 24 | 표준 |
| 포커스 영역 | 32 | 탭 선택 시 |
| 결과 요약 큰 카드 | 48 | 히어로 |
| 버튼 내부 | 16 | 인라인 |

### 4.3 접근성

- 의미 있는 픽토그램은 `role="img" aria-label="..."` 필수.
- 장식용은 `aria-hidden="true"`.
- 색상만으로 의미 전달 금지 → 항상 텍스트 라벨 동반.

## 5. 스타일 레퍼런스

### 5.1 기존 컴포넌트에서 추출한 공식 스타일

`OhengIcons.tsx` 기준의 스타일 규칙:
```tsx
<svg viewBox="0 0 24 24" fill="none">
  <path d="..." 
        fill={color} 
        fillOpacity="0.15"
        stroke={color} 
        strokeWidth="1.5" 
        strokeLinejoin="round" />
</svg>
```

### 5.2 신규 픽토그램 작성 체크리스트

- [ ] viewBox="0 0 24 24"
- [ ] stroke-width 1.5 (strong 버전은 1.8)
- [ ] fillOpacity 0.1~0.2
- [ ] 불필요한 노드 최소화 (path 3개 이하 권장)
- [ ] currentColor 또는 props.color 지원
- [ ] size prop (default 24)
- [ ] className prop
- [ ] JSX 주석으로 어떤 의미인지 1줄 설명
