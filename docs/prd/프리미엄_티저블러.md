## 1. 목적 (Goal)

**"블러 아래 글자를 읽고 싶어서 결제하게 만든다."**

블러는 사주500의 유일한 유료 전환 장치다. 로그인 벽 없음, 모달 벽 없음, 디스카운트 타이머 없음. **블러 + 결제 버튼** 이 전부다.

따라서 블러는:

1. **보안이 완벽할 것** — OCR·스크린샷·DOM 덤프로 해독 불가.
2. **심리적으로 "궁금"할 것** — 끊긴 문장의 첫 단어가 반드시 보일 것.
3. **결제 직후 **"짜릿하게" 해제될 것** — 블러→언블러 전환이 구매의 보상처럼 느껴져야 함.

**성공 지표:**
- 블러 페이지에서 결제 CTA 클릭률 ≥ 35% (업계 평균 15%).
- 블러 해독 시도(개발자 도구 접근) 이상 감지 시 0% 누설.
- 결제 완료 → 해제 애니메이션 → 1섹션 완독까지 이탈률 ≤ 5%.

## 2. 핵심 결정 (Decisions)

### 2.1 블러 경계 (Blur Boundary)

| 대상 | 공개 | 블러 | 해제 조건 |
|---|---|---|---|
| **꿈해몽** | 3줄 중 1줄 (해석 1단계) | 2줄 (해석 2·3단계) | 500원 (1운) |
| **500원 심층분석** | 섹션 1 (총평) + 각 섹션 리드 문장 1줄 | 섹션 2~10 본문 | 500원 (1운) |
| **5,000원 프리미엄** | 500원 버전 전체 | 심화 분석 구간 (월운·대운·개운법 PDF) | 5,000원 (10운) |
| **궁합 리포트** | 종합 점수 + 1줄 요약 | 상세 분석 6섹션 | 5,000원 (10운) |

**"공개 구간은 이미 만족스러워야 한다"** — 블러 아래 안 보여도 값어치가 있어야 함. 그래야 블러 아래가 "더 궁금해진다."

### 2.2 블러 렌더링 방식

**3중 방어:**

1. **CSS filter blur(8px)** — 기본 시각 블러.
2. **텍스트 셔플링** — 실제 본문 대신 랜덤 한글 문자열 DOM에 렌더. 실제 본문은 **서버에서만 보유**, 결제 후에 내려옴.
3. **오버레이 노이즈** — 옅은 샌드 텍스처 SVG 오버레이로 OCR 교란.

**이유:** CSS blur만 있으면 개발자 도구에서 `filter: none` 한 줄로 해독된다. 실제 본문이 클라이언트에 없어야 누설 0%.

### 2.3 "첫 단어 노출" 규칙

블러 시작점은 반드시 **의미 있는 문장 도입부를 1~3단어 노출**한 뒤 시작한다.

예:
- ❌ `▓▓▓▓▓▓ ▓▓ ▓▓▓ ▓▓▓▓` — 내용 0% 추정 가능, 호기심 자극 실패.
- ✅ `당신이 가장 두려워하는 것은 ▓▓▓▓▓▓ ▓▓▓▓▓▓…` — "뭘 두려워한다는 거지?" 훅 완성.

AI 프롬프트에 **"블러 시작 위치"** 토큰을 생성시켜서 위치 지정. 단순 "본문의 N% 이후" 아님.

### 2.4 언블러 애니메이션

결제 성공 → 리포트 페이지 진입 → 다음 순서:

1. **0.0s:** 블러 상태 그대로 표시.
2. **0.3s:** 상단에서 밝은 골드 라이트 라인이 세로로 흘러내림 (1.2s 동안).
3. **0.6s~1.5s:** 라이트 지나간 부분이 블러→언블러 크로스페이드.
4. **1.5s 종료:** 상단으로 "모든 내용이 열렸어요 ✨" 토스트 (2초 후 자동 닫힘).
5. 총평 섹션이 자동 펼쳐진 상태로 완료.

**이 애니메이션은 환불 후 재구매 시에도 재생** — 반복 보상감.

### 2.5 블러 → CTA 배치

- CTA는 **화면 하단 고정(sticky)**, 52px, 단일 버튼.
- 버튼 위에는 **잔액/가격 요약 1줄** — "지갑 500원 · 바로 열람" 또는 "500원 결제 후 열람".
- 버튼 아래는 **소셜프루프 1줄** — "오늘 324명 구매".
- **로그인 유도 UI 금지** (로그인 전략 AC-02, 가격 AC-10과 일관).

### 2.6 반복 방문자 처리

- 결제 완료 유저는 블러 없음, 전체 언블러 상태로 진입.
- 결제 이력이 서버에 있지만 세션 익명인 경우: 결제 영수증 URL(`/r/:token`)로 접근하면 블러 해제.
- **구매 안 한 상태로 같은 상품 2회차 방문**: 블러는 유지하되 CTA 카피를 "지난번에 궁금했던 그 내용"으로 전환 → A/B.

## 3. 시각 명세

### 3.1 블러 스펙

```css
.blur-locked {
  filter: blur(8px);
  user-select: none;
  -webkit-user-select: none;
  pointer-events: none;
  overflow: hidden;
  position: relative;
}

.blur-locked::after {
  content: '';
  position: absolute;
  inset: 0;
  background: url('/noise-sand.svg') repeat;
  opacity: 0.15;
  mix-blend-mode: overlay;
}
```

- 블러 강도: **8px** (4px는 약해서 해독 가능, 12px는 아예 안 보여서 호기심 0).
- 노이즈 텍스처: 샌드·크림 톤 SVG, 8x8 타일.

### 3.2 첫 단어 노출 영역

- 각 블러 문단의 첫 1~3 단어는 **블러 미적용** (명료하게 보임).
- 그 뒤 단어부터 블러 시작. **서서히 페이드**되는 전환은 금지 — 명료↔블러의 선명한 대비가 호기심 최대화.

### 3.3 락 아이콘

- 각 섹션 상단 우측에 작은 🔒 아이콘 (16px).
- 아이콘 호버/탭 시: "500원으로 열기" 툴팁.
- 아이콘 탭 = CTA 클릭으로 간주 (이벤트).

### 3.4 언블러 애니메이션 (CSS)

```css
@keyframes goldenLine {
  0%   { transform: translateY(-100%); opacity: 0; }
  20%  { opacity: 1; }
  100% { transform: translateY(100%); opacity: 0; }
}

.unlock-line {
  position: absolute;
  top: 0; left: 0; right: 0;
  height: 80px;
  background: linear-gradient(180deg, 
    transparent 0%, 
    rgba(160,139,106,0.6) 50%, 
    transparent 100%);
  animation: goldenLine 1.2s ease-out;
  pointer-events: none;
}

.unlocking {
  animation: blurFadeOut 0.9s ease-in-out 0.6s forwards;
}

@keyframes blurFadeOut {
  from { filter: blur(8px); }
  to   { filter: blur(0); }
}
```

## 4. 데이터 플로우

### 4.1 비구매 시 서버 응답

```json
// GET /api/report/:reportId (unauthorized / unpaid)
{
  "reportId": "abc123",
  "tier": "basic",
  "sections": [
    { "id": "overview", "title": "총평", "body": "…전체 본문…", "locked": false },
    { "id": "personality", "title": "성격의 뼈대", 
      "preview": "당신은 겉은 단단하지만…",  // 블러 시작 전 공개
      "body": null,  // 본문은 숨김
      "locked": true, "blurStartsAfter": "당신은 겉은 단단하지만" },
    …
  ],
  "cta": { "product": "basic_saju", "price": 500, "unitCost": 1 }
}
```

### 4.2 결제 직후 서버 응답

- 같은 엔드포인트, 결제 영수증 헤더 확인 → 전체 `body` 반환.
- 클라이언트는 응답 교체 후 **언블러 애니메이션 트리거**.

### 4.3 클라이언트 렌더 로직

```tsx
function SectionContent({ section }) {
  if (!section.locked) {
    return <FullBody body={section.body} />;
  }
  return (
    <>
      <p>{section.preview}</p>
      <BlurredPlaceholder minLines={8} />  // 가짜 셔플 텍스트
    </>
  );
}
```

- `BlurredPlaceholder`는 **실제 본문 길이를 모름** — 서버에서 제공하는 `estimatedLines`만 받아서 높이 근사.
- 셔플 텍스트는 한글 랜덤 글자 + 임의 공백 → 시각적으로 "문장처럼" 보이지만 의미 0.

## 5. 유저 스토리

### US-01. 꿈해몽 블러 → 500원 결제
> *지은(27, 여). 꿈해몽 탭 진입, "전날 밤 당신은 큰 뱀을 본 꿈을 꾸었습니다. 이 꿈은 ▓▓▓▓▓" 블러. 첫 문장 도입부만 보여서 "뱀 꿈 뭐래" 궁금증 폭발. 500원 결제 → 골드 라인 애니메이션 → 전체 해석 열림. 2분 만에 완독.*

### US-02. 500원 → 5,000원 업셀
> *태현(33, 남). 500원 리포트 완독 후 하단 "이 분석, 10배 깊이로 보실래요?" 카드. 프리뷰에 "당신의 2026년 3월은 ▓▓▓▓" 월운 블러. "10배가 뭔데" 궁금해서 5,000원 결제. 월운 12개월 전체 + PDF 다운로드 열림.*

### US-03. 보안 공격 시도
> *공격자 X. 개발자 도구에서 `.blur-locked`의 `filter: none`으로 해제 시도. 보이는 것은 셔플된 랜덤 글자. DOM에 실제 본문 없음. 좌절.*

### US-04. 재방문 유저
> *수아(24, 여). 어제 500원 심층분석 결제. 오늘 다른 기기로 접근. 결제 영수증 URL 클릭 → 자동 언블러 (애니메이션 없음 — 첫 해제만 재생).*

## 6. 엣지 케이스

| ID | 상황 | 처리 |
|---|---|---|
| E-01 | 결제 성공했지만 클라이언트 응답 늦음 | 스켈레톤 → 5초 타임아웃 → 수동 "새로고침" 버튼 |

| E-08 | 결제 성공 → 환불 | 환불 확정 시 다음 접근부터 블러 복원 |
