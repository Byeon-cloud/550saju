## 1. 목적 (Goal)

**"10섹션 3,000자 리포트를 끝까지 읽게 만든다."**

사주500의 핵심 가치는 "500원에 철학관 10만원 수준의 깊이"다. 하지만 깊이 = 분량이 되는 순간 유저는 이탈한다. 경쟁사(포스텔러·점신) 후기의 1위 이탈 사유가 **"너무 길어서 안 읽게 됨"**이다.

이 PRD는 **"깊이는 유지하되, 접근은 가볍게"** — 아코디언·스낵화·리듬을 통해 읽는 심리적 저항을 90% 낮추는 것을 목표로 한다.

**성공 지표:**
- 리포트 마지막 섹션까지 도달률 ≥ 70% (현 추정 30% → 목표 70%).
- 평균 체류 시간 ≥ 6분 (유료 리포트 기준).
- "너무 길다" 유형 후기 비중 ≤ 5%.

## 2. 핵심 결정 (Decisions)

### 2.1 10섹션 구조 + 기본 상태

| 순서 | 섹션 | 기본 상태 | 길이 | 역할 |
|---|---|---|---|---|
| 1 | **총평** | 🔓 펼침 | 짧음 (150자) | 첫인상, 핵심 요약 |
| 2 | **성격의 뼈대** | 🔓 펼침 | 중간 (400자) | "맞다!" 훅 |
| 3 | 대인관계 | 🔒 접힘 | 중간 (350자) | |
| 4 | **직업·재능** | 🔓 펼침 | 중간 (400자) | 유저 관심 상위 |
| 5 | 재물운 | 🔒 접힘 | 중간 (350자) | |
| 6 | 애정·결혼 | 🔒 접힘 | 중간 (400자) | |
| 7 | 건강 | 🔒 접힘 | 짧음 (250자) | |
| 8 | **올해의 운세** | 🔓 펼침 | 긴 편 (500자) | 시의성, 구매 직후 가장 궁금 |
| 9 | 인생의 과제 | 🔒 접힘 | 중간 (400자) | |
| 10 | **개운법** | 🔓 펼침 | 짧음 (200자) | 닫는 훅, 공유 욕구 자극 |

**기본 펼침은 5개만** (1, 2, 4, 8, 10) — "핵심만 보여주고, 나머지는 궁금하면 열어라" 원칙.

**리듬 설계 (강→약→강):**
- 1~2 강 (총평·성격) → 3~7 약 (접힘이 많아 호흡) → 8 강 (올해) → 9 약 → 10 강 (개운법)
- 중간에 힘 빼는 구간을 의도적으로 배치해서 10까지 완주 가능.

### 2.2 아코디언 인터랙션

- 접힘 상태: 섹션 제목 + **2줄 프리뷰 텍스트** + "펼치기 ⌄"
- 펼침 상태: 본문 전체 + "접기 ⌃"
- 애니메이션: 180ms ease-out, `max-height` 기반 transition.
- 접혀 있는 섹션의 **프리뷰 2줄은 궁금증을 유발하는 문장**으로 자동 선택 (AI가 생성 시 프리뷰 메타 지정).

예:
```
[🔒] 대인관계
    당신은 처음 만난 사람에게 쉽게 마음을
    열지 않습니다. 하지만 한 번 열린 다음엔…
    [펼치기 ⌄]
```

### 2.3 섹션 내부 규칙

모든 섹션은 아래 구조를 강제한다:

1. **리드 문장 (1줄)** — 굵게, 핵심 한 줄 요약.
2. **본문 (2~4 문단)** — 각 문단 3~5줄, 120~180자.
3. **"왜 이런가" 근거 블록** (접힘) — 명리학적 근거, 6대 원전 인용.
4. **구체 행동 패턴 3~5개** — 불릿 금지, 문단형 예시. "이런 순간에 이런 반응을 합니다" 형식.

**금지 사항:**
- 불릿 리스트(•) 5개 이상 연속 — 명부처럼 읽힘.
- 한 문단 7줄 이상 — 벽 느낌.
- "~입니다"로만 끝나는 3문장 연속 — 호흡 단조.

### 2.4 한자 병기 규칙

CLAUDE.md 규정 재확인:

> 모든 한자에 **한국어 읽기 + 의미**를 함께 표기.

구체적으로:
- **첫 등장:** `壬水(임수, 큰 바다의 물)` — 한자 + 독음 + 뜻.
- **같은 섹션 내 재등장:** `壬水(임수)` — 독음만.
- **다른 섹션 재등장:** 다시 `壬水(임수, 큰 바다의 물)` 전체 병기.
- 시주·월주 같은 구조 용어: `시주(時柱)` — 한국어 먼저, 한자 괄호.
- 지지 12자, 천간 10자, 오행 5자는 섹션 상단에 용어집 접기 제공.

**금지:**
- 한자 단독 노출 금지 (`甲` 만 있는 경우 없음).
- 독음 없는 한자 혼합 단어 금지 (`甲木 기질` → `甲木(갑목, 큰 나무)의 기질`).

### 2.5 타이포그래피

- 본문 폰트 크기: **16px** (모바일 기본, 520px max-width).
- 행간 (line-height): **1.7** (일반 1.5보다 넉넉, 가독성 + 신비감).
- 자간 (letter-spacing): **-0.01em** (한글은 약한 음의 자간이 붙음).
- 문단 간격: **16px** (공백으로 호흡).
- 섹션 간격: **32px** + 점선 또는 가는 브라운 라인.
- 리드 문장: **18px, weight 600, 골드브라운 색**.
- 강조 (한자·용어·핵심): **본문 색 유지, weight 500**. 색 강조 금지 (디자인 톤 흐림).

### 2.6 스낵 포인트 (Micro-Reading Anchors)

- 긴 섹션(400자 이상)은 **중간에 인라인 구분**:
  - 회색 가로선 + 작은 라벨 ("그렇다면 어떻게 살아야 할까요?")
- **풀 쿼트(Pull Quote):** 섹션당 1회, 큰 글씨로 핵심 1줄 끄집어냄.
  - 예: *"당신의 고민은 무엇을 택하느냐가 아니라, 무엇을 놓아주느냐입니다."*
- **이미지·인포그래픽:** 섹션당 0~1개. 오행 밸런스·대운 타임라인 등 이미 SVG 자산 존재.
- **엔드 카드:** 섹션 마지막에 "이 내용이 공감되셨다면" 형식 1줄. 공유 CTA 연결.

### 2.7 스크롤 관리

- 아코디언 펼침 시: 펼쳐진 헤더가 **뷰포트 상단 64px(nav) 아래에 스냅**되도록 스크롤 자동 이동.
- 여러 섹션 동시 펼침 가능 (단일 펼침 금지 — 비교 독서 가능해야 함).
- "모두 펼치기" 버튼 상단 우측 제공. "모두 접기" 토글.
- **마지막 섹션 도달 시 하단 액션 카드** 자동 등장:
  - 5,000원 업셀 (500원 구매자에게)
  - 공유 CTA (5,000원 구매자에게)
  - "보관함에 저장" (비로그인 유저에게)

## 3. 유저 스토리

### US-01. 처음 열자마자 3섹션 완독
> *지은(27, 여). 500원 결제 완료. 리포트 페이지 진입. 1·2·4·8·10 펼쳐져 있음. 1 총평 3줄, 2 성격 읽고 "맞아!" 공감 → 아래로 스크롤. "대인관계" 프리뷰 "당신은 처음 만난 사람에게…" 궁금해서 펼침.*

### US-02. "너무 길어" 이탈 방지
> *태현(33, 남, 바쁜 회사원). 리포트 진입 후 1분 안에 뭘 봐야 할지 판단하고 싶음. 접힌 섹션 덕분에 "전체 분량" 압박 없이 상위 3개만 읽음. 만족. 다음에 또 올 생각.*

### US-03. 완독 유도
> *수아(24, 여). 8 올해의 운세까지 읽고 9 "인생의 과제" 접혀 있는 거 발견. 프리뷰 문장이 궁금해서 펼침. 끝까지 읽음. 10 개운법의 "매일 아침 동쪽을 향해…" 구체적 행동 제시에 공유 욕구 폭발.*

### US-04. 풀쿼트 공유
> *민준(29, 남). 5 재물운 섹션의 풀쿼트 *"돈은 당신에게 오지만, 머무르지 않습니다."* 를 스크린샷 찍어서 친구에게 보냄. 유기적 바이럴 발생.*

## 4. 컴포넌트 명세

### 4.1 `AccordionSection`

```tsx
interface AccordionSectionProps {
  id: string;                     // 'overview' | 'personality' | ...
  title: string;                  // "성격의 뼈대"
  preview: string;                // 2줄 프리뷰 (접힘 시)
  content: ReactNode;             // 본문
  defaultOpen: boolean;           // 기본 펼침 여부
  length: 'short' | 'medium' | 'long';  // 파이프라인 메타
  icon?: ReactNode;
}
```

- 클릭 시 `max-height` 트랜지션. 모션 감소 환경에서는 즉시 토글.
- URL 해시 동기화: `/r/:id#personality` 진입 시 해당 섹션 자동 펼침 + 스크롤.

### 4.2 `PullQuote`

```tsx
interface PullQuoteProps {
  children: ReactNode;
  source?: string;   // 인용 출처 (명리학 원전 시)
}
```

- 좌측 세로 골드브라운 라인 + 24px 이탤릭.
- 공유 버튼 hover 시 표시 (마우스) 또는 long-press (터치).

### 4.3 `InlineDivider`

```tsx
interface InlineDividerProps {
  label?: string;   // "그렇다면 어떻게 살아야 할까요?"
}
```

- 긴 섹션 중간 삽입. 회색 가로선 + 중앙 라벨.

### 4.4 `SectionFooterAction`

- 마지막 섹션(10) 하단 자동 삽입.
- 조건 분기: 500원 구매자 → 업셀 / 5,000원 구매자 → 공유 / 비구매 조회자 → 본인 분석 유도.

## 5. AI 프롬프트 연동 (Content Contract)

AI가 섹션별로 생성하는 JSON 스키마에 **프리뷰·풀쿼트 메타를 요구**한다.

```json
{
  "section": "personality",
  "title": "성격의 뼈대",
  "leadSentence": "당신은 겉은 단단하지만 속은 섬세한 사람입니다.",
  "preview": "당신은 처음 만난 사람에게 쉽게 마음을 열지 않습니다. 하지만 한 번 열린 다음엔…",
  "body": "… (3~4 문단) …",
  "pullQuote": "고요한 물처럼 보여도, 당신 안에는 깊은 회오리가 있습니다.",
  "evidence": "丙火가 子水 위에 있는 구조는…",
  "actionPatterns": [
    { "context": "회의에서 반대 의견", "behavior": "즉시 반박하지 않고 3초 침묵 후 질문" },
    …
  ]
}
```

프롬프트에 명시: 프리뷰는 **"끊긴 문장으로 궁금증 유발"**, 풀쿼트는 **"문학적 1줄"**, actionPatterns는 **"구체 상황 + 반응"**.

## 6. 엣지 케이스

| ID | 상황 | 처리 |
|---|---|---|
| E-01 | AI가 프리뷰를 생성하지 않은 경우 | 본문 첫 80자 자동 추출 + "…" 말줄임 |
| E-02 | AI가 풀쿼트를 생성하지 않은 경우 | 풀쿼트 생략 (강제하지 않음) |
| E-03 | 특정 섹션이 200자 미만으로 짧은 경우 | "short" 메타 적용, 인라인 구분·풀쿼트 생략 |
| E-04 | 시주 미입력 유저 | 시주 관련 해석 조건부 제외, "미입력으로 이 부분은 생략" 안내 배너 |
| E-05 | 네트워크 느려서 섹션 지연 로드 | 각 섹션 스켈레톤 플레이스홀더, 본문만 교체 |
| E-06 | 모션 감소 OS 설정 | 트랜지션 즉시 토글로 폴백 |
| E-07 | 접근성(스크린리더) | 아코디언 상태 `aria-expanded` 동기화, 키보드 네비(Enter/Space) |
| E-08 | 모바일 가로 회전 | 컨텐츠 너비 고정 (520px), 양쪽 여백 자동 |
| E-09 | 같은 한자가 여러 섹션에 걸친 반복 등장 | 섹션 진입 시 첫 등장 기준으로 전체 병기 |
| E-10 | 풀쿼트 너무 길어서 2줄 이상 | 1줄 초과 시 자동 축약 또는 2줄 허용 (디자인 토큰) |
| E-11 | 유저가 "모두 펼치기" 후 브라우저 백 | 펼침 상태 sessionStorage 저장, 복귀 시 복원 |
| E-12 | 인쇄/PDF 내보내기 | 전체 펼침 + 액션 카드 제외 버전 |

## 7. 수용 기준 (Acceptance Criteria)

| ID | 기준 |
|---|---|
| AC-01 | 리포트 최초 진입 시 5개 섹션만 펼침, 나머지 5개는 접힘 |
| AC-02 | 접힌 섹션에는 2줄 프리뷰가 반드시 표시됨 |
| AC-03 | 모든 한자는 **독음 + 의미** 병기, 단독 한자 노출 0건 |
| AC-04 | 본문 행간 1.7, 폰트 16px, 520px max-width 준수 |
| AC-05 | 긴 섹션(400자 이상)에는 인라인 구분선 or 풀쿼트가 최소 1개 |
| AC-06 | 아코디언 상태는 `aria-expanded`와 동기화, 키보드 조작 가능 |
| AC-07 | "모두 펼치기/접기" 버튼 상단 우측 고정 |
| AC-08 | 섹션 10(개운법) 하단에 조건부 액션 카드 자동 노출 |
| AC-09 | URL 해시(`#personality`)로 직링크 진입 시 해당 섹션 자동 펼침 + 스크롤 |
| AC-10 | 마지막 섹션까지 도달률 ≥ 70% (PostHog/GA 이벤트 기반) |
| AC-11 | 불릿 리스트 연속 5개 이상 금지 (린트 룰 추가) |
| AC-12 | 풀쿼트는 공유 가능한 스크린샷 영역으로 캡처 가능 (data-shareable) |

## 9. 오픈 퀘스천 (Open Questions)

1. **1/2/4/8/10 기본 펼침은 확정인가, 유저 세그먼트(연령·성별)에 따라 가변인가** — 개인화는 Phase 2. MVP는 고정.
2. **풀쿼트 공유 시 "사주500" 워터마크 유무** — 브랜드 노출 vs 공유 부담. 연한 워터마크 추천.
3. **섹션 순서를 유저가 재배열할 수 있는가** — 복잡도 증가 vs 컨트롤감. 일단 고정, 후속 검토.
4. **"모두 펼치기"가 이탈을 증가시킬 위험** — A/B 필요. MVP에는 버튼 포함, 1주 데이터 후 결정.
5. **펼침 상태 저장을 로컬에만 할지, Firestore에도 저장할지** — 크로스 디바이스 경험 vs 저장 비용. sessionStorage만 우선.
