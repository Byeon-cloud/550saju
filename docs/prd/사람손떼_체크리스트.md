## 0. 이 문서의 목적

런칭 전 또는 주요 배포 전, **"AI가 대충 만든 티"가 남아있는지** 마지막 관문에서 검증. 상위 가이드의 원칙을 **액션 가능한 체크리스트**로 떨어뜨린 것.

**전제**:
- 이 체크리스트는 **리뷰어 1인이 30분 이내에** 주요 페이지를 훑을 수 있도록 설계.
- "위험도 H(High) / M(Medium) / L(Low)"로 우선순위 표기.
- H 하나라도 걸리면 **릴리스 블록**.

**용어**:
- **손 안 뗀 티**: AI가 뽑은 걸 사람이 검수 없이 그대로 놔둔 흔적.
- **사람 손 떼기**: 사람 손으로 한 번 더 다듬어 AI 티를 제거한 상태.

## 1. 사전 준비 — 필요한 도구

- 리뷰 환경: iOS Safari + Android Chrome + 데스크톱 Chrome 각 1회.
- 테스트 계정 3개 (신규 가입·재방문·결제 유경험자).
- 리뷰 기록 시트 (결과 기록, 실패 캡처).
- 린터: 브라우저 콘솔 `saju500.devTools.runQualityAudit()` (Phase 2 자동화 예정).

## 2. 일반 검사 (전체 페이지 공통)

### 2.1 금칙어 스캔 [H]

페이지 내 모든 텍스트 스크롤하며 다음 단어 검색:

- [ ] "물론이죠" / "물론입니다"
- [ ] "좋은 질문이에요"
- [ ] "도움이 되셨기를 바랍니다"
- [ ] "요약하자면" / "정리하자면"
- [ ] "흥미롭게도" / "놀랍게도" / "특이하게도"
- [ ] "긍정적인 에너지" / "부정적인 에너지"
- [ ] "당신만의 특별함" / "여러분만의"
- [ ] "반드시 ~하세요" / "절대 ~해야 합니다"
- [ ] "놓치지 마세요" / "지금 바로"
- [ ] "한정 특가" / "초특가"
- [ ] "만족도 100%"
- [ ] "~를 추천드립니다"
- [ ] "소중한 고객님" / "손님"
- [ ] "운명적인" / "신비로운"
- [ ] "카르마" / "전생"
- [ ] "액운" / "재앙" / "저주" / "살이 끼었다"
- [ ] "부적" / "굿" / "영혼" / "조상님"

**판정**: 0건이면 PASS. 1건이라도 있으면 FAIL.

### 2.2 형용사 나열 [M]

- [ ] "~하고, ~하고, ~한" 3개 이상 형용사 나열 3회 이상 있음?
- [ ] "매우", "정말", "굉장히", "너무" 한 섹션당 3회 이상 있음?

**판정**: 둘 다 NO면 PASS.

### 2.3 어미 반복 [M]

- [ ] "~입니다" 3회 연속 있음?
- [ ] "~죠" 4회 연속 있음?
- [ ] 한 화면 내 "~해요" 10회 이상 등장?

### 2.4 "당신" 빈도 [M]

- [ ] 한 섹션 안에 "당신" 3회 이상 있음?

### 2.5 메타 언급 [H]

- [ ] "이 사주를 보면" / "당신의 사주에서는" 등 외부 시점 서술 있음?
- [ ] "AI가 분석한 결과입니다" 등 자기 참조 있음? (단, 명시적 AI 공시는 하단 1회만 허용)

### 2.6 이모지 정책 [M]

- [ ] AI 리포트 본문 섹션당 이모지 2개 이상 있음?
- [ ] 결제 CTA에 이모지 있음?
- [ ] 에러 메시지에 이모지 있음?

**판정**: 셋 다 NO면 PASS.

## 3. 페이지별 체크리스트

### 3.1 홈(랜딩) 페이지 [H]

- [ ] 히어로 H1 "500원, 진짜 사주." 또는 승인된 태그라인 노출.
- [ ] "왜 500원인가" 설명 블록 존재.
- [ ] "AI + 명리학자 감수" 문구 최소 1회 노출.
- [ ] CTA 버튼 "500원 시작" 또는 승인 카피.
- [ ] 소셜 프루프 (구매수 or 후기) 블록 노출.
- [ ] 별점 아이콘 (⭐) 0건.
- [ ] "지금 바로", "놓치지 마세요" 0건.
- [ ] 이미지 alt 전부 존재.

### 3.2 사주 입력 페이지 [H]

- [ ] 상단 인사 카피 "준비됐어요" 등 브랜드 톤 맞음.
- [ ] 생년월일 입력 필드 라벨 + placeholder 명확.
- [ ] 시간 미입력 옵션 "시간 모름" 버튼 명시.
- [ ] 시간 모름 시 안내 카피 "시주 없이도 80% 정확도" 표시.
- [ ] 더블클릭 방지 적용 (연속 제출 방지).
- [ ] 성별 선택 2개 라디오 카드.
- [ ] 상황 질문 칩 5개 (선택 사항).
- [ ] CTA 하단 고정 or 스크롤 밀착.
- [ ] 경계 시간 입력 시 ±30분 보정 툴팁 표시.

### 3.3 로딩 페이지 [H]

- [ ] 3단계 멀티 페이지 로딩 구조 (`로딩전략.md`).
- [ ] Stage 1 카피 "만세력 맞추는 중이에요".
- [ ] Stage 2 카피 "당신의 사주 원국이 완성됐어요".
- [ ] Stage 3 카피 "선배 명리학자가 해석을 시작합니다".
- [ ] 로딩 중 뒤로가기 차단 (앱인토스).
- [ ] 로딩 실패 시 환불 + 에러 카피 준수.

### 3.4 결과 페이지 [H]

- [ ] 상단 summary 한 줄 노출.
- [ ] 10섹션 아코디언 구조, 5개 기본 펼침 (섹션 1·2·4·8·10).
- [ ] 각 섹션 300~450자 분량.
- [ ] 각 섹션 사주 데이터 앵커 1회 이상 (일간·월지·십성 등).
- [ ] 각 섹션 구체 장면 2개 이상.
- [ ] PullQuote 섹션당 1회 이하.
- [ ] InlineDivider 섹션당 1회 이하.
- [ ] 프리미엄 섹션 블러 + CTA 작동.
- [ ] 공유 버튼 노출.
- [ ] 보관함 저장 버튼 노출.

### 3.5 오늘의 운세 페이지 [M]

- [ ] 하루 1회 제한 작동.
- [ ] 한자 대신 이모지 치환 0건 (CLAUDE.md 룰).
- [ ] 운세 한 줄 + 실천 팁 구조.
- [ ] 방향·색·시간 인포 표시.

### 3.6 궁합 페이지 [M]

- [ ] 두 명 입력 폼 대칭적 레이아웃.
- [ ] 관계 맥락 (연인/친구/가족) 선택 가능.
- [ ] 한쪽 기울어짐 서술 없음 (양방 공정).
- [ ] "결혼하세요"·"이별 예정" 단정 0건.

### 3.7 결제 페이지·모달 [H]

- [ ] CTA 카피 `결제CTA심리학.md` 준수.
- [ ] 단수 가격 표기 ("497원" or "5,000원") 정확.
- [ ] 가짜 긴박감 (카운트다운·재고) 0건.
- [ ] 광고·유료 표시 명확.
- [ ] 환불 정책 링크 하단 노출.
- [ ] 약관 동의 체크박스 기본 OFF.
- [ ] 앱인토스 환경 TDS 버튼 52px 적용.
- [ ] 웹 환경 토스페이먼츠 SDK 호출.

### 3.8 마이페이지 [M]

- [ ] 운 잔액 3버킷 구분 표시 (paid/bonus/reward).
- [ ] 보관함 리포트 목록 표시.
- [ ] 프로필 수정 가능.
- [ ] 브랜드 재확인 문구 하단 존재.

### 3.9 보관함 [M]

- [ ] 리포트 카드 리스트.
- [ ] 빈 상태 카피 "아직 풀어본 사주가 없어요" 등.

### 3.10 공유 링크 수신 페이지 [M]

## 4. AI 리포트 콘텐츠 검수 [H]

각 섹션 10개 모두에 대해 아래 체크.

### 4.1 섹션 구조 [H]
- [ ] 훅 (1~2문장) 있음?
- [ ] 원리 설명 (2~4문장) 있음?
- [ ] 디테일 묘사 (2~4문장) 있음?
- [ ] 클로저 (1~2문장) 있음?
- [ ] 분량 300~450자 범위?
- [ ] 문단 2~3개?

### 4.2 어조 [H]
- [ ] 섹션별 톤 매트릭스 준수? (총평=단호, 성격=담담, 대인=다정, 등)
- [ ] "~입니다" 3회 연속 없음?
- [ ] 명령문 없음?
- [ ] "당신" 2회 이하?

### 4.3 근거 [H]
- [ ] 사주 데이터 앵커 1회 이상?
- [ ] 만세력 팩트 오류 없음?

### 4.4 구체성 [H]
- [ ] 형용사 단독 나열 3개 이내?
- [ ] 구체 장면 2개 이상?
- [ ] "OO하는 편이다" 어미 적절?

### 4.5 금기 주제 [H]
- [ ] 죽음·수명 언급 0?
- [ ] 이혼·사별 단정 0?
- [ ] 질병명 직접 언급 0?
- [ ] 이성 강제 표현 0?

## 12. 런칭 직전 스모크 테스트 [H]

실사용자 시나리오 5가지:

### 시나리오 1 — 처음 방문 유저 (무료)
1. 홈 진입.
2. 오늘의 운세 클릭.
3. 결과 확인.
4. 홈 복귀.

**체크**: 전 단계 금칙어 0, 톤 일관, 로딩 자연스러움.

### 시나리오 2 — 500원 결제 유저
1. 홈 진입.
2. "500원 시작" CTA 클릭.
3. 생년월일 + 시간 입력.
4. 결제 (웹: 토스페이먼츠 / 앱인토스: IAP).
5. 로딩 3단계.
6. 결과 10섹션 확인.
7. 공유·보관 동작 확인.

**체크**: 결제 성공, 운 차감 정확, 리포트 품질 AC 통과.

### 시나리오 3 — 시간 모름 유저
1. 입력 페이지 시간 모름 체크.
2. 제출.
3. 결과 페이지에서 시주 빈칸 처리 확인.

### 시나리오 4 — 궁합 유저
1. 궁합 페이지 진입.
2. 두 명 입력.
3. 결과 6섹션 확인.

### 시나리오 5 — 재방문 유저 (보관함)
1. 마이페이지 → 보관함.
2. 기존 리포트 열기.
3. 스크롤·아코디언 동작.

## 13. 실패 처리 플로우

체크리스트 중 H 하나라도 FAIL 시:

1. **즉시 릴리스 차단**.
2. Slack 또는 지라에 "런칭 블록" 티켓 생성.
3. 수정 → 재검수 → PASS 확인.
4. 수정 후에도 FAIL 재발 시 **근본 원인 분석** (프롬프트·컴포넌트·설계 중 어디서?).

**Phase 1 (수동, 지금)**:
- 리뷰어 1명 30분 수동 체크.

**Phase 2 (부분 자동)**:
- 금칙어 린터 (빌드 타임).
- axe-core a11y 린터 (빌드 타임).
- AI 리포트 자기 리뷰 (생성 직후 2차 호출).

**Phase 3 (완전 자동)**:
- E2E 시나리오 5개 Playwright 자동 실행.
- 리포트 100개 샘플 배치 검증.
- 시각 회귀 테스트 (Percy or Chromatic).

## 15. 엣지 케이스

1. **체크리스트가 길어서 일부 스킵됨**: H 항목만이라도 반드시 완료. M/L은 다음 릴리스로 이월 가능.
2. **리뷰어가 명리학 모를 때**: 콘텐츠 부분은 명리 배경 있는 리뷰어 필수. 나머지는 일반 리뷰어 가능.
3. **런칭 긴급**: H 기준만 통과 + M/L은 D+3 내 완료 보증.
4. **신규 페이지 추가 시**: 페이지별 체크리스트 신규 블록 추가 후 진행.
5. **카피 변경 시**: 금칙어 스캔 + UX라이팅 린터 필수.
