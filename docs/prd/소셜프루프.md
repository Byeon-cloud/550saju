## 1. 목적 (Goal)

**"혼자 사는 500원이 아니라, 오늘 300명이 산 500원이다."**

사주500의 전환 결정권은 "이게 진짜인가?"에서 난다. 블러 아래 본문이 보이지 않는 상태에서 유저를 확신시키는 가장 강력한 장치는 **"다른 사람들도 이미 샀다"**라는 소셜프루프다.

단, 별점은 명백한 리스크가 있어 MVP에는 도입하지 않는다.

**성공 지표:**
- 소셜프루프 노출 영역의 전환 기여도 ≥ 8%p (A/B on vs off).
- 후기 카드 클릭률 ≥ 12%.
- 조작/스팸 후기 노출 0건 (모더레이션 통과율 100%).

## 2. 핵심 결정 (Decisions)

### 2.1 도입 장치 3종

| 장치 | 표시 내용 | 위치 | 근거 |
|---|---|---|---|
| **구매자 수 카운터** | "총 12,384명이 구매 / 오늘 324명" | 상품 카드, 블러 페이지 CTA 바로 위 | 암묵적 퀄리티 증빙 |
| **후기 카드 슬라이더** | 실명 익명화된 후기 5~10개 | 블러 페이지 CTA 아래 | 내용 기반 공감 |
| **"방금 구매" 티커** | "전주에 사시는 지은님이 방금 구매" | 홈·리포트 페이지 우측 하단 fade toast | 실시간 감각 |

### 2.2 별점(★) 미도입

**이유:**

1. **조작 감지 비용이 높다** — 5점 만점 UI는 "4.9점"이 기본 허들이 되며, 경쟁사 4.9와 구분 되지 않음. 차별화 부재.
2. **네거티브 리뷰 유도** — 별점 낮춘 유저 원인 분석이 리소스 과다. 1인 오너 운영 구조에 부담.
3. **"별점이 콘텐츠 퀄리티를 결정한다"는 프레이밍** — 사주500은 콘텐츠 자체가 가치. 별점으로 격하되면 안 됨.
4. **전자상거래법 리스크** — 조작/허위 별점에 대한 공정위 가이드라인 강화 추세. 안전 마진 확보.
5. **"몇 명이 샀나"가 더 강력** — 별점은 상대값, 구매수는 절대값. "324명"은 즉각적 신뢰.

**결정:** 별점 UI 전체 금지. 평점 숫자도 노출 금지. Phase 2 이후 필요시 "추천/비추천 2지선택"으로 재검토.

### 2.3 후기 운영 원칙

| 항목 | 정책 |
|---|---|
| 수집 경로 | 결제 48시간 후 자동 DM / 앱인토스 알림으로 2줄 후기 작성 유도 |
| 작성 보상 | 0.5운(250원) 리워드 1회, 30일 유효 |
| 최소 길이 | 20자 이상 (1자·이모지만 등록 차단) |
| 최대 길이 | 200자 (초과 시 자동 말줄임 미리보기) |
| 노출 익명화 | "ㅇㅇ(29, 여)" 형식. 본명·아이디 비노출 |
| 모더레이션 | ① AI 1차(욕설·스팸·타사 언급) → ② 수동 2차(준기 승인) |
| 표시 주기 | 최신 5개 + 베스트 5개(공감수) 교차 노출 |
| 삭제 정책 | 작성자 본인 요청 즉시 삭제, CS 판단 시 비노출 전환 |
| 편집 가능 | 24시간 내 1회 수정, 이후 잠김 |
| 구매 검증 | 구매 이력 있는 uid만 작성 가능 (비구매 방어) |

### 2.4 별도 UI: "구매수" 와 "후기"의 관계

- 구매자 수는 **블러 페이지 CTA 위에** — 결제 직전 의심 차단.
- 후기 카드는 **CTA 아래에** — "결제 후에 내가 저렇게 쓸 수 있겠다" 예상.
- 홈 상품 카드에도 구매자 수 **mini 라벨** — 상품 진열 단계에서 기본 신뢰 확보.

### 2.5 "방금 구매" 티커

- 우측 하단 fade-in toast, 3초 노출 후 fade-out.
- 5분에 1회 등장 (너무 자주 = 가짜스러움, 너무 드물게 = 효과 약함).
- 익명화: "전주에 사시는 지은님" 지역명 + 이름 1글자만.
- **어뷰징 방지:** 실제 결제 이벤트 기반. 페이크 데이터 절대 금지.
- 결제 이벤트 없는 시간대(새벽 3~6시)엔 **티커 자체 생략** — 오히려 진정성 확보.

### 2.6 조작 방지 알고리즘

| 대상 | 검증 | 조치 |
|---|---|---|
| 후기 작성자 | `payments` 컬렉션에 해당 uid의 해당 productId 결제 기록 존재 | 없으면 작성 차단 |
| 구매자 수 | 결제 성공 이벤트만 카운트 (실패·환불 제외) | 환불 시 -1 |
| "오늘" 카운트 | 서버 시간 기준 00:00~23:59 롤링 | 클라이언트 조작 불가 |
| IP/기기 집중 후기 | 동일 IP에서 24h 내 3건 이상 → 보류 | 수동 검토 |
| 언어 패턴 | 반복 표현 · 키워드 스팸 감지 | AI 1차 필터 |
| 광고성 링크 | URL · 경쟁사 언급 감지 | 자동 거절 |

### 2.7 표시 카피 규칙

**숫자 앞에 맥락 있는 단어:**
- ❌ "12,384명" — 단순 수.
- ✅ "지금까지 12,384명이 내 사주를 확인했어요" — 서사 + 숫자.

**"오늘" 카운트 배지:**
- ❌ "오늘 324" 
- ✅ "오늘만 324명" — "오늘"이 뚜렷한 시간 단위.

**후기 카드 헤더:**
- ❌ "고객 후기"
- ✅ "먼저 본 사람들의 후기" — 행동 묘사형.

## 3. 컴포넌트 명세

### 3.1 `PurchaseCountBadge`

```tsx
interface PurchaseCountBadgeProps {
  productId: string;
  variant: 'home-card' | 'blur-cta' | 'inline';
}
```

**데이터:**
- Firestore `counters/products/{productId}` 문서 구독 (실시간 증가 카운터).
- 증가는 Cloud Function `onPaymentSuccess` 트리거.

**표시:**
- `home-card`: `324명이 오늘 구매`
- `blur-cta`: `지금까지 12,384명이 내 사주를 확인했어요 · 오늘만 324명`
- `inline`: 소형, 15px, 회색.

### 3.2 `ReviewCardSlider`

```tsx
interface Review {
  id: string;
  text: string;
  authorMask: string;   // "ㅇㅇ(29, 여)"
  productId: string;
  createdAt: Timestamp;
  empathyCount: number; // 공감 수
  featured: boolean;    // 베스트 5 선정
}

interface ReviewCardSliderProps {
  productId: string;
  limit?: number; // default 10
}
```

- 가로 스와이프 슬라이더, 카드 1개 너비 280px.
- "공감 ❤️" 버튼 (로그인 필요 — 리워드 연계 없음, 순수 시그널).
- 피처드 카드는 상단 골드 라인.

### 3.3 `LivePurchaseTicker`

```tsx
interface LivePurchaseTickerProps {
  enabled: boolean;    // 새벽대 false
}
```

- 우측 하단 absolute, 3초 토스트.
- 데이터 출처: 최근 5분 결제 이벤트 스트림 (Firestore listener 또는 WebSocket).
- 실명 익명화 함수: `maskName(name, region)` = `"${region[0]}주에 사시는 ${name[0]}님"`.

### 3.4 `ReviewComposer`

- 결제 완료 후 48시간 알림 DM에 포함된 링크로 진입.
- 20자 제한 카운터, 보상 안내, 스팸 가이드.
- 제출 시 AI 1차 필터 → 대기 큐 → 수동 승인.

## 6. 모더레이션 파이프라인

### 6.1 AI 1차 필터 (즉시)

- 입력 후 1초 내 반환.
- 기준:
  - 욕설·혐오표현 (Perspective API 또는 Claude classifier)
  - 타사명·링크 포함
  - 광고성 어투
  - 동일 후기 반복 등록

### 6.2 수동 2차 (준기 1인 운영)

- 승인 대기 큐 관리자 페이지.
- 1건당 10초 내 판단 목표 (업무 시간 1일 1회 처리).
- 엣지 케이스:
  - 부정적 후기 → 노출 허용 (필터링 금지, 투명성).
  - 단, 허위·비방·개인정보 포함은 거절.

### 6.3 노출 알고리즘

```
최종 노출 풀 =
  최근 승인 10건 (recency) 40%
+ 공감 수 상위 10건 (quality) 40%
+ 다양성 보정 (성별·연령 균형) 20%
```

- 상품별로 분리 적용.
- 슬라이더는 랜덤 시드(날짜 기반)로 매일 순서 변경 → "새로워 보임".

| E-09 | 티커가 새벽 3~6시 노출됨 | 서버 시간 체크, 해당 시간대는 `enabled=false` |
| E-10 | 후기 텍스트에 개인정보 포함 (이름·전화·이메일) | AI 필터에서 PII 감지 → 거절 |
| E-11 | 후기 슬라이더 가로 스와이프가 세로 스크롤과 충돌 | `touch-action: pan-y`로 제어 |

| E-13 | 실시간 티커가 이탈 유저를 놓고 가짜처럼 느껴짐 | 결제 이벤트 10분 TTL, 가짜 데이터 절대 금지 |
| E-14 | 후기가 너무 짧아서 노출 품질 낮음 (20~30자) | 공감수 알고리즘 자동 하향 |

## 10. 오픈 퀘스천

1. **"방금 구매" 티커 노출 빈도** — 5분 vs 7분 vs 10분. A/B 후 결정.
2. **후기 작성 보상 0.5운이 낮은지** — 1운(500원)으로 올리면 스팸 증가 우려. 균형점 탐색.
3. **공감 수 UI 도입 여부** — "❤️ 42"가 별점처럼 작동할 리스크. 초기 비활성화 권장.
4. **부정 후기 비율 상한** — 노출 풀에 부정적 후기 비중이 높을 경우 구매 저해. 자연 분포 유지 vs 편향 관리.
5. **모더레이션 자동화 수준** — 준기 1인 수동 승인 한계, Phase 2에 외주/자동화 필요.
6. **"먼저 본 사람들의 후기" vs "실제 후기"** — 카피 A/B.
7. **별점 대체로 "내 친구에게 추천할까?" NPS식 단순 버튼 도입 여부** — Phase 2 재검토.
