## 1. 목적 (Goal)

**"런칭 2주 동안 '유료 결제 경험자'를 최대한 많이 만든다."**

사주500은 결제 1회의 심리적 허들을 넘긴 유저가 ARPU를 만든다. 런칭 프로모션의 유일한 목표는 **"유료 결제 경험자 수 최대화"** — 나중에 진짜 500원을 낼 때 망설이지 않는 유저군을 단기간에 확보한다.

**성공 지표:**
- 런칭 D+14 기준, 3원 리워드 지급 유저 ≥ 20,000명.
- 그 중 **실제 결제(전체 무료 아닌 다른 상품) 경험자** ≥ 5,000명 (25%).
- 프로모 종료 후 7일 내 유료 결제 복귀율 ≥ 40%.
- 어뷰징으로 인한 부정 지급 < 2%.

## 2. 프로모션 구성 (Composition)

### 2.1 프로모션 2종 병행

| 장치 | 대상 | 효과 | 기간 |
|---|---|---|---|
| **A. 3원 리워드** | 신규 가입자 1회 | 지갑에 3원 자동 적립, 결제 시 최대 3원 할인 | 상시 (런칭 직후 한정 공지) |
| **B. 전상품 무료 개방** | 모든 유저 | 500원·5,000원 상품 전부 무료 열람 (횟수 제한 있음) | 런칭 D0 ~ D+14 |

**왜 2개를 쓰는가:**
- 3원 리워드는 **"내 돈으로 결제한 느낌"**을 주는 행동 유도 장치 (유료 전환 학습).
- 무료 개방은 **"진짜 퀄리티를 먼저 보여주는"** 확신 장치 (상품 자체 경험).
- 두 장치가 **보완**. 무료만 하면 "꽁짜라 쓴다", 3원만 하면 "한 번 쓰고 끝". 둘이 맞물려야 "한번 봤더니 좋아서 다음엔 내 돈으로".

### 2.2 무료 개방 상세

- 대상 상품:
  - 500원 심층분석 (성격·직업·재물·애정·건강 5종)
  - 5,000원 프리미엄 종합 리포트
  - 5,000원 궁합 리포트
- 횟수 제한:
  - 500원 상품: **1계정당 3회 무료** (5종 중 3개 선택 가능)
  - 5,000원 상품: **1계정당 1회 무료**
  - 궁합: **1계정당 1회 무료**
- 무료 결제도 **"결제" UX 그대로 경험** — IAP/PG 호출은 실제 발생하지 않되, 화면 플로우는 동일. "결제가 필요 없어요, 런칭 기념으로 무료!" 배너로 차별화.
- 프로모 종료(D+14 23:59 KST) 순간 정확히 차단.

### 2.3 3원 리워드 상세

- **지급 시점:** 가입 직후(익명 또는 인증 무관), 홈 진입 3초 이내 토스트.
- **금액:** 3원 (`reward` 버킷에 `bonus_launch` 태그로 적립).
- **사용 조건:**
  - 500원 상품 결제 시 자동 적용 → 497원 결제로 변환.
  - 무료 개방 기간 중 무료 결제 시 **차감되지 않음** (리워드 잔액 보전).
  - 5,000원 상품에는 자동 적용되지 않음 (의도적 제한).
- **유효 기간:** 30일 (지급일 기준).
- **중복 방지:** 계정당 1회, 3축 검증 (토스 CI + 기기 fingerprint + 전화번호).
- **환급 불가:** 출금·환불 대상 아님.

## 3. 어뷰징 방어 (Anti-Abuse)

### 3.1 3축 검증

| 축 | 앱인토스 | 웹 |
|---|---|---|
| 1. 기기 fingerprint | SDK 제공 기기 ID | FingerprintJS |
| 2. 인증 식별자 | `tossCi` (토스 CI) | 전화번호 (Phase 2 OAuth) |
| 3. 전화번호 | 토스 계정 번호 | SMS 인증 (Phase 2) |

**검증 로직:**

```
신규 가입 →
  기기 fingerprint 조회 → 이미 지급? → YES: 차단
                                      → NO: 다음
  tossCi(또는 전화번호) 조회 → 이미 지급? → YES: 차단
                                          → NO: 다음
  지급 + 3축 모두 저장
```

- **Phase 1 웹:** 기기 fingerprint만으로 1차 방어. 완벽하지 않음 (쿠키 삭제·시크릿 모드 회피 가능).
- **Phase 2 웹:** SMS 인증 추가 시 3축 완성.

### 3.2 행동 패턴 감지

| 패턴 | 임계 | 조치 |
|---|---|---|
| 동일 IP에서 24시간 내 가입 시도 | 5건 이상 | IP 차단, 수동 검토 |
| 결제 없이 무료 개방만 소진 | 3회 모두 소비 + 결제 0건 | 재방문 푸시, 차단은 아님 |
| 동일 프로필(이름·생년월일)로 재가입 | 2회 이상 | 신규 지급 차단 |
| 기기 변경 없는 재로그인 후 재지급 시도 | N/A | fingerprint 매칭 차단 |
| 환불 이후 3원 재지급 시도 | N/A | 이미 지급 flag 유지 |

### 3.3 예산 상한

| 항목 | 상한 | 비상 정지 |
|---|---|---|
| 3원 리워드 총 지급액 | 20만원 (약 6.6만명) | 15만원 도달 시 관리자 알림 |
| 무료 개방 총 원가 | 1,000만원 (상품 원가 기준) | 700만원 도달 시 프로모 조기 종료 검토 |
| AI 호출 비용 | 총 상품 수 × Claude API 원가 | 실시간 대시보드 모니터링 |

**비상 정지 스위치:** Firebase Remote Config `promo.launchActive = false` → 즉시 종료 가능.

## 6. 유저 스토리

### US-01. 런칭 당일 가입 → 무료 체험 → 결제 전환
> *지은(27, 여, D+2 가입). 홈에 "전상품 무료" 배너 → 500원 성격분석 무료로 열림 → "이거 진짜네?" 만족 → 다음날 직업분석 무료 체험 → D+5에 애정분석은 결제 (3원 적용 → 497원). 유료 전환 성공.*

### US-02. 무료만 소비하고 이탈
> *태현(33, 남, D+10 가입). 500원 3개 + 5,000원 1개 모두 무료 소비. 결제 0건. 프로모 종료 D+14. 종료 후 "3원 아직 남으셨죠" 푸시 받음. 망설이다 D+17에 재방문, 추가 상품 결제 1건. 늦었지만 전환.*

### US-03. 어뷰징 시도
> *공격자 X. 브라우저 시크릿 모드로 10회 가입 시도. 1회는 fingerprint 변화로 지급됨(한계). 2회차부터 동일 전화번호로 인증 실패 (웹은 Phase 2) → SMS 없는 Phase 1은 부분 방어.*

### US-04. 대기자 → 오픈 당일
> *수아(24, 여, D-3 대기자 등록). D0 오픈 알림 푸시 수신. 즉시 가입, 3원 리워드 + 무료 개방 병행 경험. 친구 2명 초대 → 궁합 무료로 확인.*

## 7. 엣지 케이스

| ID | 상황 | 처리 |

| E-01 | 프로모 종료 1분 전 결제 시작, 완료는 1분 후 | 결제 시작 시점 기준 프로모 적용. 종료 후 완료 결제는 무료 유지 |

| E-11 | 3원 리워드를 5,000원 결제에 적용 시도 | 서버 거절, "3원은 500원 상품에만" 안내 |

| E-13 | 종료 공지를 못 본 유저 | 종료 후 7일간 "런칭 기념 아쉽게 놓치셨다면…" 푸시 1회 |
| E-14 | 프로모 기간 중 후기 작성 | 리워드 지급(0.5운)은 정상, 후기 내용에 "공짜로 받아서" 언급은 필터링 X (자유) |
| E-15 | D+14 23:59:59에 완료 결제 경계 | 서버 시간 기준, 1초 단위 정확히 차단 |

## 8. 수용 기준 (Acceptance Criteria)

| ID | 기준 |
|---|---|
| AC-01 | 3원 리워드 지급은 신규 가입 직후 3초 이내 토스트로 안내 |
| AC-02 | 리워드는 3축 검증 후에만 지급, 실패 시 재시도 없음 |
| AC-03 | 무료 개방 기간 중 500원 3회 / 5,000원 1회 / 궁합 1회 한도 강제 |
| AC-04 | 프로모 종료 시점은 서버 시간 기준 1초 단위 정확 |
| AC-05 | Firebase Remote Config로 언제든 비상 정지 가능 |
| AC-06 | 예산 상한 도달 시 관리자 슬랙 알림 + 자동 차단 검토 |
| AC-07 | 모든 프로모 이벤트는 `promo_events` 컬렉션에 감사 로그 저장 |
| AC-08 | 프로모 종료 후 7일간 "3원 남았어요" 리마인더 발송 |
| AC-09 | 프로모 배너는 홈 sticky, 카운트다운 실시간 갱신 |
| AC-10 | 무료 결제 UX는 일반 결제와 **시각적으로 동일**, 런칭 기념 문구만 차별 |
| AC-11 | 3원 리워드는 5,000원 상품에 적용 불가 |
| AC-12 | 런칭 사전 예고 페이지(D-7)에서 대기자 등록 가능 |

## 11. 오픈 퀘스천

1. **3원이 너무 작아서 "무시되는" 문제** — 5원·10원 A/B 필요. 단, 심리적 "정확히 500원 체험" 효과가 3원 가까울수록 강함.
2. **무료 개방 3회 / 1회 한도가 적절한가** — 너무 많으면 유료 전환 지연, 너무 적으면 체험 부족.
3. **프로모 기간 14일이 최적인가** — 7일(짧고 강렬) vs 21일(완만) 비교. 14일은 중간값.
4. **대기자 등록 인센티브** — "오픈 알림 + α"로 뭘 더 줄지. 추가 비용 없는 선으로.
5. **친구 초대 프로모를 동시에 할지** — 3원 × 2 (초대자 + 피초대자) 바이럴 고려.
6. **무료 결제 후 유저가 "결제 없는 서비스"로 인식하는 리스크** — 종료 후 전환 속도 A/B 필요.
7. **어뷰징 방어의 Phase 1 웹 한계** — SMS 인증 없는 상태에서 fingerprint만으로 몇 %가 뚫리는지 실측 필요.
