# 앱인토스 제출 전 품질 감사 — 7축 체크리스트

**목적:** 앱인토스 검수 제출 전 "완벽한 앱이냐" 판단. 검수 반려·민원·환불 사유를 사전 차단.
**상태 표기:** ✅ 통과 / ⚠️ 의심 / ❌ 미통과 / ❓ 확인 불가 (준기·Claude Code·실기기 필요).
**작성일:** 2026-04-20. 각 축은 **실사용자 1명 풀 플로우**를 완주하며 점검한다.

---

## 감사 자세

감사는 **문서 검토가 아니라 실사용 검증**이다. 코드·PRD·메모리만 보고 통과 판정하지 말 것.

- 실기기 2대(iOS 1 + Android 1) 또는 최소 데스크톱 + 모바일 Safari 크롬.
- 실계정 2~3개 (신규 가입 + 재방문 + 결제 완료 페르소나).
- 실결제 1건은 반드시 포함 (토스페이 또는 카카오페이).
- 각 축 확인 시 스크린샷·녹화로 증거 남길 것. 검수 반려 시 증거로 재제출 가능.

**기준:** 플로우가 꼬이지 않는지. 첫 진입~결제까지 클릭 8회 이내, 뒤로가기 파괴 없음.

## 축 4 — 고객경험 전체 흐름

**기준:** 페르소나 3명이 각자 다른 의도로 진입해 완주하는 시나리오. 각 페르소나 20분 녹화.

**페르소나 A — "재미로 한번"**
입력 → 무료 Aha → 블러잠금 보고 "이 정도면 충분" 이탈. 이탈 시점까지 불편·혼란 0인지.

**페르소나 B — "궁합 보려고"**
입력 → 무료 Aha → 블러 L3(궁합) 보고 500원 결제 → 풀 리포트 → 재방문 유도.

**페르소나 C — "회의론자, 500원 써봄"**
입력 → 무료 Aha 회의적 태도 → 블러 L1(풀 리포트) 결제 → "맞네" 또는 "별로"로 이탈.
이탈 시 리텐션 유도 포인트 어디 있는지. 재방문 이유가 있는지.

**평가 관점:**
- 각 페르소나가 **"이 앱은 500원 값어치 한다"** 판단하는 지점이 존재하는가?
- 반대로 **"500원 아까웠다"** 판단할 위험 지점은 어디인가?

**Claude 판단 가능:** 페르소나 시나리오 작성만 가능. 실제 체감은 준기 본인 또는 지인 3명 테스트 필요.

## 앱인토스 검수 대응 체크 (별도)

축 1~7과 별개로 앱인토스 심사 기준이 따로 있을 가능성. 지금 확인 필요:
1. 앱인토스 운영자에게 검수 기준 문서 요청 (콘텐츠 가이드라인·결제 정책·UX 필수 요건).
2. 사주·점술 카테고리 특별 정책 (연령 제한, 공지 문구, 면책 문구) 확인.
3. 제출 양식·스크린샷 규격·설명문 요구사항 확인.

이 3개 확인 전에는 감사 결과가 "잘 만들어졌지만 검수 반려" 가능성 있음.
