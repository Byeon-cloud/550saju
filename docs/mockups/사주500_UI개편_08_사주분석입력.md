# 사주500 UI 개편 — 08 사주분석 입력 (`/input`)

> 마스터 스펙 토큰 기반.
> 핵심: **빈 폼으로 시작** (버그 4). 이전 데이터 자동 prefill 금지.
> 한국 시간 보정 ±30분 UX 반영 (`project_kr_saju_time_correction.md`).

---

## 0. 결정 반영 요약

| 항목 | 정책 |
|----|----|
| 초기값 | **빈 폼**. `?profileId=` 있으면 prefill, 아니면 전부 empty |
| `lastInput` | "이전 입력값 불러오기" Ghost 버튼 통해서만 사용 (명시 액션) |
| 시간 보정 | 출생 시간 ±30분 한국 지역 보정 안내 + 모름 옵션 |
| 음력/양력 | 토글 2버튼 (기본 양력) |
| 진입 후 목적지 | 분기 — 결과 페이지 / 대화 시작 / 보관함 추가 |

## 6. BirthDateField

### 6-1. 양력/음력 토글
- 높이 40, pill 2버튼 (폭 120씩)
- 기본: 양력 선택됨
- 음력 선택 시 작은 Caption `ink-soft` "음력은 사주 계산에 맞춰 변환해요"

### 6-2. 날짜 입력
- 높이 52, radius 12, border 1px `gray-line`
- iOS/Android 네이티브 date picker 호출 (`<input type="date">`) — HTML5 native
- placeholder "1995.05.12 선택"
- 값은 YYYY.MM.DD 표시 (DD/MM/YYYY 금지)
- 유효 범위: 1900-01-01 ~ 오늘
- 에러: "오늘 이후는 선택할 수 없어요"

### 6-3. 음력 선택 시 윤달 처리
- 음력 선택 + 윤달 있는 달 선택 시 체크박스 "윤달" 노출
- 1985 이후 음력 DB 기준 (서버 검증)

## 10. SubmitBar (하단 sticky)

### 10-1. 시각
- 높이 80, 배경 `paper`, 상단 1px `gray-line`, padding 16 20, safe-area
- Primary 버튼 (높이 52, 풀폭)
- 유효성 충족 시 활성 / 아니면 비활성 (opacity 0.4)

### 10-2. 버튼 레이블 (진입 경로별)

| 경로 | 레이블 |
|----|----|
| 홈 Pillar daily | "오늘의 운세 보기" |
| 홈 Pillar dream | "꿈해몽 시작하기" |
| 홈 Body Premium | "프리미엄 풀이 시작하기 (10운)" |
| 홈 Body Topic | "주제 고르러 가기" |
| 홈 Caption (대운·월운·궁합·토정) | "{주제} 풀이 시작 (1운)" |
| 보관함 → 새 사주 추가 | "사주 저장하기" |
| 사주대화 → 사주 추가 | "이 사주로 대화 시작하기" |
| 결과 페이지 → 다른 분 사주 | "이 분으로 풀이 시작" |

### 10-3. 제출 플로우
1. 유효성 검증 (이름·성별·날짜 필수, 시간은 "모름" 허용)
2. 시간 보정 적용 (KR ±30분)
3. 서버에 프로필 저장 (로그인 상태면 서버 DB, 아니면 localStorage)
4. 진입 경로별 목적지로 이동:
   - daily → `/daily/{newResultId}` (풀이 생성 → 풀스크린 로딩)
   - premium → 10운 결제 확인 모달 → 결과
   - topic → `/topic` 리스트
   - dream → `/dream`
   - chat 추가 → `/chat/{newSessionId}`
   - 보관함 추가 → 보관함 복귀 토스트

## 11. 폼 유효성

### 11-1. 필수 필드
- 이름 (1~12자)
- 성별 (선택됨)
- 생년월일 (오늘 이하)
- 시간 (12지지 중 1개 또는 "모름")

### 11-2. 에러 표기
- 인라인: 각 필드 아래 Caption 12/500 `danger`
- 예:
  - "이름을 입력해주세요"
  - "성별을 선택해주세요"
  - "오늘 이후 날짜는 선택할 수 없어요"
  - "생년월일을 선택해주세요"
  - "태어난 시간을 선택해주세요 (모르면 '모름')"
- 모든 필드 통과 전까지 Submit 비활성

### 11-3. 중복 프로필 처리
- 로그인 상태 + 동일 이름·생년·시간 프로필 존재 시
  - 모달: "같은 정보의 프로필이 이미 있어요. 기존 프로필을 사용하시겠어요?"
  - 기존 사용 / 새로 저장 / 취소

## 14. 데이터 구조 (PC 참고)

```ts
type InputFormState = {
  name: string;
  gender: 'male' | 'female' | '';
  calendar: 'solar' | 'lunar';
  isLeapMonth?: boolean;
  birthDate: string;      // YYYY-MM-DD
  hourCode: '자'|'축'|'인'|'묘'|'진'|'사'|'오'|'미'|'신'|'유'|'술'|'해'|'unknown';
};

type SubmitPayload = InputFormState & {
  correctedHourMinutes?: number;   // KR 보정 적용 후 분 단위 (예: 06:00 → 05:30)
  clientTimezone?: string;         // 기본 'Asia/Seoul'
  referrer?: string;               // 진입 경로 식별
};
```

## 17. 접근성

- 각 필드 `<label for="">` 로 인풋 연결
- 시간 시트 = `role="listbox"` + 각 옵션 `role="option"`
- 에러 Caption = `aria-describedby="..."` 로 인풋과 연결
- 제출 버튼 비활성 상태도 스크린 리더가 읽을 수 있게 (`aria-disabled="true"`)
- 시간대 설명(KR 보정)은 `<details>` 또는 항상 노출, `aria-live="polite"`
