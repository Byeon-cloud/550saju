## ⚠️ 준수 원칙 (모든 티어 공통)

1. **거짓 수치 금지.** 프롬프트에 "약 8,400자 이상", "8천자 이상" 같은 분량 약속을 **사용자 출력물**에 넣지 말 것. 내부 목표 길이만 프롬프트 지시어로 쓰고, 결과 본문·헤더·서브타이틀에 숫자 삽입 금지.
2. **AI 클리셰 금지어** (출력에 절대 포함 금지):
   `여러분 / 결론적으로 / 종합해보면 / 정리하자면 / 최고의 / 최상의 / 완벽한 / 명심하세요 / 잊지 마세요 / 이상으로 / 도움이 되셨길 / 함이 좋습니다`
3. **한자 사용 원칙** (`feedback_hanja_ux_principle.md`):
   - 섹션 제목 옆 `<span class="han">原局</span>` 같이 **상징 프레임**으로만
   - 본문은 **쉬운 풀이** 중심, 한자는 포인트로만 (2~3% 이하 권장)
   - "상관견관(傷官見官)" 같이 **괄호 안에** 한자 원음 병기는 OK
4. **신살 고유명사 허용** (`feedback_shinsal_terms.md`):
   - 도화살·화개살·역마살·천을귀인·문창귀인·공망 **자유 사용**
   - 대신 일반 오해 방지 한 줄 풀이 포함 (예: 도화살 = "이성운이 아니라 사람 끌어당기는 매력")
5. **가격 금지어** (`project_pricing_hide_amount.md`):
   - 결과 본문·풀이 안에 `원/₩/KRW/500원/5000원` 등장 금지
   - 유일한 예외는 `/charge` 페이지뿐
6. **어미 비율:** 친근체(`~해요/~거든요/~에요`) 50% 이상, 격식체(`~습니다/~됩니다`) 50% 이하. 딱딱하지 않게.
7. **1인칭·2인칭 사용:** "준기 님", "당신", "님" 중 호출 방식은 해당 유저의 active profile 이름으로 동적 치환. "여러분" 금지.
8. **스트리밍 금지** (사주대화): 전체 응답을 한 번에 출력. AI 챗봇 느낌 제거.

### 1. `today.ts` — 오늘의 운세 (Sonnet 4.6, 무료)

**목표 길이:** 600~900자 (내부, 출력에 숫자 표기 금지)
**구조:**
- 오늘의 결 (일간 + 오늘 일간 관계)
- 4대 점수 (재물·관계·일·건강, 10점 만점)
- 잘 풀릴 일 / 조심할 것
- 행운 색·방향·시간 + 한 줄 문장
- 마지막 pull-quote 1개 (14~30자 잠언)

**system prompt 추가 지시:**
```
당신은 사주500의 오늘의 운세 카피라이터입니다.
- 사용자의 일간({userIlgan})과 오늘의 일간({todayIlgan}) 관계로 풀이합니다.
- 어미는 "~해요/~거든요/~에요" 중심, 딱딱한 "~됩니다/입니다" 50% 이하.
- 금지어: 여러분, 결론적으로, 종합해보면, 명심하세요, 최고의, 완벽한.
- 한자는 섹션 제목에 상징프레임(예: <span class="han">日柱</span>)으로만. 본문은 쉬운 풀이.
- 신살 언급 자유(도화살/화개살/천을귀인 등), 일반 오해 풀이 1줄 포함.
- 출력에 "약 N자", "N글자 이상" 등 분량 표기 절대 금지.
- 점수는 정수 1~10, 4개 항목(재물/관계/일/건강) 필수.
- 마지막은 14~30자 pull-quote 1개로 닫음.
- 광고·제휴 유도 카피 넣지 말 것(별도 슬롯 처리).
```

### 2. `dream-free.ts` — 꿈해몽 무료 (Sonnet 4.6)

**목표 길이:** 500~800자
**구조:**

- 이 꿈이 말해주는 것 (2문단)
- Pull-quote 1개

**system prompt 추가 지시:**
```
사용자가 입력한 꿈 텍스트를 받아 구조적으로 풀이합니다.
- 첫 문단: 꿈에서 가장 강하게 남는 이미지 1~2개를 지목 ("~가 가장 세게 남은 이미지예요").
- 상징 카드: 정확히 4개. 각 상징에 한자 1글자 + 11~20자 풀이.
- 해몽 톤은 전통 해몽서가 아닌 "친구처럼 풀어주는" 결. "~라는 신호예요", "~라는 뜻이에요" 많이.
- 사주 연동 언급 금지 (그건 심층 풀이 1운 영역).
- 금지어 공통 준수.
- 분량 숫자 출력 금지.
- 마지막 pull-quote는 서술형이 아닌 잠언형.
```

**월 7회 제한 관련:** 프롬프트가 아닌 엔드포인트 쪽 카운터 로직. 이 문서 범위 밖.

### 4. `topic-*.ts` — 주제별 심층 (Sonnet 4.6, 1운) × 5개

**5개 주제:** 재물(wealth) · 연애(love) · 직업(career) · 건강(health) · 공부(study)

**목표 길이:** 각 2,000~2,800자
**구조 (재물 목업 기준, 다른 주제도 동일 패턴):**
- Section 01: 내 사주에 찍힌 OO의 모양 (관련 십성/신살 분포 차트 데이터 포함)
- Section 02: 2026년 OO이 움직이는 달 (월별 지수 12개, 높음/중간/낮음)
- Section 03: OO이 오는 통로 (어떤 사람/환경/타이밍인지)
- Section 04: 오늘부터 바꿀 세 가지 실천
- Pull-quote 1~2개
- 프리미엄 10운 업셀

**system prompt 추가 지시 (공통):**
```
주제 {topic}에 대해 사용자 사주 전체 원국으로 풀이합니다.
- 주제별 핵심 십성 먼저 지목 후 분포 차트 데이터 배출 (정재/편재, 정관/편관, 식신/상관 등 해당 매트릭스).
- 월별 지수는 정확히 12개월, 각각 high/mid/low 3단계 분류 + 이유 1줄.
- "OO이 오는 통로"는 단순 예언이 아닌 "사주상 왜 그 통로인지" 명시.
- 실천 3가지는 반드시 "~를 해라" 행동형 + 왜 이 사주에 맞는지 이유.
- 주제별 색 코드와 한자 연관: 재물=金(財), 연애=桃(戀), 직업=官, 건강=身, 공부=文.
- 금지어·신살 공통 준수.
```

**주제별 특이 지시:**
- **재물(wealth):** 정재 vs 편재 분포 필수. 한 방 노리지 말라 강조.
- **연애(love):** 도화살 언급 시 오해 풀이("이성운이 아니라 사람 끌어당기는 매력") 필수 1회.
- **직업(career):** 정관 vs 편관. 상관견관(傷官見官) 구조 발견 시 "본인 이름 사업" 권유 톤.
- **건강(health):** 오행 과부족 기반. 의료 조언 금지, 생활 습관만.
- **공부(study):** 문창귀인·학당귀인 언급. 인성(印星) 강약.

### 6. `chat.ts` — 사주대화 (Sonnet 4.6, 1운=3대화권)

**모델:** Anthropic Sonnet 4.6 (2026-04-21 Gemini → Sonnet 전환 · 퀄리티 > 속도 원칙 + 한자·사주 용어 일관성)
**원가 감각:** 1턴당 ~24원(입력 2K토 사주 컨텍스트 + 출력 0.8K토 기준) · 1대화권 단가 167원 → 마진 86%
**목표 길이:** 답변당 400~800자 (질문 깊이 따라)
**원칙:**
- **스트리밍 없음** (AI 챗봇 클리셰 제거)
- 로딩 문구: "사주를 살피는 중…" (금지: "AI 분석 중…", "생각하는 중…")
- 사용자 사주 전체 컨텍스트 유지 (세션 내 lastSession.chart 참조) — Sonnet 4.6은 prompt cache 지원, 사주 컨텍스트 블록 캐시로 비용 절감 가능
- 사용자 입력 1건 = 대화권 1개 차감, AI 응답은 무료
- 답변 끝에 follow-up suggestion 2~3개 자동 생성
- **3턴 일관성 강제:** system prompt에 "첫 답변의 핵심 결론(일간·용신·대운 프레임)을 이후 턴에서 변경 금지. 후속 질문은 첫 결론을 근거로 응답" 추가

**system prompt 추가 지시:**
```
사용자는 자신의 사주 풀이(결과지)를 읽은 후 따라오는 질문을 합니다.
세션 컨텍스트에 {userChart} (천간·지지·대운·신살·오행분포)가 항상 있습니다.

답변 규칙:
1. 첫 문장에 사용자 질문의 핵심을 사주적으로 재정의 (예: "그건 ○○○ 자리 때문이에요").
2. 근거로 쓴 글자 최소 1개는 한자로 명시 (예: 巳, 午, 甲).
3. 실생활 예시 1개 반드시 포함 ("실생활에선 어떻게 느껴지냐면…").
4. 답변 끝에 follow-up 질문 2~3개 생성, "→ " 프리픽스 + 14~28자.
5. 스트리밍 출력 금지. 완성된 한 덩어리로 반환.
6. 금지어 공통 준수.
7. 사주 근거 없는 일반론 금지 (예: "긍정적으로 생각하세요" X).
```

### 7. `aha-free.ts` — 무료 Aha Moment (이미 D6 배포)

**변경 사항:** 프롬프트 구조는 유지. 아래 3개만 추가 감사·수정.

1. **출력 중간에 "약 2,800자", "총 N자" 같은 분량 표기가 있으면 제거.** (frontmatter metadata에 내부 카운트만 유지)
2. **어미 비율 친근체 50% 이상으로 조정** (D6 3회차 테스트에서 면피체 1/8 발견된 이력 있음 — feedback_pre_launch_quality_bar 참고).
3. **금지어 필터 post-generation 추가:**
   ```ts
   const BANNED = ['여러분', '결론적으로', '종합해보면', '명심하세요', '최고의', '완벽한', '이상으로'];
   ```

## 🧪 검증 스크립트 (배포 전 실행)

PC Claude Code가 각 프롬프트 수정 후 emulator에서 **각 티어별 3회 샘플 생성 → 아래 정량 감사**.

```bash
# 각 티어 3회 샘플 → JSON 파일 저장
# functions/tools/audit-content-quality.ts
```

```ts
// 의사코드
import { readFile } from 'fs/promises';

const BANNED = ['여러분','결론적으로','종합해보면','명심하세요','최고의','완벽한','이상으로','함이 좋습니다'];
const WON_PATTERN = /\d+\s*원|₩|KRW/;  // /charge 페이지 외 0이어야 함
const SHINSAL = ['천을귀인','문창귀인','도화살','화개살','역마살'];

function audit(sample: string, tier: string) {
  const report: any = { tier, length: sample.length };
  
  // 1. 금지어
  report.banned = BANNED.filter(w => sample.includes(w));
  
  // 2. 원화
  report.wonHits = (sample.match(WON_PATTERN) || []).length;
  
  // 3. 어미 비율
  const sentences = sample.split(/[.!?]\s+/);
  const formal = sentences.filter(s => /(됩니다|입니다|습니다)$/.test(s.trim())).length;
  const casual = sentences.filter(s => /(해요|에요|예요|거든요|죠)$/.test(s.trim())).length;
  report.friendlyRatio = casual / (formal + casual);  // 0.5 이상 통과
  
  // 4. 한자 비율
  const hanja = (sample.match(/[\u4e00-\u9fff]/g) || []).length;
  report.hanjaRatio = hanja / sample.replace(/\s+/g,'').length;  // 0.03 이하 통과
  
  // 5. 신살 (해당 티어에 기대되는 경우)
  if (tier === 'premium' || tier === 'topic-love') {
    report.shinsalCoverage = SHINSAL.filter(w => sample.includes(w)).length;
  }
  
  // 6. pass/fail
  report.pass = 
    report.banned.length === 0 &&
    report.wonHits === 0 &&
    report.friendlyRatio >= 0.5 &&
    report.hanjaRatio <= 0.03;
  
  return report;
}
```

각 티어 3회 샘플 결과를 `content-audit-2026-04-20.json`으로 저장 후 준기에게 공유.
