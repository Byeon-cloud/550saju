# 사주500 UI개편 09 — 이벤트 탭 (v3, 정책 반영·UX 재설계)

**개정**: 2026-04-21 v3. v2의 7일차 확률 박스(1운 85%/2운 10%/토스포인트 5%)가 앱인토스 프로모션 "랜덤 보상 금지" 정책과 충돌하여 전면 재설계. 토스포인트는 UAC 프로모션으로 완전 분리.

**원칙**:
1. 쉽게·간단하게·직관적으로 — "공짜돈 벌어가는 느낌" 유지
2. **주간 누적 출석 모델** — 끊김 스트레스 제거, 재시작 허들 제로
3. **이모지 0개 · 자체 SVG 픽토그램만** — 전체 앱 일관
4. **랜덤·확률·뽑기 어휘 전면 금지** — 정책 충돌
5. 토스포인트 지급 경로는 UAC 프로모션(신규 설치) 1회성 고정 금액만 — 이벤트 탭 경로에는 포함 불가

## §3. 출석 — 주간 누적 모델

### 3.1 기본 로직

- **주 사이클**: 매주 **월요일 00:00 KST** 리셋 → 일요일 23:59 KST까지가 한 주
- **출석 1일 인정 기준**: 해당 날짜(KST)에 **콘텐츠 결과 페이지를 1회 이상 본 경우** — 무료·유료 무관
  - 무료 오늘의 운세·꿈해몽도 인정
  - 500원 단건도 인정
  - 5000원 프리미엄도 인정
  - **사주 등록만 한 경우는 불인정** (콘텐츠 소비 아님)
- **마일스톤 2개**: 이번 주 **4일 출석 → 1운** · 이번 주 **7일 출석 → 2운**
  - 4일이 연속일 필요 없음 (월·화·목·토 → 4일 인정)
  - 7일 = 월~일 전부 출석
- **주간 리셋 시점**: 월요일 00:00 KST → 이번 주 보상 청구 기록·일일 출석 기록 모두 신규 주로 초기화

### 3.2 4일차 실패 UX (v2 대비 핵심 개선)

v2는 "연속 4일" 모델 → 3일차에 끊기면 전부 리셋 = 심리적 손실. v3는 **끊김 개념 제거**:

| 상황 | UX 처리 |
|---|---|
| 월화수 출석 → 목요일 놓침 | "이번 주 3일 출석 · 4일까지 1일 남았어요" · 금토일 중 하루만 더 찍으면 4일 달성 |
| 월화수목 출석 → 1운 지급 완료 | "4일 출석 보상 받았어요 · 주말까지 3일 더 출석하면 2운" · 목표 바꿔 보여줌 |
| 월~금 중 아무 날도 놓침 · 토·일 2일 찍음 | "이번 주 2일 출석 · 다음 주 월요일부터 새로운 한 주" · 패배감 없음 |
| 월~일 7일 모두 찍음 | 1운 + 2운 둘 다 순차 지급 (일요일에 2운 모달 축하) |

### 3.3 주간 진행도 UI 컴포넌트

```
요일 칸 (7개 · 좌→우):
  - 과거 날짜 + 출석 O → ● (브랜드 골드 #B8965A 채움)
  - 과거 날짜 + 출석 X → ○ (회색 #D0C9BD 빈 원)
  - 오늘 날짜 + 미출석 → ◉ (골드 테두리 + 내부 빈 원 + 부드러운 펄스)
  - 오늘 날짜 + 출석 완료 → ● (채움 + 오늘 표식 얇은 밑줄)
  - 미래 날짜 → ○ (회색 빈 원)

프로그레스 바:
  - 길이 7칸 중 이번 주 출석 일수 비율로 채움
  - 색: #B8965A gradient (linear 0deg)
  - 4일차 마커 · 7일차 마커에 얇은 세로선 + 미니 라벨

마일스톤 리스트:
  - 체크마크 SVG (기 수령 ✓) · 빈 원 SVG (미수령)
  - 이번 주 달성 완료 항목은 “받음” 뱃지 (골드 배경 · 화이트 글씨 · 미니 라운드)
```

### 3.4 보상 지급 트리거

- **즉시 지급** (이벤트 탭을 닫고 있어도):
  - 콘텐츠 완료 시 CF `onContentCompleted` 실행 → attendance doc upsert → 이번 주 출석 일수 집계 → 마일스톤 신규 도달 시 `un` balance +1 or +2 + claim doc insert
  - `rewardClaims` 문서에 `cycle: YYYY-Wnn` + `milestone: 'week4'|'week7'` + `idempotencyKey` 저장 → 더블 클레임 방지
- **UI 반영**:
  - 유저가 이벤트 탭 다시 열 때 지급 연출(2티어) 미재생 여부 확인 플래그 `seenAt` 사용
  - 결과 페이지 이탈 후 이벤트 탭 진입 시 → `pendingReveals[]` 조회 → Tier A/B 연출 실행
- **푸시 알림** (v3에서는 필수 기능 아님 · D+30 이후):
  - 수요일 저녁까지 이번 주 0일 출석 → "이번 주 출석 1일만 해도 4일 목표의 시작이에요"
  - 토요일 오후 이번 주 3일 출석 → "하루만 더 출석하면 1운"

### 3.5 어뷰징 방어

- 같은 유저가 같은 날 여러 콘텐츠 소비 시 → **하루 1회만 출석 인정** (`attendance/{YYYY-MM-DD}` 문서 존재 여부로 판별)
- idempotencyKey = `uid_${uid}_week_${weekKey}_milestone_${milestone}` → Firestore transaction으로 2중 지급 방지
- dateKey는 **서버 타임스탬프 → KST 변환**으로 생성 (클라 시계 조작 방지)
- 보관함 삭제·계정 삭제·재가입 시 이번 주 진행도는 소실 → 재가입 어뷰징 무의미

## §4. 공유하기 — 단일 버튼 + 앱인토스 위임

### 4.1 로직 변경

v2는 카톡·X·인스타 3장의 카드를 노출하고 각 플랫폼 버튼이 개별 공유 리워드 호출을 트리거. v3는:

1. **단일 버튼 하나**: "친구에게 공유하기 (0/3)"
2. 버튼 탭 → 앱인토스 `ShareReward.open({ rewardId: 'a56725a6-...'})` 호출
3. 토스 앱이 자체 공유리워드 페이지로 전환 — 플랫폼 선택(카톡/X/인스타/링크복사)은 토스가 담당
4. 공유 발화 완료 시 토스가 리워드 콜백 전달 → CF `onShareEventReceived` 수신 → `un` +1 + claim 기록

### 4.2 UX 스펙

- 일 상한: **1일 3회 · 1회당 1운**
- 버튼 라벨: `친구에게 공유하기 (0/3)` · `친구에게 공유하기 (1/3)` · ... · `친구에게 공유하기 (3/3)`
- 3회 소진 시 버튼: 라벨 `오늘은 3회 모두 받았어요` · 비활성 스타일 (#D0C9BD 배경 · #8A7F6E 글자) · 탭 비활성
- 매일 00:00 KST 카운트 리셋
- 보조 텍스트: `오늘 남은 공유: N회 · 1회당 1운`

### 4.3 보상 지급 트리거

- 공유 리워드 콜백 수신 즉시 `un` +1 (모달 연출 없음 — 토스트만)
- 토스트: "공유해 주셔서 감사합니다. 운 1을 지급했어요." (1초)
- 연출 이유: 공유는 반복 행위 → 강한 모달은 피로도. 4일/7일 마일스톤만 모달.

### 4.4 어뷰징 방어

- 공유 리워드 API ID `a56725a6-4c52-40e5-b68b-2f752caf0a94` 고정 → 앱인토스 콘솔에서 일 3회 상한 정책 설정
- Firestore CF에서 동일 claim이 5분 내 중복 시 무시 (idempotencyKey)
- 자기 자신에게 공유(예: 자기 카톡으로 보내기) 방어는 앱인토스 측에서는 "수신자 체크" 미지원 → 현재 수단 없음. D+30 이후 완료율 모니터링해 규모 감당 안 되면 상한 2회로 낮춤.

## §5. 당첨 연출 — 2티어 (v2 3티어 대비 단순화)

### 5.1 Tier A — 1운 수령 (공유 1회당 · 주간 4일 보상)

- **형태**: 하단 토스트
- **지속**: 1.2초 (페이드인 0.15s + 유지 0.8s + 페이드아웃 0.25s)
- **요소**: 왼쪽에 작은 원형 SVG (브랜드 골드 체크마크) + "운 1을 받았습니다."
- **색**: 배경 #1F1B16 95% opacity + 글자 #F8F5EE + SVG 골드 #B8965A
- **위치**: 탭바 바로 위 (safe-area + 12px)
- **동시 노출 방지**: 기존 토스트가 있으면 큐에 쌓아 순차 노출

### 5.2 Tier B — 2운 수령 (주간 7일 보상)

- **형태**: 중앙 모달 (탭 바깥 닫기 가능)
- **지속**: 유저 명시 닫기 or 4초 후 자동 닫기
- **요소**:
  - 상단: **네잎클로버 SVG** (약 80x80px · 골드 스트로크 + 녹색 채움 ≠ 이모지)
  - 중앙: 한자 카드 `天乙貴人` (천을귀인 · Noto Serif KR + 골드 외곽선)
  - 본문: "이번 주 끝까지 달려주셨네요. 운 2를 드립니다."
  - CTA: `확인` (가볍게 닫힘)
- **색**: 모달 배경 #F8F5EE · 골드 포인트 #B8965A · 한자 #2F2A23
- **연출**: 클로버 0.3s scale in(from 0.7 to 1, cubic-bezier) + 한자카드 0.4s fade in + 골드 파티클 얇은 가루 12개 (감각만 · 과하지 않음)
- **사주 브랜드 내러티브**: "사주가 좋아서 길조가 비쳤다"는 톤 — 로또 당첨 X · 사주에서 귀인이 들어왔다 O

## §6. 운 경제 시뮬 (v3 기준)

### 6.1 월 단일 유저 기대값

| 유형 | 출석 | 공유 | 월 운 | 월 원화 |
|---|---|---|---|---|
| 헤비 (매주 7일 + 공유 3회×주6일 가정) | 12운 (4주 × 3운) | 72운 (6일 × 3운 × 4주) | **84운** | 42,000원 |
| 미디엄 (주 4일 달성 + 공유 3회×주3일) | 4운 | 36운 | 40운 | 20,000원 |
| 라이트 (주 1~2일 출석 · 공유 거의 안 함) | 0운 | 4운 | 4운 | 2,000원 |

- 공유가 절대 비중 ≒ 85~90% → 1일 3회 상한이 핵심
- v2 대비 변화: 7일차 5% 확률 100원 토스포인트 제거 → 월 20원/유저 손실 방지 → 운영비 감소
- 토스포인트는 UAC 프로모션(신규 설치 1회 1,000원 고정)으로 완전 분리 (§11 참조)

### 6.2 손익 감각

- 월 헤비 유저 42,000원 = 5000원 프리미엄 8.4회분 → 유저 제한 없음 (공유 상한이 1일 3회이므로 자연 한계)
- 프리미엄 전환 시 1명 = 5,000원 → 운 42,000원은 **LTV 확장용**이지 CAC 아님
- 리텐션 도구 1순위 → 유료 결제 유도는 5000원 프리미엄 · 500원 단건에서 나오면 됨

## §8. Firestore 스키마 + Cloud Functions

### 8.1 스키마

```
/users/{uid}/attendance/{YYYY-MM-DD}
  dateKey:     "2026-04-21"     (KST 기준)
  weekKey:     "2026-W17"       (ISO week)
  source:      "content_view"   (or "content_complete" · 기타)
  contentId:   "daily_fortune_2026-04-21"
  createdAt:   serverTimestamp

/users/{uid}/rewardClaims/{claimId}
  type:        "attendance_week4" | "attendance_week7" | "share"
  cycle:       "2026-W17"        (주간 마일스톤) or "2026-04-21"(공유 일일)
  amount:      1 | 2              (운)
  rewardKind:  "un"               (v3: tossPoint 제거)
  idempotencyKey: "uid_week4_2026-W17" · "uid_share_2026-04-21_1"
  seenAt:      serverTimestamp    (UI에서 연출 재생되면 기록)
  createdAt:   serverTimestamp

/users/{uid}/un
  balance:     number
  updatedAt:   serverTimestamp
```

### 8.2 Cloud Functions 4종

| 함수 | 트리거 | 처리 |
|---|---|---|
| `onContentCompleted` | HTTPS (클라에서 결과 페이지 렌더 시 호출) | attendance doc upsert → 주간 집계 → week4/week7 도달 시 `claimAttendanceMilestone` 내부 호출 |
| `claimAttendanceMilestone` | 내부 | Firestore transaction · `un` +N · rewardClaims insert · idempotencyKey 체크 |
| `onShareEventReceived` | 앱인토스 콜백 webhook | 일 3회 상한 체크 · `un` +1 · rewardClaims insert |
| ~~`grantTossPoint`~~ | **v3에서 삭제** | UAC 프로모션으로 분리 — 앱 코드 경로 없음 |

### 8.3 보안 규칙 (간략)

- `rewardClaims` 쓰기는 CF 서비스 계정만
- 클라는 `un.balance` 읽기만 가능 · 쓰기 X
- `attendance` 쓰기는 CF만 (클라에서 직접 조작 방지)

## §11. UAC 프로모션 — 토스포인트 신규 유입 경로 (§ 이벤트 탭과 분리)

### 11.1 목적

- v2에서 이벤트 탭 7일차 5%로 토스포인트 100원을 지급하려 했으나 **정책 위반** → 이벤트 탭에서 제거
- 대신 앱인토스 관리자 콘솔의 UAC(User Acquisition Campaign) 프로모션으로 **신규 설치 1회 1,000원 고정** 지급

### 11.2 등록 내용 (준기가 콘솔에서 직접 등록)

| 필드 | 값 |
|---|---|
| 미션 이름 | `서비스 이용하기` |
| 지급 방식 | 고정 금액 |
| 지급 금액 | 1,000원 |
| 이동 URL (딥링크) | `intoss://saju-500` (확정 필요 · 앱인토스 미니앱 URL 스킴) |
| 전체 예산 | 3,000,000원 (현재 비즈월렛 잔액 237,947원 · 추가 충전 필요 여부 판단) |
| 심사 조건 | 랜덤 보상 없음 · 실사용 증명 가능 (사주 1회 분석 = 실사용 증명) · 미션 이름에 "가입" 단어 X |

### 11.3 주의사항 (프로모션 가이드 기반 · 하드 체크)

- "랜덤 · 확률 · 뽑기" 용어 절대 미사용 → 심사 거절 사유
- 미션 이름에 "가입"·"signup" 금지 → 앱인토스는 가입 개념 없음
- 지급 금액이 예산 대비 과도하면 심사 반려 → 1,000원은 평균대
- 미션 조건 설명은 실행 행위 기반 ("서비스 이용하기" = 사주 분석 1회 완료)

### 11.4 코드 경로 (분리 원칙)

- 사주500 앱 코드베이스에서 UAC 프로모션 처리 없음
- 유저가 프로모션 링크로 진입 → 앱 내 일반 플로우 진행 → 앱인토스가 뒤에서 1회 완료 체크 → 토스포인트 지급
- `grantPromotionReward` SDK 미호출 (서버리스)
