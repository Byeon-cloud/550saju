## 0. 전체 원칙 (회귀 절대 금지)

### 0.1 디자인 5원칙
1. **검정·골드·크림 SSOT** — 모든 페이지의 base. 주제색은 **액센트로만** (Hero stripe 3px / 한자 워터마크 opacity 0.10 / chip soft bg 14%)
2. **한자 = 상징** — 본문엔 풀이 함께 ("도화(桃花, 인연 끌어오는 살)"), 단독 노출 금지
3. **카드 단위 정보 캡슐화** — 흰 surface + gold-line border, sec-num + sec-title + chevron 헤더
4. **단정형 톤** — "~할 수 있어요" / "~될 가능성이 있어요" 금지 → "~합니다" / "~됩니다" / "~하세요"
5. **자동 강조 위계 3-tier** — `<strong>` 골드 형광펜 / `<u>` 골드 밑줄 / `<b>` 검정 한자

### 0.2 회귀 방지 (mockup HTML 작성 시)
- 자유 hex 금지 — CSS 변수 (`--c-paper`, `--c-gold`, `--c-topic-accent`) 만 사용
- 머스타드 #B8941F · 구 골드 #C9A96E · 구 비비드 #D4A843 0건
- 이모지 0건 (한자/SVG/컬러칩만 허용)
- text-[10px] 미만 금지 (60대 가독)
- mockup 의 placeholder 는 `{{변수명}}` 패턴 (Mustache 식)
- AI 자유서술 금지 — schema 안의 모든 필드는 명확한 의미·길이·톤 mandate 가짐

### 0.3 카피라이팅 5계명
1. **단정형 강제** — "~할 수 있어요" ❌ / "~합니다" ✅
2. **사주 호명 mandatory** — 1회+/섹션 (예: "병화(丙火) 일간이 신사(辛巳) 일진을 만나…")
3. **"결" 남발 금지** — 한 섹션 3회+ 금지. 대안: 흐름·리듬·패턴·특징·성향·스타일·구간
4. **출처 mention 0건** — 자평진전·적천수·궁통보감·홍성민 등 본문에 절대 등장 X (학술 출처는 footer 별도)
5. **임팩트 단어는 적절히 OK** — DNA·패턴·타입·전환점·함정 OK / 죽는다·망한다·재앙 X

## 4. 카피라이팅 가이드 (강제 룰)

### 4.1 톤 — "가까운 사람이 곁에서 풀어주는 느낌"
- 무속인 톤 ❌ "조심하셔야 합니다" "신령님이 그렇게 말씀하셨어요"
- AI 톤 ❌ "당신의 사주는 다음과 같은 특징이 있습니다"
- 사주500 톤 ✅ "병화 일간 + 자수 일지 만남이 만드는 결은…"

### 4.2 단정형 5단계
| Bad (면피체) | Good (단정형) |
|---|---|
| ~할 수 있어요 | ~합니다 |
| ~될 가능성이 있어요 | ~됩니다 |
| ~할지도 몰라요 | ~합니다 / 안 합니다 |
| 일반적으로 ~합니다 | (사주 호명 후) ~합니다 |
| ~한 경향이 있어요 | ~한 사람이에요 / ~성향입니다 |

### 4.3 사주 호명 패턴 (mandatory 1회+/섹션)
- **일간 호명**: "병화 일간이 신사 일진을 만나서…"
- **십성 호명**: "재성 ×3 + 정관 ×1 분포가…"
- **신살 호명**: "일지 자수의 도화가…"
- **합·충 호명**: "월지 신금과 인목의 충돌이…"
- **대운 호명**: "30대 갑인(甲寅) 대운이 들어오면…"

### 4.4 한자 등장 룰 (강화 — 2026-05-07)

> **사용자 결단**: "한자만 사용 못하게 해야됨. 유저 입장에서 읽기 쉽지 않아."
> → 본문에 **한자 단독 등장 절대 금지**. 무조건 한국어 발음 또는 의미 동반.

#### 패턴 SSOT (모든 mockup·prompt 강제)

**❌ 절대 금지 (한자 단독)**:
- `戊癸합` / `寅申 충` / `寅午 반합` / `巳申 형`
- `戊癸合火` / `寅午半合火` / `巳申刑`
- `寅 도화` / `도화 寅` / `子 일지`

**✅ 허용 (한국어 우선 + 한자 보조)**:
- `무계(戊癸) 합` / `인신(寅申) 충` / `인오(寅午) 반합` / `사신(巳申) 형`
- `무계 합(戊癸合, 화 기운 결합)` — 첫 등장에 의미까지
- `인(寅) 도화` / `도화 인(寅)` / `자(子) 일지`

#### 우선순위 (가장 친근한 순)
1. **한국어 발음(한자) + 의미** — 가장 친절: "병화(丙火, 밝고 활달한 기운)"
2. **한국어 발음(한자)** — 기본: "무계(戊癸) 합"
3. **의미만** — 한자 생략 가능: "두 천간이 만나는 결합"
4. **한자(한국어 발음)** — 학술 톤: "戊癸合(무계합)" — 결과 페이지 footer 만 OK
5. **한자 단독** — ❌ 본문 절대 금지

#### 1 섹션 등장 빈도
- 같은 한자가 한 섹션에 4번+ 반복되면 후속은 한국어로 ("무계 합" → "이 합")
- 한자 등장 자체는 4-6회 적정, 8회+ 과다

#### prompt mandate (AI 강제 룰)
```
[한자 등장 ABSOLUTE]
- 본문에 한자 단독 등장 절대 금지
- 모든 한자는 한국어 발음 동반 ("무계(戊癸)" 패턴)
- 첫 등장 시 의미까지 권장 ("병화(丙火, 밝고 활달한 기운)")
- 한자 4글자 이상 (戊癸合火 등) 은 의미 풀이 mandatory
- 같은 한자 5번+ 반복 시 후속은 한국어로 대체
```

이 룰은 **모든 주제 mockup + AI prompt** 에 강제 적용.

### 4.5 강조 위계 사용 빈도
- `<strong>` (골드 형광펜): 한 문단 1-2회 — **일상 결론** 어구 ("적극적인 만남이 효율적입니다")
- `<u>` (골드 밑줄): 한 문단 0-2회 — **시기·숫자·색·방위·시간대** ("동남쪽", "5월 14-17일", "오후 2~5시")
- `<b>` (검정 한자): 한자 첫 등장에만

### 4.6 금지어 사전
| 금지 | 이유 | 대체 |
|---|---|---|
| 죽는다 / 망한다 / 재앙 | 자극적·점집 톤 | 큰 변화·주의·전환점·함정 |
| 신령님·하늘이·운명이 | 무속 톤 | 사주가·일간이·재성이 |
| 자평진전·적천수·궁통보감·박청화 | 출처 mention 0건 | 그냥 단정형으로 ("이런 사주는 ~합니다") |
| AI · 인공지능 · 머신러닝 | self-reference | (생략 또는 "사주500이") |

### 4.7 "결" 남발 제한
- 한 섹션 3회+ 등장 금지
- 대안 사전: 흐름 / 리듬 / 패턴 / 특징 / 성향 / 스타일 / 구간 / 결정점 / 색깔
- 예: "이 사주의 연애 결은 ~결로 풀려서 ~결을 만들어요" → "이 사주의 연애 흐름은 ~패턴으로 풀려서 ~성향을 만들어요"

## 5. 주제별 §01 narrative 1000자 구성 (공통 골격)

각 주제 §01 본문 (paragraph 1-3) 의 권장 골격:

```
paragraph1 (300-350자, 사주 진단)
  · 일간 호명 + 일지/월지 핵심 글자 등장
  · 주제 핵심 십성 카운트 + 강도 평가
  · "이 사주는 ~한 패턴/성향" 1차 단정
  · <strong> 1-2회 + <b> 한자 풀이 1-2회

paragraph2 (350-400자, 동적 풀이)
  · 4축 십성 균형 분석 (메인 강·약 + 상생/저항/보조)
  · 주제 specific 시기 또는 만남 패턴 1-2개 인용
  · "강점은 ~ / 함정은 ~" 균형 진단
  · <strong> 2-3회 + <u> 3-4회 (시기/숫자/색)

paragraph3 (300-350자, 행동/시기 안내)
  · 가장 가까운 시기 (이번 분기 또는 이번 달) 행동 권장
  · 사주 호명 마무리 ("병화 일간이라 ~")
  · <strong> 1-2회 (결론 어구) + <u> 2-3회
```

## 6. AI prompt schema (1:1 mapping)

> `functions/src/ai/promptsV3.ts` 에 추가될 prompt 의 schema mandate 섹션. mockup placeholder 와 1:1.

```typescript
interface TopicResultV2 {
  topicId: TopicKey;

  // §01
  title: string;                    // 20자 — "{topicLabel} 핵심 결" 고정 권장
  oneLineConclusion: string;        // 50-80자 — <strong> 1회, 사주 호명 0-1회
  conclusionSajuRef: string;        // 30-50자 — "병화 일간 + 자수 일지 + 인목 도화"
  narrative: string;                // \n\n 으로 3 paragraph 구분, 합 1000자

  // §02
  sajuHighlights: string[];         // 4-6 chip — "재성 ×3 (정재 2 + 편재 1)"

  // §03
  topicSipsung: {
    main:        { name: string; count: number; level: '강함'|'보통'|'약함'|'부족' };
    secondary:   { name: string; count: number; level: '강함'|'보통'|'약함'|'부족' };
    resistance:  { name: string; count: number; level: '강함'|'보통'|'약함'|'부족' };
    aux:         { name: string; count: number; level: '강함'|'보통'|'약함'|'부족' };
    interpretation: string;         // 200-300자, 4축 종합
  };

  // §04
  timeline: {
    type: '12months' | '3stage' | 'semester';
    items: Array<{
      slot: string;                 // "1월" / "1단계 시작" / "1학기"
      score: number;                // 0-100 정수, 5의 배수 박멸 (자연수)
      message: string;              // 30-60자 (3stage/semester 한정)
    }>;
    bestSlots?: string[];           // 강조 slot ["5월", "9월"]
  };

  // §05
  meet: {
    boost: { who: string; why: string };  // who: 30-50자, why: 80-120자
    clash: { who: string; why: string };
    calm:  { who: string; why: string };
  };

  // §06
  doList:   Array<{ title: string; when?: string; detail: string }>;  // 4-6
  dontList: Array<{ title: string; when?: string; detail: string }>;  // 4-6

  // §07
  lucky: {
    color:     { value: string; reason: string };
    direction: { value: string; reason: string };
    hour:      { value: string; reason: string };
    number:    { value: string; reason: string };
    word:      { value: string; reason: string };
    food:      { value: string; reason: string };
  };

  // §08
```

### 6.1 prompt 강제 룰 (system + user 양쪽)

```
[ABSOLUTE RULES]
1. 단정형만 — "~할 수 있어요" 류 금지, "~합니다" / "~됩니다" / "~하세요"
2. 사주 호명 — 모든 섹션에 1회+ ("병화 일간", "재성 ×3", "일지 자수" 등 8글자/십성/신살 직접 인용)
3. 출처 mention 0건 — 자평진전·적천수·박청화 등 본문 등장 절대 금지
4. "결" 한 섹션 3회+ 금지
5. 이모지 0건
6. 한자 첫 등장 시 풀이 함께 ("도화(桃花, 인연 끌어오는 살)")
7. 점수는 자연수 (5의 배수 박멸)
8. <strong>/<u>/<b> 정확히 적용 — strong=일상 결론, u=시기·숫자·색·방위, b=한자
9. 사용자 이름 placeholder 보일러플레이트 금지 — "이혜지·준기·변준기" 등 prompt 안에 사람 이름 금지
10. AI self-reference 금지 — "AI가" / "분석해드릴게요" 등 금지

[DYNAMIC PERSONALIZATION MANDATE]
- 같은 사주 8글자가 들어오면 매번 같은 결과 (deterministic, temperature 0.1)
- 다른 사주 8글자가 들어오면 매번 다른 결과 (사주 specific 호명 강제)
- 십성 카운트는 사주 8글자 + 지장간 (월지 본기·중기·여기) 합산
- 강함(3+) / 보통(2) / 약함(1) / 부족(0) 4단계 분류
- timeline.score 는 명리학 기반 — 월지 12지지 vs 사주 4기둥 합·충·형·해·파 + 주제 핵심 십성 들어오는지

[TOPIC BOUNDARY MANDATE]
- {{topicLabel}} 만 풀이 — 인접 주제 (연애운에서 결혼·재회·재물 등) 한 줄도 언급 금지
- 같은 사주 → 10주제 결과 모순 절대 금지 (예: 연애에서 "관계 안정", 결혼에서 "결혼 불리" 같이 모순 X)
```
