## 2. 비로그인 진입 처리

### 2-1. 흐름
1. TabBar에서 "내정보" 탭 → `/my` 진입 시도
2. 로그인 상태 체크
3. 비로그인 → 즉시 **로그인 모달** (전체화면 모달)
4. 모달 닫기 = 직전 탭으로 복귀 (`/my` 진입 무효)
5. 로그인 성공 → `/my` 정상 렌더

### 2-2. 로그인 모달
- 풀스크린 시트 (radius-top 24, 높이 80vh)
- 배경 `paper`, 닫기 버튼 우상단 (X 아이콘 24)
- 헤더: H1 "내 사주를 안전하게 보관해요"
- 서브: Body 16/500 "로그인하면 운 잔액·풀이 기록·결제 내역을 안전하게 관리할 수 있어요"
- 그림: 64×64 신살 심볼 일러스트 (잠금/별)
- CTA 영역 (하단 stack):
  - **카카오 계속하기** (Primary, 카카오 옐로우 #FEE500, ink 텍스트, 높이 52)
  - **네이버 계속하기** (Secondary, #03C75A, white 텍스트, 높이 52)
  - **Apple 계속하기** (Secondary, ink, white 텍스트, 높이 52) — iOS 정책 대응
- 하단 Caption: "로그인하면 [이용약관], [개인정보처리방침]에 동의한 것으로 간주합니다." (밑줄 링크 2개)

### 2-3. 비로그인이어도 가능한 동선 (이 페이지 외)
- 홈·꿈해몽·오늘의 운세·사주분석·보관함 일부 = 비로그인 OK
- 운 **사용**(결제 후 풀이) = 비로그인 OK (공유 리워드로 받은 운으로 가능)
- 운 **구매** = 로그인 필수 (`/charge` 결제 모듈)

## 6. /billing — 결제/사용 내역

### 6-1. 골격
- TopBar (← 닫기 + 제목 "결제·사용 내역")
- 탭 전환 (Pill 2개): "충전" / "사용"
- 각 탭 = 시간 역순 리스트

### 6-2. 충전 탭 항목
- 좌: 날짜·시각 (YYYY.MM.DD HH:mm)
- 중: 결제 수단 + 운 수량 ("토스페이 · +10운")  ← 앱인토스 빌드 기준. 웹앱은 결제 수단 문자열 동적
- 우: 결제액 (Caption 12/500 `gray-500`, "5,000원")
- 보너스 운 적립은 별도 행으로 표기 ("공유 리워드 · +1운")

### 6-3. 사용 탭 항목
- 좌: 날짜·시각
- 중: 콘텐츠명 ("프리미엄 종합 사주 분석 · 변준기")
- 우: 차감 운 (Caption "−10운", `danger` 컬러)
- 클릭 시 해당 결과 페이지로 이동

### 6-4. 빈 상태
- "아직 충전 내역이 없어요" / "아직 사용 내역이 없어요"
- 가운데 심볼 + Body-sm + Ghost 버튼 ("운 충전하러 가기" / "사주 분석 시작하기")

## 11. 접근성

- 메뉴 카드 = `<button>` 또는 `<a>`, `aria-label` 명시
- 잔액 뱃지 = `aria-live="polite"` (변경 시 스크린 리더 통지)
- 로그인 모달 = `role="dialog"` + `aria-modal="true"` + focus trap
- 카카오·네이버·Apple 버튼 = 각 플랫폼 공식 가이드 색·로고 준수

## 12. 데이터 구조 (PC 참고)

```ts
type MyPageProps = {
  user: {
    id: string;
    nickname?: string;
    provider: 'kakao' | 'naver' | 'apple';
    joinedAt: string;
  } | null;             // null = 비로그인
  balance: {
    un: number;
    chatTickets: number;
    todayShareCount: number;     // 0~3
  };
  build: 'appintos' | 'webapp';
};
```

- `build === 'appintos'`이면 로그아웃·회원탈퇴 메뉴 자동 숨김
- `build === 'webapp'`은 별도 컴포넌트 분기 (`MyPageWebapp.tsx`)에서 처리
