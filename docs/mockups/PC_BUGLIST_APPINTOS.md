## 버그 1 — 홈 "주제별 심층 500원 풀이" 라우트 오류

### 증상
- 홈에서 "주제별 심층 500원 풀이" 카드(또는 버튼) 클릭 시 잘못된 곳으로 이동

### 진단 보고 요청
1. 홈페이지에서 "주제별" 관련 CTA JSX 블록 전부 grep → 파일:라인 목록
2. 각 CTA의 `to`·`href`·`onClick` 값 그대로 출력
3. 해당 path가 `src/App.tsx` Routes에 등록됐는지 확인
4. 등록됐다면 실제 이동하는 페이지가 맞는지 (`/topic` vs `/topic/:id` vs `/input?topic=...` 등)

### 수정 가이드
- 주제별 심층분석 = `/topic` 경로로 정리 (섹션 4.5 같은 체계)
- 만약 `/topic`이 리스트고 `/topic/:id`가 상세면 홈 CTA는 리스트로 가야 맞음
- 라우트 자체가 없으면 추가하지 말고 **Cowork에 보고** — 준기 결정 받음

## 버그 2 — 보관함 사주팔자 정보 삭제 불가

### 증상
- 보관함 화면에 사주팔자 정보(프로필) 카드 있는데 **삭제 버튼 없음**
- 사용자가 등록한 프로필 제거 방법 자체 부재

### 진단 보고 요청
1. 보관함 페이지 파일 경로 + 사주 프로필 렌더 JSX 블록 출력
2. 프로필 데이터 소스 (localStorage key 이름 + 구조)
3. 프로필 CRUD 중 D(delete) 함수가 코드상 존재하는지 grep
4. 만약 delete 함수는 있는데 UI만 없는 경우 → UI 추가 난이도 보고
5. delete 함수 자체가 없으면 → 추가 필요 범위 보고

### 수정 가이드 (준기 2026-04-20 Q5 결정 반영)
- **삭제 UX 두 방식 모두 지원:**
  1. **스와이프** — 프로필 카드를 좌→우(또는 우→좌) 스와이프 시 빨간 "삭제" 영역 노출
  2. **휴지통 아이콘** — 카드 우상단에 휴지통 아이콘 상시 노출, 탭 시 삭제 확인
- 삭제 확인 모달: "○○님의 사주 정보를 삭제할까요? 이용기록은 그대로 유지됩니다."
- **중요**: 이 프로필과 연결된 이용기록은 **삭제하지 않음** (버그 3 참고)
- 스와이프 라이브러리: react-swipeable-list 등 기존 프로젝트 의존성 확인 후 선택. 없으면 pure CSS transform + touch event로 자체 구현.

## 버그 3 — 이용기록 삭제 시 사주 정보가 자동 사라짐 (cascade delete)

### 증상
- 이용기록을 모두 지우면 연결된 사주팔자 정보까지 함께 사라짐
- 기대 동작: 이용기록 지워도 사주 정보는 그대로, 그 이름도 살아있어야

### 진단 보고 요청
1. 이용기록 삭제 함수 (이름·파일:라인·본문) 전문 출력
2. 함수 내부에서 사주 프로필(사주팔자 정보) 참조·수정·삭제 로직이 있는지
3. 데이터 모델 — 이용기록과 프로필이 같은 localStorage key에 섞여있는지 분리돼있는지
4. 만약 섞여있다면 → 분리 리팩터링 범위 보고

### 수정 가이드
- **데이터 분리 원칙 (준기 명시):**
  - 사주팔자 정보 = 별도 저장소 key (예: `saju500.profiles`)
  - 이용기록 = 별도 저장소 key (예: `saju500.history`)
  - 이용기록 항목은 프로필 ID를 FK처럼 참조만. 삭제 시 참조만 끊고 프로필 본체는 유지.
- cascade delete 로직이 있으면 제거
- 이용기록 일괄 삭제 후 "○○님의 풀이 N건" 표기는 0으로 갱신하되 ○○님 카드 자체는 유지

## 버그 4 — 데이터 삭제 후에도 이전 입력 잔존 (2곳)

### 증상
- 보관함에서 이용기록 모두 삭제 → "첫 사주 입력하기" 클릭 → 이전 입력 데이터가 그대로 나타남
- 보관함에서 모든 사주 데이터 지운 상태인데 사주분석(/input) 진입 시에도 이전 데이터 잔존

### 진단 보고 요청
1. `/input` 페이지 진입 시 초기값 소스 grep
2. localStorage migration 로직 존재 여부 (예전 키에서 자동으로 복원하는 코드?)
3. React 상태 초기값이 localStorage에서 바로 끌어오는지, 세션 중 캐시하는지
4. "모두 삭제" 함수가 실제로 모든 관련 key를 다 지우는지, 누락된 key 있는지

### 수정 가이드
- 모든 관련 localStorage key 전수 조사 → 삭제 함수에 누락 key 추가
- 페이지 진입 시 초기값은 localStorage를 **실시간**으로 읽도록 (세션 캐시 제거)
- migration 로직이 자동 복원 중이면 제거 또는 조건부 실행
