# 사주500 — 프리미엄 PDF 서버 엔드포인트 스펙

> 대상: 5000원(10운) 프리미엄 결과를 A4 PDF로 다운로드
> 아키텍처: Cloud Functions + Puppeteer + Firebase Storage signed URL
> 작성: 2026-04-20
> PC 구현용 설계서

---

## 0. 배경 · 왜 서버 PDF인가

**결정 메모**: `project_premium_pdf_plan.md` — "5000원 결과 PDF는 서버 Puppeteer + Storage 다운로드. 이미지 캡쳐는 길이 때문에 X."

**이유**:
- 프리미엄 결과는 10섹션·1만 4천 자 분량. 화면 캡쳐 방식은 길이·해상도 제약으로 불가.
- 클라이언트 HTML→PDF(`jsPDF`, `html2canvas`)는 SVG·웹폰트·그라데이션에서 품질 저하 심함.
- Puppeteer(Chromium 헤드리스)가 웹폰트·SVG·CSS 3D까지 원본 그대로 렌더. 프린트 품질.

**부수 효과**:
- PDF 원본을 Storage에 보존 → 유저가 "보관함 > 프리미엄 리포트"에서 재다운 가능
- 공유 링크는 별도 — PDF를 외부 배포하는 기능은 초기엔 X (법적·가격정책 이슈)

## 1. 아키텍처

```
[클라이언트 /premium/result/:reportId 페이지]
    ↓ POST /api/premium/pdf  { reportId }
[Cloud Functions: generatePremiumPdf]
    ↓ Firestore에서 reportId → HTML 템플릿 데이터 로드
    ↓ Puppeteer 헤드리스 Chromium 실행
    ↓ HTML 렌더 → A4 print PDF 생성
    ↓ Firebase Storage 업로드 (유저별 경로)
    ↓ Signed URL 발급 (7일 유효)
[응답: { url, expiresAt, sizeBytes }]
    ↓ 클라이언트가 url로 PDF 다운로드 또는 브라우저에서 열기
```

## 2. Endpoint 스펙

### 2-1. 엔드포인트

```
POST /api/premium/pdf
Host: asia-northeast3-saju500.cloudfunctions.net
Auth: Firebase ID token (Authorization: Bearer <token>)
Content-Type: application/json
```

### 2-2. Request Body

```ts
type PremiumPdfRequest = {
  reportId: string;         // Firestore reports/{reportId}
  regenerate?: boolean;     // 기본 false. true면 기존 PDF 덮어쓰기
};
```

### 2-3. Response

```ts
type PremiumPdfResponse = {
  url: string;              // Signed URL (HTTPS)
  expiresAt: string;        // ISO 8601, 업로드 시각 + 7일
  sizeBytes: number;        // 생성된 PDF 크기
  cached: boolean;          // 기존 PDF 재활용 여부
  reportId: string;
};
```

### 2-4. 에러 응답

| 코드 | 의미 | 조치 |
|---|---|---|
| 401 | 인증 실패 | 클라이언트에서 재로그인 |
| 403 | 타인의 리포트 접근 | UI: "본인 리포트만 다운로드 가능" 토스트 |
| 404 | reportId 존재하지 않음 | "리포트를 찾을 수 없어요" |
| 409 | 아직 생성 중 (동시 요청 잠금) | 5초 후 재시도 |
| 429 | Rate limit (유저당 분당 3회 초과) | "잠시 후 다시 시도해주세요" |
| 500 | Puppeteer 실패 / Storage 실패 | "PDF 생성에 실패했어요. 다시 시도해주세요" + Sentry 로그 |
| 503 | 서버 부하 / Cold start 타임아웃 | 30초 후 자동 재시도 |

## 4. Puppeteer 렌더링

### 4-1. 인프라 선택

**권장**: Cloud Functions 2nd gen + Memory 2GB + Timeout 120초

이유:
- Chromium 헤드리스는 콜드 스타트 5~10초 + 렌더 10~30초 필요 → 총 40초 이상도 가능
- 2nd gen은 기본 timeout 60초지만 540초까지 확장 가능
- Memory 2GB는 Chromium 안정 최소치 (1GB는 OOM 빈발)

**대안 1**: Cloud Run — 상시 컨테이너 유지로 cold start 제거. 월 트래픽 많으면 유리하나 초기엔 오버킬.
**대안 2**: Vercel serverless — 512MB·10초 제한이라 불가.

### 4-2. Puppeteer 의존성

```json
{
  "dependencies": {
    "puppeteer": "^22.x",
    "@sparticuz/chromium": "^123.x"
  }
}
```

- `@sparticuz/chromium`: Cloud Functions 크기 제한(250MB) 맞게 최적화된 Chromium 바이너리
- 전체 puppeteer는 too big (Chromium 포함). `puppeteer-core` + `@sparticuz/chromium` 조합 권장

### 4-3. 렌더 코드 골격 (TypeScript)

```ts
import { onRequest } from 'firebase-functions/v2/https';
import puppeteer from 'puppeteer-core';
import chromium from '@sparticuz/chromium';
import { getFirestore } from 'firebase-admin/firestore';
import { getStorage } from 'firebase-admin/storage';
import { auth } from 'firebase-admin';

export const generatePremiumPdf = onRequest({
  memory: '2GiB',
  timeoutSeconds: 120,
  region: 'asia-northeast3',
  cors: true,
}, async (req, res) => {
  // 1. Auth
  const token = req.headers.authorization?.replace('Bearer ', '');
  if (!token) return res.status(401).json({ error: 'no-auth' });
  const decoded = await auth().verifyIdToken(token);
  const userId = decoded.uid;

  // 2. Body
  const { reportId, regenerate = false } = req.body;
  if (!reportId) return res.status(400).json({ error: 'missing-reportId' });

  // 3. Firestore 조회
  const reportRef = getFirestore().doc(`reports/${reportId}`);
  const snap = await reportRef.get();
  if (!snap.exists) return res.status(404).json({ error: 'report-not-found' });
  const report = snap.data()!;
  if (report.userId !== userId) return res.status(403).json({ error: 'forbidden' });
  if (report.type !== 'premium') return res.status(400).json({ error: 'non-premium-report' });

  // 4. 캐시 확인
  if (!regenerate && report.pdf?.storagePath) {
    const url = await generateSignedUrl(report.pdf.storagePath);
    return res.json({ url, expiresAt: plus7Days(), sizeBytes: report.pdf.sizeBytes, cached: true, reportId });
  }

  // 5. 동시성 잠금 (Firestore tx 또는 Redis lock)
  const lockAcquired = await acquireLock(`pdf:${reportId}`, 90_000);
  if (!lockAcquired) return res.status(409).json({ error: 'in-progress' });

  try {
    // 6. HTML 렌더
    const html = renderPremiumReportHtml(report);

    // 7. Puppeteer
    const browser = await puppeteer.launch({
      args: chromium.args,
      executablePath: await chromium.executablePath(),
      headless: true,
      defaultViewport: { width: 794, height: 1123 }, // A4 @ 96dpi
    });
    const page = await browser.newPage();
    await page.setContent(html, { waitUntil: 'networkidle0', timeout: 60_000 });
    
    // 웹폰트 로드 대기 (Noto Serif KR)
    await page.evaluateHandle('document.fonts.ready');
    
    const pdfBuffer = await page.pdf({
      format: 'A4',
      printBackground: true,
      preferCSSPageSize: false,
      margin: { top: '20mm', right: '18mm', bottom: '20mm', left: '18mm' },
      displayHeaderFooter: true,
      headerTemplate: `<div style="font-size:9px;color:#7F6B4E;padding:0 18mm;width:100%;text-align:right;">
        사주500 · 프리미엄 리포트
      </div>`,
      footerTemplate: `<div style="font-size:9px;color:#7F6B4E;padding:0 18mm;width:100%;display:flex;justify-content:space-between;">
        <span>${report.userName || ''} · ${new Date().toLocaleDateString('ko-KR')}</span>
        <span>Page <span class="pageNumber"></span> / <span class="totalPages"></span></span>
      </div>`,
    });
    await browser.close();

    // 8. Storage 업로드
    const storagePath = `pdf/${userId}/${reportId}.pdf`;
    const file = getStorage().bucket().file(storagePath);
    await file.save(pdfBuffer, {
      contentType: 'application/pdf',
      metadata: { cacheControl: 'private, max-age=604800' },
    });

    // 9. Signed URL
    const [url] = await file.getSignedUrl({
      action: 'read',
      expires: Date.now() + 7 * 24 * 3600 * 1000,
    });

    // 10. Firestore 메타데이터 업데이트
    await reportRef.update({
      pdf: {
        storagePath,
        sizeBytes: pdfBuffer.byteLength,
        generatedAt: new Date(),
        contentHash: sha256(JSON.stringify(report.sections)),
      },
    });

    return res.json({
      url,
      expiresAt: new Date(Date.now() + 7 * 24 * 3600 * 1000).toISOString(),
      sizeBytes: pdfBuffer.byteLength,
      cached: false,
      reportId,
    });
  } catch (err) {
    console.error('PDF generation failed', err);
    Sentry?.captureException(err);
    return res.status(500).json({ error: 'render-failed' });
  } finally {
    await releaseLock(`pdf:${reportId}`);
  }
});
```

## 5. 성능·비용

### 5-1. 예상 실행 시간

- Cold start: 5~10초
- Warm start: 1~2초
- Puppeteer launch: 3~5초
- HTML 렌더 + font 로드: 3~8초
- PDF 변환: 5~15초 (10섹션 기준)
- Storage 업로드: 1~3초
- **합계 목표**: 콜드 20초, 웜 15초 이하

### 5-2. Cold start 완화

- `minInstances: 1` 설정 → warm 1개 상시 유지 (월 $15~20 추가 비용)
- 또는 UI에 로딩 스피너 + "PDF를 생성하고 있어요 (보통 15~20초)" 문구로 UX 완충 — `feedback_quality_over_speed.md` 방침과 일치

### 5-3. 비용 추정 (Cloud Functions 2nd gen, asia-northeast3)

- Memory 2GB · 20초 평균 = GB-s 40 = $0.0000105 × 40 × 10000건 = $4.2 / 10k 생성
- Storage: 500KB PDF × 10,000건 = 5GB × $0.026 = $0.13 / 월
- 에그레스: Signed URL 다운로드 트래픽 별도

**총 예상**: 월 10,000 PDF 기준 ≈ $5 미만. 유료 결제 5,000원 × 10,000건 = 5,000만 원 매출 대비 인프라 비용 0.01% 수준. 무시 가능.

### 5-4. 캐시 전략

- 기본은 "같은 리포트 = 같은 PDF" → Firestore `pdf.contentHash` 확인 후 재사용
- `regenerate: true` 플래그는 리포트 내용이 바뀌었을 때만 사용 (예: 사주 프로필 보정 후 재생성)
- Storage 파일 보존 기간: 영구 (유저 탈퇴 시 삭제)

## 6. 보안

### 6-1. 권한 체크

- [x] Firebase ID token 검증 (Bearer)
- [x] `report.userId === decoded.uid` 확인 (403 방지)
- [x] 리포트 타입 체크 (`premium`만 허용)

### 6-2. Storage 규칙

```
// storage.rules
match /pdf/{userId}/{reportId}.pdf {
  allow read: if request.auth.uid == userId;  // 본인만 직접 읽기
  allow write: if false;                       // 클라이언트 쓰기 금지
}
```

Signed URL은 서버에서 발급하므로 클라이언트의 직접 Storage 읽기는 차단해도 무방.

### 6-3. Rate limit

- 유저당 분당 3회 — `pdfJobs/{jobId}` 타임스탬프 기준 카운트
- 같은 `reportId`는 동시 1회 (Firestore tx 또는 Redis lock)
- 429 응답 시 `Retry-After` 헤더에 대기 시간 표시

### 6-4. Signed URL 만료

- 7일 권장 — 유저가 이메일·카톡으로 공유한 링크가 너무 오래 살아있으면 유출 리스크
- PDF 재생성 요청 시 매번 새 Signed URL 발급 (기존 URL은 만료까지 살아있음)

## 7. 클라이언트 통합

### 7-1. 버튼 클릭 → 다운로드 플로우

```tsx
async function handleDownloadPdf() {
  setLoading(true);
  try {
    const token = await getIdToken();
    const res = await fetch('/api/premium/pdf', {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ reportId }),
    });
    
    if (res.status === 409) {
      showToast('PDF를 아직 만들고 있어요. 잠시 후 다시 시도해주세요.');
      return;
    }
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    
    const { url, cached } = await res.json();
    
    // 앱인토스 환경 = WebView → 외부 브라우저 열기 또는 Storage 링크로 직접 다운
    if (isAppInToss()) {
      appintoss.openUrl(url);  // SDK 제공 메서드
    } else {
      window.open(url, '_blank');
    }
    
    showToast(cached ? '리포트를 불러왔어요' : 'PDF가 준비됐어요');
  } catch (err) {
    showToast('PDF 생성에 실패했어요. 잠시 후 다시 시도해주세요.');
    Sentry?.captureException(err);
  } finally {
    setLoading(false);
  }
}
```

### 7-2. 로딩 UX

- 버튼 클릭 즉시 스피너 + "PDF를 준비하고 있어요"
- 10초 경과 시 "한 해 운의 결을 엮는 자리입니다"
- 30초 경과 시 "서버가 붐비는 시각. 결을 한 번 더 다듬는 중입니다"
- 에러 시 재시도 버튼

### 7-3. 앱인토스 WebView 환경 고려

- `window.open()`이 동작하지 않을 수 있음 → 앱인토스 SDK `openUrl` 또는 `share` 메서드 사용
- 다운로드 대신 WebView 내부에서 PDF 뷰어 띄우는 방식도 고려 (`<iframe src={url}>`)

## 9. 로컬 개발·배포

### 9-1. 로컬 테스트

`reference_local_validation_cycle.md` 표준 준수:
1. Firebase emulator 실행 (`firebase emulators:start --only functions,firestore,storage,auth`)
2. 테스트 reportId를 emulator Firestore에 주입
3. `curl -X POST http://localhost:5001/.../generatePremiumPdf` 로 호출
4. 생성된 PDF 로컬에서 열어 시각 검증
5. 문제 없으면 prod 배포

### 9-2. 배포

```bash
cd functions
npm run build
firebase deploy --only functions:generatePremiumPdf
```
