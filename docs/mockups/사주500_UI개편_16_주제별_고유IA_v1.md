## 0. 핵심 원칙 (이전 generic spec 와의 차이)

### 0.1 무엇을 공유하는가 (JDS 통일)
- **컬러 토큰** (검정 base + 골드 + 크림 + 주제 액센트)
- **타이포 시스템** (Pretendard / Noto Serif KR / 한자 etc.)
- **강조 위계** (`<strong>` 골드 형광펜 / `<u>` 골드 밑줄 / `<b>` 검정 한자)
- **사주 미니카드 패턴** (한자 + 한국어 읽기 + **의미** 3-line — Daily 진본 동기화)
- **다크 결론박스** + **Upsell 다크 박스** + **Footer 3-part CTA** (구조만)

### 0.2 무엇이 주제별로 다른가 (고유성)
- **섹션 개수** — 4-7섹션 자유 (8섹션 강제 X)
- **섹션 구성** — 주제별 핵심 분석 축 다름
- **시각화** — 주제마다 1-3개의 고유 viz (다른 주제에 없는 것)
- **카피 톤 무게감** — 사랑=따뜻 / 시험=확신 / 건강=경고 / 재물=기회
- **사용자 상태 분기** — 연애 (솔로/썸/연애중), 결혼 (미혼/기혼), 시험 (자격증/입시/공시/이직), 사업 (창업준비/운영중), 직업 (재직/구직), 공부 (학생/직장인/성인) — IA 자체가 다름
- **상대방/대상 사주 입력** — 연애·재회·결혼·궁합 등에서 옵션

### 0.3 사주 8글자 미니카드 — **앱 SSOT (락)**

> **출처**: 사용자 캡처 (2026-05-07) — "내 사주 8글자" 카드의 진본 디자인.
> 모든 주제·콘텐츠 (연애·재물·직업·건강·재회·결혼·시험·사업·이사·공부 + 오늘의 운세 + 종합사주) 에 **반드시 동일하게** 사용.
> 회귀 절대 금지.

#### 디자인 골격 (회귀 금지 록)
- **카드 컨테이너**: 흰 surface + 골드 라인 border (`--c-card-line`) + radius 14px
- **헤더**: "내 사주 8글자" — 주제 액센트 색 (`--c-topic`) · letter-spacing 0.15em · 11px · 700
- **셀**: paper 배경 + 골드 라인 border + radius 10px + padding 6px
- **일주 셀**: 골드 그라디언트 (`--c-gold-soft → 4%`) + 골드 line border + 셀 하단 "일간" 라벨
- **천간 박스 (.gan-block)**:
  - 솔리드 컬러 박스 (오행 색)
  - 한자 24px · weight 800
  - 읽기 9px · weight 700 · opacity 0.85
- **지지 박스 (.ji-block)**: 천간과 동일 패턴 · 한자 20px (천간보다 작게)
- **의미**: 박스 바깥 위/아래에 회색 (`--c-mute`) · 9.5px · weight 600
  - 천간 의미: "큰 나무" / "밭" / "큰 산" / "큰 강" 등 (한국어)
  - 지지 의미: "호랑이" / "닭" / "원숭이" 등 (12지 동물 한국어)

#### 오행 솔리드 색 매핑 (SSOT — 천간/지지 동일)

| 오행 | 배경 | 텍스트 | border | 비고 |
|---|---|---|---|---|
| 목 (甲乙寅卯) | `var(--c-mok)` #2D8A4E | #FFF | mok | 솔리드 초록 |
| 화 (丙丁巳午) | `var(--c-hwa)` #D32F2F | #FFF | hwa | 솔리드 빨강 |
| 토 (戊己辰戌丑未) | `var(--c-to)` #E8B82A | #FFF | to | 솔리드 골드 노랑 |
| 금 (庚辛申酉) | #FFF | `var(--c-geum)` #4A4A4A | card-line | 흰 박스 + 회색 글자 |
| 수 (壬癸子亥) | `var(--c-ink)` #1A1A1A | #FFF | ink | 솔리드 검정 |

#### HTML 구조 (모든 주제 동일)
```html
<div class="my-saju">
  <div class="ttl">내 사주 8글자</div>
  <div class="saju-grid">
    <div class="saju-cell">
      <div class="lab">시</div>
      <div class="gan-block o-{오행}"><span class="han">{한자}</span><span class="read">{읽기}</span></div>
      <div class="meaning">{한국어 의미}</div>
      <div class="ji-block o-{오행}"><span class="han">{한자}</span><span class="read">{읽기}</span></div>
      <div class="meaning">{12지 동물}</div>
    </div>
    <div class="saju-cell ilju">
      <!-- 일주 — 골드 그라디언트 + 하단 "일간" 라벨 -->
      <div class="lab">일</div>
      ...
      <div class="ilgan-tag">일간</div>
    </div>
    <!-- 월·년 동일 -->
  </div>
</div>
```

#### 회귀 패턴 (절대 금지)
- ❌ paper 배경 셀에 텍스트만 쌓기 (이전 v3 의 잘못된 디자인)
- ❌ 천간/지지를 `<div class="gan o-to">` 같이 텍스트만 + 의미를 inline `<span>` 로 처리
- ❌ ttl 색을 골드로 (앱 SSOT 는 주제 액센트 색 = 연애운=분홍 / 재물=골드 / 직업=파랑 / ...)
- ❌ 일주 셀 라벨을 "일 (나)" 로 (앱 SSOT 는 "일" + 하단 "일간")
- ❌ 한자 의미를 `<span class="meaning">` 으로 inline (앱 SSOT 는 `<div class="meaning">` 박스 바깥 line)

이 컴포넌트 = 사주500 의 **시각적 정체성**. 모든 결과·분석 페이지의 첫 만남 카드. 깨지면 브랜드 신뢰 깨짐.

### 2.1 연애 (緣) — 3분기 SSOT (사용자 상태별로 IA·시각화·프롬프트가 완전히 다름)

| §A | 月運 | 올해 연애 흐름 전략 | 12개월 도화 캘린더 + 분기별 전략 (best/충 시기) |

#### [썸] 5섹션 — "이 사람과 풀릴까" (썸 SSOT)
> 썸 = **그 사람과의 가능성 + 진전 시기 + 행동** 핵심.

**상대 사주 입력**: 옵션 (입력 시 합·충 정밀 / 미입력 시 일반 가이드)

**고유 시각화**:

- 합 강도 게이지 (천간합 + 지지합/충/형/해 4축 → 종합 점수 0-100)
- 3-stage timeline (시작·전환·결판 + 변곡점)
- 결정 게이지 (진전 vs 정리)

## 4. AI prompt schema 분기

### 4.1 주제별 schema 다름
이전 generic `TopicResultV2` 폐기. 주제마다 schema 다름:

```typescript
type TopicResult =
  | LoveSoloResult
  | LoveSseomResult
  | LoveDatingResult
  | ReunionResult
  | MarriageResult
  | WealthResult
  | ExamResult
  | BusinessResult
  | CareerResult
  | HealthResult
  | MoveResult
  | StudyResult;

interface LoveSoloResult {
  // §A 일지 배우자궁
  iljiAnalysis: { iljiHan: string; meaning: string; narrative: string };
  // §B 도화 12개월
  dohwaCalendar: Array<{ slot: string; score: number; tag?: string }>;
  // §C 5오행 매칭
  ohengMatching: Array<{ partnerOheng: '목'|'화'|'토'|'금'|'수'; score: number; why: string }>;
  // §D 처방
  prescription: { hour: string; direction: string; do: string[]; dont: string[] };
  // §E 한 문장
  pullQuote: string;
}

interface LoveSseomResult {
  // §A 합·충 카드
  hapChung: { my: SajuMini; partner: SajuMini; relations: Array<'天干合'|'地支合'|'沖'|'刑'|'害'>; strength: number };
  // §B 3-stage
  threeStage: Array<{ phase: '시작'|'전환'|'결판'; slot: string; message: string }>;
  // §C 상대 결
  partnerNarrative: string;
  // §D 결정
  decision: { direction: '행동'|'기다림'; when: string; reason: string; do: string[] };
  // §E 한 문장
  pullQuote: string;
}

// LoveDatingResult, ReunionResult, ... 각자 다름
```

### 4.2 동적개인화 mandate (모든 주제 공통)
- 단정형 강제
- 사주 호명 (1회+/섹션)
- 출처 mention 0건
- "결" 한 섹션 3회+ 금지
- 이모지 0건
- 한자 첫 등장 시 풀이
- 강조 위계 (`<strong>·<u>·<b>`)
- 점수 자연수 (5의 배수 박멸)

### 4.3 주제별 추가 mandate
- 연애 [썸]/[연애중]: 상대 사주 입력 시 합·충 인용 mandatory

## 5. 작업 순서

```
Phase 1 — 마스터 매트릭스 (이 문서) ✅
Phase 2 — 연애 3분기 mockup (솔로 / 썸 / 연애중)

Phase 4 — AI prompt schema 12개 작성
Phase 5 — TopicMockupView 코드 분기 (12개 케이스 → switch)
```

각 mockup 분량: 600-900줄.
