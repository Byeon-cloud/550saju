## 2. 단가 계산 (Anthropic 공식 요율 기반)

### 2.1 요율 (2026-04 현재)

| 모델 | Input ($/1M tok) | Output ($/1M tok) | 대 Sonnet 비율 |
|---|---|---|---|
| Sonnet 4.6 | $3 | $15 | 1x |
| Opus 4.6 | $15 | $75 | **5x** |
| Haiku 4.5 | $0.8 | $4 | 0.27x |

Prompt caching: cached input 10%, batch API 50% — 동일 비율.

### 2.2 확장 1건 토큰 실측 (daeun 기준)

- Input: system prompt 없음 + user prompt ~1,200 tok + 사주데이터 ~300 tok = **약 1,500 tok**
- Output: 실제 JSON 응답 평균 ~5,500 tok (8,192 한도의 67%)

### 2.3 Sonnet → Opus 단가 차이

| | Sonnet | Opus | 차이 |
|---|---|---|---|
| Input (1,500 tok) | $0.0045 = 6원 | $0.0225 = 31원 | +25원 |
| Output (5,500 tok) | $0.0825 = 114원 | $0.4125 = 570원 | +456원 |
| **합계 / 1건** | **~120원** | **~601원** | **+481원** |

*환율 $1 = 1,380원 기준.*

### 2.4 수익성 검토

- 현재 확장 1건 = **500원 수취 → Sonnet 원가 120원 → 순익 380원** (기타 Firebase/PG 제외)
- Opus 승격 시 = **500원 수취 → Opus 원가 601원 → 순손실 101원**
- 마진 증발 + 적자 전환. **즉각 승격 불가**.

## 3. Opus 승격 시 퀄리티 기대값

### 3.1 일반론 (Anthropic 자료 + 커뮤니티 벤치)

Opus 4.6가 Sonnet 대비 우위를 갖는 영역:
1. **긴 컨텍스트 추론** — 사주 8글자 × 십성 × 대운 10행 × 신살 교차 관찰
2. **뉘앙스 조절** — 격식체 50% + 친근체 30~40% 혼합 (`feedback_brand_voice_tone.md`)
3. **내적 일관성** — 10주제 간 모순 방지 (`feedback_topic_consistency_ssot.md`)
4. **마크다운 규칙 준수** — `**`/`#` 금지 instruction 장기 준수율 ↑
5. **정형 JSON 안정성** — 파싱 실패율 ↓ (parseJson.ts 재시도 부담 ↓)

### 3.2 확장 4종 구체 qualitative 기대값

- **daeun**: 10개 대운 × 4영역 × score = 40+ 개별 판정. 현재 Sonnet에서도 무난하나, "과거 → 현재 → 미래" 시제 분기와 "소름 포인트" 구체성에서 Opus 우위 가능.
- **monthly**: 12월 × 5영역 = 60 셀. Sonnet으로 충분. 월별 편차의 자연스러움은 프롬프트 의존도가 모델보다 큼.
- **compatibility**: 두 사주 교차 해석 → Opus 우위 예상 영역. 다만 현재 overallScore 분포 검증이 우선.
- **tojung**: 주역 64괘 + 현대 해석 하이브리드 → Opus 우위 예상. 단 "전통 해석 시적 표현" 은 프롬프트 엔지니어링 비중 큼.

### 3.3 예상 퀄리티 개선 폭 (경험치)

- daeun/monthly/tojung: 체감 품질 +10~15% (직접 변별 어려움)
- compatibility: +15~25% (교차 추론 난이도)
- 블라인드 A/B에서 Opus 선택률 55~65% 예상 (50% = 차이 없음)

## 4. 대안 프로그램 (비용-품질 최적화)

### 대안 A: **Sonnet 유지 + 2-pass 자기 검증** ⭐ 권장

```
1st call: Sonnet으로 초안 생성 (8,192 tok)
2nd call: Sonnet으로 "톤 일관성 + 한자 초과 + 모순 검증 + 보강" (3,000 tok 추가)
```

- 추가 원가: ~50원/건 (총 170원)
- 기대 개선: 한자 정책 위반 ↓, 빈약한 섹션 보강, 내적 일관성 ↑
- 구현 난이도: 중 (claudeReport.ts 에 있는 패턴 복제)
- 마진 영향: 380원 → 330원 (13% 감소)

### 대안 B: **Prompt caching + 부분 Opus**

- System prompt를 200+ 토큰으로 확장해 caching 활성화 (5분 TTL)
- 반복 호출 시 input 비용 10%로 감소 (31원 → 3원, -28원)
- daeun 만 Opus 승격, 나머지 Sonnet 유지
- 마진: daeun 만 500원 → -73원 (여전히 적자) → Opus 불가

**→ 대안 B는 현 토큰 설정에서 작동 안 함. 보류.**

### 대안 C: **max_tokens 축소 + Opus 승격**

max_tokens를 8,192 → 4,500 으로 축소 시:
- Opus 원가: 31 + (4,500 × $75/M × 1380) = 31 + 466 = ~497원
- 수지: 500 - 497 = +3원 (사실상 0마진, 적자 방어 수준)

**→ 수치상 가능하지만 유저 체감 리포트 길이 감소(~30%) → 품질 하락 체감 더 큼. 비추천.**

### 대안 D: **reunion 토픽 선별 승격** (claudeTopic.ts reunion case)

reunion은 이미 max_tokens 16,000 으로 가장 긴 출력. 이별/재결합 민감 주제라 퀄리티 요구도 최상.

- Sonnet 현재: input 1,500 + output 12,000 → $0.186 = 257원 원가, 마진 243원
- Opus 승격: input 1,500 + output 12,000 → $0.9225 = 1,273원 원가 → **-773원 적자**

**→ reunion 단독 승격도 현 토큰으론 불가. 토큰 축소(16k → 10k)와 세트여야 의미.**

### 대안 E: **요금 인상 (1운 → 2운)**

- 확장 4종 공급가를 1운에서 2운으로 조정 시 수취 1,000원.
- Opus 원가 601원 → 순익 399원 (Sonnet 380원과 비슷 수준)
- 단 "500원 시리즈" 브랜딩 훼손. 가격전략 v3.1 `가격_상품구조.md` 개정 필요.

## 5. 권장 로드맵

### Phase 1 — 즉시 (launch 전)
**현재 Sonnet 4.6 유지**. `generateReport` 만 Opus 4.6 (이미 확정).
- 이유: 즉시 적자 전환 방지. `project_unit_economics_pending.md` 대로 런칭 후 실측 LTV를 기다려야.
- 작업: 없음. 현 상태 유지.

### Phase 2 — 런칭 +2주
**대안 A (2-pass 자기 검증) 적용**. 4종 확장 + 10주제.
- 추가 원가 50원/건 ≈ 전체 매출의 10%. 감당 가능.
- 구현: `claudeDaeun.ts` 등에 `reviewPass()` 헬퍼 추가. 패턴은 `claudeReport.ts` 2-pass 섹션 재사용.
- 완료 기준: 전 10종 A/B에서 "한자 규칙 위반 0건, 문장 완성도 +10%"

### Phase 3 — 런칭 +1개월
**실측 데이터 수집 후 판단**. 다음 조건 모두 충족 시 Opus 승격 검토:
1. DAU × 확장 호출 전환율이 수익 모델 감당 가능 수준 (월 LTV ≥ 5,000원/유저)
2. 블라인드 A/B에서 Opus 우위 60% 이상 (준기 수동 샘플 20건)
3. 토큰 최적화로 Opus 원가 400원 이하 달성

### Phase 4 — 선별 승격
충족 시: **reunion(compat) + compatibility 2종 우선 Opus 승격** + max_tokens 축소.
- 두 주제는 퀄리티 체감 효과 가장 큼.
- daeun/monthly/tojung은 Sonnet + 2-pass 유지.
